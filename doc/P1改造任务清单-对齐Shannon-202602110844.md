## 4. 具体改造任务清单

## 4.1 批次 P1-1：OPA 接入（FR-024）

### T-P1-OPA-01：抽象策略提供者 SPI

- 目标：将 `PolicyEngine` 从“硬编码规则”改为“可插拔决策入口”。
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/governance/policy/spi/PolicyDecisionProvider.java`
  - 修改 `src/main/java/com/example/agent/governance/policy/PolicyEngine.java`
- 验收标准：
  - `PolicyEngine` 不直接包含具体策略实现细节。
  - 支持按配置切换 provider。

### T-P1-OPA-02：实现本地 provider（兼容现有行为）

- 目标：保留当前本地规则能力作为默认 provider。
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/governance/policy/provider/local/LocalPolicyDecisionProvider.java`
  - 调整 `PolicyEngine` 依赖注入。
- 验收标准：
  - 现有 `policy` 用例不回归。
  - 未配置 OPA 时行为与当前一致。

### T-P1-OPA-03：实现 OPA provider 与 client

- 目标：新增 OPA 远端评估链路。
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/governance/policy/provider/opa/OpaPolicyDecisionProvider.java`
  - 新增 `src/main/java/com/example/agent/governance/policy/provider/opa/OpaClient.java`
  - 新增 `src/main/java/com/example/agent/governance/policy/config/PolicyProviderProperties.java`
  - 修改 `src/main/resources/application.yml`
- 验收标准：
  - OPA 可用时走 OPA。
  - OPA 不可用时按 `fail-open/fail-closed` 策略可控。
  - 记录审计字段（tenant/action/resource/decision/reason）。

### T-P1-OPA-04：补齐策略测试与守卫

- 涉及文件：
  - 修改 `src/test/java/com/example/agent/governance/PolicyEngineTest.java`

- 验收标准：

  - `POLICY_DENIED` 错误码与日志字段一致。

## 4.2 批次 P1-2：DAG 执行闭环（FR-021）

### T-P1-DAG-01：建立 DAG 子域包结构

- 目标：避免把 DAG 逻辑塞回 `MultiAgentCoordinator`。
- 涉及文件：

  - 新增 `DagNode.java`、`DagPlan.java`（或等价模型）
- 验收标准：
  - 包职责清晰，运行时与规划层边界明确。

### T-P1-DAG-02：实现依赖图构建与环检测

- 目标：从 `StepSpec.dependsOn` 构建图并校验循环依赖。
- 涉及文件：
  - 新增 `DagGraphBuilder.java`
  - 新增 `DagCycleDetector.java`
  - 可选新增异常 `DagDependencyException.java`
- 参考：`dag.go:134`。
- 验收标准：
  - 环依赖输入可被检测并返回明确错误码。
  - 无依赖图构建结果稳定。

### T-P1-DAG-03：实现最小可用 DAG 执行协调器

- 目标：支持“依赖满足即执行”的调度语义（先串行最小版，再并行扩展）。
- 涉及文件：
  - 新增 `DagExecutionCoordinator.java`
  - 修改 `src/main/java/com/example/agent/runtime/engine/AgentRuntime.java`
  - 修改 `src/main/java/com/example/agent/runtime/step/executor/StepExecutorRouter.java`（如需）
- 参考：`dag.go:1244`、`dag.go:1312`。
- 验收标准：
  - 对含依赖计划不再固定按原列表顺序执行。
  - 依赖失败可按策略传播。

### T-P1-DAG-04：补齐 DAG 事件与日志

- 目标：保证 DAG 执行可观测。
- 涉及文件：
  - 修改 `RuntimeEventDispatchService`（若需新增 payload）
  - 修改 `DagExecutionCoordinator` 日志与事件发布
- 验收标准：
  - 关键日志包含 workflowId/stepId/dependsOn/调度决策。
  - 出错时日志带异常堆栈与上下文。

### T-P1-DAG-05：测试补齐

# runtime 复核整改下一批实施记录（二）

## 1. 执行目标

- 执行依据：`doc/runtime包设计合理性与坏味道复核评估-202602071851.md`
- 本批目标：继续推进 `output <-> summary` 依赖收敛，形成单向“契约依赖”。
- 设计原则：新项目直接按新方案落地，不保留历史兼容分支债务。

## 2. 实施内容

### 2.1 新增运行时输出契约层

- 新增 `RuntimeOutputKeys`，沉淀输出公共键常量：
  - 文件：`src/main/java/com/example/agent/runtime/contract/RuntimeOutputKeys.java`
- 新增 `RuntimeOutputFieldExtractor`，沉淀跨包字段提取能力：
  - 文件：`src/main/java/com/example/agent/runtime/contract/RuntimeOutputFieldExtractor.java`

### 2.2 output 包回收为契约适配层

- `OutputKeys` 由“定义常量”改为“转发契约常量”，避免重复定义：
  - 文件：`src/main/java/com/example/agent/runtime/output/OutputKeys.java`
- `OutputFieldExtractor` 由“实现提取逻辑”改为“委托契约提取器”：
  - 文件：`src/main/java/com/example/agent/runtime/output/OutputFieldExtractor.java`

### 2.3 summary 包改为依赖契约层

- `StepSummaryTextService` 改为依赖 `RuntimeOutputFieldExtractor`。
- `StepOutputSummaryBuilder` 改为依赖 `RuntimeOutputKeys`。
- `StepOutputSummaryView` 改为依赖 `RuntimeOutputKeys`。

实施后，`summary` 包不再直接依赖 `runtime.output` 包，实现“summary -> contract”单向依赖。

### 2.4 守门测试增强

- 增强 `SummaryDependencyGuardTest`：
  - 在原有禁止 `step/engine/recovery` 依赖基础上，新增禁止 `runtime.output` 依赖。

结果：通过。

### 3.2 全量测试

`mvn -q test`

结果：通过。

## 4. 本批效果

- `summary` 包已与 `output` 包解耦，改为依赖稳定契约层。
- `output` 包职责收敛为适配器，不再承担跨包唯一契约职责。
- 通过守门测试防止依赖方向回退。

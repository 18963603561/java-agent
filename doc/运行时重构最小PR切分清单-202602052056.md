# 运行时重构最小 PR 切分清单

## 1. 目标与约束

本清单基于当前包结构制定，目标是：

- 不做大规模移包。
- 每个 PR 可以独立编译和回归。
- 每个 PR 只解决一类设计问题，降低回滚成本。

本清单覆盖三大复杂类：

- `src/main/java/com/example/agent/runtime/engine/AgentRuntime.java`
- `src/main/java/com/example/agent/runtime/engine/StepRuntimeService.java`
- `src/main/java/com/example/agent/planning/PlannerService.java`

## 2. 切分总览

建议按 `PR-0 -> PR-7` 顺序推进。

- `PR-0`：测试护栏与行为基线。
- `PR-1`：提取 `AgentRuntime` 前后置处理。
- `PR-2`：提取步骤类型路由与执行器。
- `PR-3`：提取执行控制与审批 gate。
- `PR-4`：拆 `PlannerService` 的 LLM 链路。
- `PR-5`：拆 `PlannerService` 的规则规划链路。
- `PR-6`：拆 `StepRuntimeService` 的结果装配。
- `PR-7`：收口清理与文档补齐。

## 4. 每个 PR 的规模控制建议

- 每个 PR 控制在 6 到 12 个文件以内。
- 单 PR 代码行变更建议不超过 600 行。
- 单 PR 优先只改变一个构造器签名，避免测试同时大面积调整。

## 5. 依赖关系提示

- `PR-1` 是 `PR-2` 与 `PR-3` 的前置。
- `PR-4` 与 `PR-5` 建议连续合并，避免中间状态出现双实现分叉。
- `PR-6` 可在 `PR-3` 之后独立推进。

## 6. 建议执行顺序

- 先做 `PR-0` 到 `PR-3`，先稳定运行时。
- 再做 `PR-4` 到 `PR-5`，再稳定规划链路。
- 最后做 `PR-6` 到 `PR-7`，完成结果装配解耦和收口。

## 7. 备注

- 本清单是“最小改造”版本，尽量避免跨包移动。
- 新增类均放在已有包路径或其直接子路径下，保证改动面最小。

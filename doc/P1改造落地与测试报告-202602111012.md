## 2. 代码落地清单

### 2.1 P1-1（OPA）

1) `OpaPolicyDecisionProvider` 增加空决策容错，避免 mock/default 返回导致空指针。  
2) `OpaClient` 支持 `RestTemplateBuilder` 缺省回退（`ObjectProvider` + 默认构造），提升测试与运行环境兼容性。  
3) `PolicyEngineTest` 对 `parseDecision` 补 `thenCallRealMethod`，修复错误桩导致的非业务失败。  
4) `QuickstartFlowTest` 明确启动类，避免多 `SpringBootConfiguration` 冲突。

### 2.2 P1-2（DAG）

1) `MultiAgentCoordinator` 的 `executeDag` 去除对原始 `StepSpec` 的就地污染，改为副本构建。  
2) DAG 节点产出 topic 改为按节点 `produces` 全量写入工作区并发布 `WORKSPACE_UPDATED`。  
3) `DagPlanner` 新增角色级依赖映射能力：支持 `arguments.dagDependencies`。  
4) 新增 `DagPlannerTest`：
   - 线性依赖拓扑排序断言
   - `dagDependencies` 构造环依赖并断言 `DagCycleDetectedException`

### 2.3 P1-3（Supervisor / Handoff）

1) 重构 `SupervisorCoordinator` 状态判定：
   - 依赖缺失不再误判为 `COMPLETED`
   - 引入 `terminatedByFailurePolicy`，统一终止语义
   - 区分 `FAILED / PARTIAL_SUCCESS / COMPLETED`
2) `HandoffService` 在有效 topic 下补齐协作消息事件：
   - `MESSAGE_SENT`
   - `MESSAGE_RECEIVED`
   - `WORKSPACE_UPDATED`
3) 扩展测试覆盖：
   - `HandoffServiceTest` 校验消息事件确实发布
   - `MultiAgentCoordinatorTest` 增加路由分支覆盖（Supervisor / DAG）

## 4. 关键设计点说明

1) **避免输入对象污染**：DAG 执行不再直接改写上游 `StepSpec.arguments`，降低副作用与并发风险。  
2) **失败语义一致化**：Supervisor 路径统一通过失败计数与传播策略得出最终状态，避免“缺依赖仍完成”的语义漂移。  
3) **协作事件可观测性增强**：handoff 过程补齐消息类事件，便于后续时序诊断、审计与前端可视化。  
4) **DAG 可扩展依赖模型**：`dagDependencies` 提供角色级图定义入口，兼容后续复杂编排（非线性依赖）。

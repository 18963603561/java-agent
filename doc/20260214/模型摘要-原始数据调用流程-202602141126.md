# 模型摘要-原始数据调用流程设计

## 1. 背景与目标

当前工程已经完成了摘要策略路由、语义摘要与模板摘要能力，但“模型摘要（`strategy=model`）”仍未形成完整闭环。

本设计目标是：

1. 当摘要策略命中 `model` 时，优先基于 `rawRef` 读取原始数据，调用模型生成步骤级语义摘要。
2. 模型摘要失败时自动降级，不影响主流程执行结果。
3. 摘要结果继续复用当前统一输出结构（`text/highlights/openQuestions/risks/sourceRefs/truncated`）。
4. 原始数据不进入主输出正文，仅通过引用链路与调试接口可见。

## 3. 现状结论

结论：当前工程“支持模型摘要策略的配置与路由”，但“未实现真实模型摘要调用流程”。

具体缺口：

1. `MODEL` 分支没有调用模型，而是直接执行 `semantic` 逻辑。
2. 缺少“原始数据 -> 摘要模型上下文 -> 摘要结果解析”的专用链路。
3. 缺少摘要专用场景路由，无法独立分配模型与成本策略。
4. 缺少摘要专用配置（超时、重试、解析失败降级、是否保留摘要 rawRef）。
5. 缺少模型摘要路径的单元测试与集成测试。

## 4. 目标架构设计

### 4.1 设计原则

1. 复用现有基础设施，不重复造轮子。
2. `result` 主路径不受影响，`summary` 仅作为增强路径。
3. 失败可降级，不能阻塞步骤主执行。
4. 默认安全：原始数据最小暴露、可追溯、可审计。

### 4.2 端到端调用流程

1. `StepExecutionCoordinator` 在步骤完成后调用 `StepOutputSummaryBuilder.build(...)`。
2. `SummaryStrategyResolver` 决策命中 `MODEL`。
3. `StepOutputSummaryBuilder` 将请求委派给新增 `ModelStepSummaryService`。
4. `ModelStepSummaryService` 解析 `rawRef`：
   - 优先从 `input.output.rawRef` 或 `refs` 获取。
   - 若存在 `rawRef`，通过 `RawResultResolveService.resolve(...)` 读取原始文本。
   - 若无 `rawRef` 或读取失败，回退到当前步骤输出的受控序列化文本。
5. 对待摘要原文执行安全处理：
   - 长度裁剪。
   - 可选脱敏（复用 `RedactionService`）。
6. 组装模型摘要提示词，输入内容包含：步骤元信息、原始内容片段、已知结构化结果提示、摘要输出格式约束。
7. 调用 `ModelInvocationService.invoke(...)`，场景建议使用新增 `ModelScene.SUMMARY`。
8. 解析模型输出为结构化摘要对象：`text/highlights/openQuestions/risks/sourceRefs`。
9. 若解析失败且启用修复，调用 `JsonOutputRepairService` 修复后重试解析。
10. 若仍失败，降级到 `SemanticSummaryService.buildSummary(...)`。
11. 将摘要结果映射为 `SemanticSummary`，回到 `StepOutputSummaryBuilder` 后续质量评分与观测链路。
12. 在步骤结果中写入 `summary`，并在 `refs.summaryRawRef` 保留模型摘要原始引用（可调试，不进主流程正文）。

### 4.3 关键时序（文本版）

`StepExecutionCoordinator`
-> `StepOutputSummaryBuilder`
-> `SummaryStrategyResolver`
-> `ModelStepSummaryService`
-> `RawResultResolveService`
-> `ModelInvocationService`
-> `JsonOutputRepairService`（可选）
-> `StepOutputSummaryBuilder`（质量评分/观测）
-> `StepResultAssembler`

## 5. 数据契约设计

### 5.1 模型摘要输入契约（建议）

```json
{
  "schemaVersion": 1,
  "step": {
    "stepId": "...",
    "stepType": "TOOL",
    "status": "COMPLETED",
    "toolName": "search-user-by-name",
    "attempt": 1
  },
  "raw": {
    "rawRef": "rawref:...",
    "content": "...",
    "truncated": true
  },
  "resultHint": {
    "kind": "RECORDSET",
    "keys": ["rows", "columns"]
  },
  "constraints": {
    "maxHighlights": 3,
    "maxOpenQuestions": 3,
    "maxRisks": 3
  }
}
```

说明：

1. `raw.content` 是受控片段，不是完整原始存储。
2. 若 `rawRef` 不可用，可置空并用 `outputSnapshot` 字段兜底。
3. 输入仅用于摘要生成，禁止复用为主任务推理输入。

### 5.2 模型摘要输出契约（建议）

```json
{
  "text": "...",
  "highlights": ["..."],
  "openQuestions": ["..."],
  "risks": ["..."],
  "sourceRefs": [
    {"type": "RAW_REF", "value": "rawref:..."},
    {"type": "TOOL_REF", "value": "search-user-by-name"}
  ]
}
```

约束建议：

1. 必须输出 JSON 对象，不允许 Markdown 包裹。
2. `text` 必填，空值时进入降级。
3. 列表字段允许空数组，但不允许字符串替代数组。
4. `sourceRefs.type` 必须使用既有枚举编码，避免下游反序列化失败。

### 5.3 与现有结构的映射

1. 输出先映射为 `SemanticSummary`，不改变 `StepResult.summary` 结构。
2. `summaryRawRef` 写入 `refs.summaryRawRef`，保持可追溯。
3. 继续由 `StepOutputSummaryBuilder` 输出统一 `summaryMap`。

## 6. 异常与降级策略

| 异常场景 | 处理策略 | 是否影响主流程 |
| --- | --- | --- |
| `rawRef` 缺失 | 使用输出快照兜底构建摘要输入 | 否 |
| `rawRef` 解析失败 | 记录 `warn`，回退输出快照 | 否 |
| 模型调用超时/失败 | 记录 `warn/error`，降级 `semantic` | 否 |
| 模型输出非 JSON | 先尝试 JSON 修复，再降级 `semantic` | 否 |
| 模型输出字段缺失 | 视为无效输出，降级 `semantic` | 否 |
| 摘要文本超预算 | 按预算裁剪并标记 `truncated=true` | 否 |

## 7. 安全与可观测性设计

### 7.1 安全策略

1. 原始数据主路径只传 `rawRef`，不回显完整原文。
2. 模型摘要输入前执行可选脱敏，建议复用 `RedactionService`。
3. 摘要模型 prompt 仅允许“总结”行为，禁止执行性指令。
4. 调试读取原始数据仍走权限与租户隔离。

### 7.2 日志与指标

建议新增日志点：

1. 模型摘要开始：`stepId/stepType/rawRef/strategy/scene`。
2. 模型摘要完成：`durationMs/modelId/inputChars/outputChars/truncated`。
3. 模型摘要降级：`reason/fallbackStrategy`。

建议新增指标：

1. `step_summary_model_total`（按成功/失败标签）。
2. `step_summary_model_latency_ms`。
3. `step_summary_model_fallback_total`。
4. `step_summary_rawref_hit_ratio`。

## 8. 配置设计（建议新增）

在保留 `agent.summary.strategy` 的前提下，新增：

1. `agent.summary.model.enabled`：是否允许模型摘要。
2. `agent.summary.model.scene`：默认 `summary`。
3. `agent.summary.model.max-raw-chars`：摘要输入原文最大字符数。
4. `agent.summary.model.max-output-chars`：模型摘要最大字符数。
5. `agent.summary.model.timeout-ms`：模型摘要调用超时。
6. `agent.summary.model.repair-enabled`：是否开启 JSON 修复。
7. `agent.summary.model.fallback-strategy`：失败回退 `semantic` 或 `template`。
8. `agent.summary.model.persist-summary-raw-ref`：是否保留摘要原始引用。

并同步模型路由：

1. `ModelScene` 增加 `SUMMARY`。
2. `application.yml` 的 `agent.llm.routes` 增加 `summary: cheap`（或独立模型）。

## 10. 分阶段落地建议

### P0（最小可用）

1. 实现 `MODEL` 分支真实调用（不再回退语义）。
2. 支持 `rawRef` 读取原始数据并构建摘要 prompt。
3. 支持解析固定 JSON 输出并映射为 `SemanticSummary`。
4. 失败降级到 `semantic`，确保不影响主流程。

### P1（稳定性）

1. 增加 JSON 修复链路与严格字段校验。
2. 增加 `summaryRawRef` 引用落盘。
3. 增加模型摘要日志与指标。

### P2（安全与治理）

1. 接入脱敏处理。
2. 增加场景化开关与请求级覆盖。
3. 增加租户维度观测与成本统计。

### P3（优化）

1. 支持摘要模型与主模型分离路由。
2. 支持按步骤类型定制摘要模板。
3. 支持摘要质量抽检与自动回归告警。

## 11. 测试与验收建议

### 11.1 单元测试

1. `MODEL` 策略命中后必须触发模型调用。
2. `rawRef` 命中与缺失两条路径。
3. 模型输出合法/非法 JSON 两条路径。
4. 失败降级路径与 `truncated` 标志。

### 11.2 集成测试

1. 启动工程执行真实步骤，验证 `summary.text` 非空。
2. 验证 `refs.summaryRawRef` 可追溯。
3. 验证关闭模型摘要后回到 `semantic/template`。

### 11.3 验收标准

1. `strategy=model` 下可稳定生成摘要。
2. 模型失败不影响 `result` 主路径。
3. 原始数据默认不可见，仅调试可取回。
4. 全链路测试通过且无回归。

## 12. 最终建议

建议按“P0 -> P1 -> P2”顺序推进。

原因：

1. 先闭环功能，再补强稳定性与安全治理，风险最小。
2. 当前工程基础设施完整，主要是链路拼装，不需要推翻已有设计。
3. 通过新增服务隔离模型摘要逻辑，可保持现有 `summary` 包结构清晰、可复用、可测试。

# 返回结果结构说明与优化建议

## 结论概览
本次返回的 JSON 结构整体正常，能够完整表达任务状态、步骤结果与最终聚合输出。
结构化结果 `kind=RECORDSET` 且 `rows/columns` 与业务数据一致，最终汇总 `finalOutput` 可读性良好。
当前结构存在字段重复与空字段占比偏高的情况，建议通过“精简模式”或“字段级开关”降低响应体积。

## 顶层结构说明
- `code`：接口返回码，`OK` 表示请求成功。
- `message`：接口返回消息，`success` 表示无错误。
- `data`：任务核心数据容器。
- `traceId`：链路追踪标识，当前为 `null`。
- `requestId`：请求标识，当前为 `null`。

## data 节点说明
- `taskId`：任务唯一标识。
- `workflowId`：工作流唯一标识。
- `status`：任务总体状态，`COMPLETED` 表示执行完成。
- `streamUrl`：SSE 流式输出地址。
- `result`：任务执行结果容器。

## result 节点说明
- `steps`：步骤结果列表，按执行顺序记录。
- `planId`：规划标识，标识本次规划方案。
- `finalOutput`：最终输出（面向用户的结果）。
- `planSummary`：规划摘要。

## steps[*] 节点说明
- `raw`：原始输出快照，当前为 `null`，说明未输出原始快照或已被裁剪。
- `meta`：步骤元信息。
- `refs`：引用集合，当前为 `null`。
- `errors`：错误列表，当前为空数组。
- `rawRef`：原始输出引用，当前为 `null`。
- `result`：结构化结果。
- `summary`：步骤摘要信息。
如需输出原始快照，需要在配置中开启 `agent.summary.rawEnable=true`。

## meta 节点说明
- `seq`：步骤序号。
- `type`：步骤类型，当前为 `TOOL`。
- `status`：步骤状态，`COMPLETED` 表示完成。
- `stepId`：步骤唯一标识。
- `timing`：时间信息。
- `attempt`：尝试次数。
- `modelId`：模型标识，工具步骤为空。
- `toolName`：工具名称。
`seq` 为事件序号，不保证连续；如需连续编号，在展示层基于当前 `steps` 列表生成 `stepIndex`（从 1 递增），不要复用 `seq`。

## timing 节点说明
- `startedAt`：步骤开始时间。
- `endedAt`：步骤结束时间。
- `durationMs`：耗时毫秒数。

## result（步骤内）节点说明
- `data`：结构化数据主体。
- `kind`：结构化类型，当前为 `RECORDSET`。
- `refs`：结构化结果引用集合。
- `quality`：结构化质量指标。
- `schemaVersion`：结构版本号。

## data（RECORDSET）节点说明
- `rows`：记录行数组。
- `columns`：字段列表。

## refs（步骤内）节点说明
- `rawRef`：原始输出引用。
- `toolRawRef`：工具输出引用。
- `evidenceIds`：证据引用。
- `modelRawRef`：模型输出引用。
- `summaryRawRef`：摘要引用。
- `decisionRawRef`：决策引用。

## quality 节点说明
- `warnings`：质量警告列表。
- `truncated`：是否截断，当前为 `null`。
- `confidence`：置信度。
- `completeness`：完整度。
- `missingFields`：缺失字段列表。

## summary（步骤内）节点说明
- `text`：摘要文本，当前为 `null`。
- `risks`：风险提示列表。
- `truncated`：摘要是否截断。
- `highlights`：高亮信息。
- `sourceRefs`：摘要来源引用。
- `openQuestions`：未解决问题列表。

## sourceRefs[*] 节点说明
- `path`：来源路径。
- `type`：来源类型。
- `value`：来源值。

## finalOutput 节点说明
- `meta`：最终输出元信息。
- `result`：最终输出主结果。
- `summary`：最终输出摘要。
- `decision`：最终决策信息，当前为 `null`。

## finalOutput.meta 节点说明
- `planId`：规划标识。
- `modelId`：模型标识。
- `planSummary`：规划摘要。

## finalOutput.result 节点说明
- `answer`：用户可读结果文本。
- `confidence`：置信度。
- `highlights`：结果高亮摘要。

## finalOutput.summary 节点说明
- `text`：摘要文本。
- `truncated`：是否截断。
- `highlights`：摘要高亮。

## 结构是否正常的判断
- 结构完整性正常：包含任务级、步骤级、最终输出级三层结构。
- 数据正确性正常：`steps[*].result.kind=RECORDSET`，`rows/columns` 与业务结果一致。
- 汇总正确性正常：`finalOutput.result.answer` 能正确整合两个步骤的结果。
- 可追踪性部分缺失：`rawRef`、`refs`、`traceId`、`requestId` 为空，说明未开启或未输出追踪与原始引用。

## 结构冗余与可优化点
1. `planSummary` 重复
- `result.planSummary` 与 `finalOutput.meta.planSummary` 内容重复。
- 建议：保留一个位置（建议仅保留 `finalOutput.meta.planSummary`）。

2. `finalOutput.result.answer` 与 `finalOutput.summary.text` 重复
- 两者内容完全一致，存在重复传输。
- 建议：若启用摘要则仅返回摘要；或摘要只保留“压缩版本”，避免与 `answer` 一致。

3. `steps[*].summary.text` 为空但 `truncated=false`
- 摘要内容为空时仍保留多字段。
- 建议：摘要关闭时直接移除 `summary` 或仅保留 `highlights`。

4. 空字段占比偏高
- `raw`、`rawRef`、`refs`、`modelId`、`decision` 等字段为 `null`。
- 建议：提供“精简模式”，默认不输出 `null` 字段；需要调试时再开启完整输出。

5. 质量字段一致性
- `quality.truncated` 为 `null`，但其他质量字段存在。
- 建议：统一为布尔值（例如 `false`），便于客户端逻辑一致。

6. 摘要预算与截取策略
当前语义摘要存在场景预算；若 `maxChars=0`（场景策略或请求级覆盖），建议默认全部输出不截取，避免出现“摘要文本被预算抑制”的误解。

## 推荐的响应优化策略
- 增加 `responseMode`：`full`（完整）、`compact`（默认精简）。
- `compact` 模式示例规则：
  - 移除值为 `null` 的字段。
  - 移除空数组字段（如 `errors`、`warnings`、`openQuestions`）。
  - 当 `summary.text` 与 `result.answer` 完全一致时，仅保留一个。
  - 仅保留一个 `planSummary`。

## 步骤级摘要策略建议
步骤级 `summary` 默认不必走模型或模板摘要。
建议对外统一配置开关（`SummaryRequestOverrides` 或场景策略），默认关闭。
保留当前默认策略，按场景加“可选摘要策略”，不要对所有步骤强制启用模型或模板。

## 保留字段的合理性说明
- 步骤级 `result` 应保留：便于回放与调试。
- 步骤级 `summary` 可以裁剪：仅保留 `highlights` 即可满足快速浏览。
- `refs` 与 `rawRef` 建议保留“可选输出”：调试环境开启，生产环境关闭。

## 结论
当前返回结构正确可用，但存在重复字段与空字段冗余。
建议引入“精简响应模式”和“摘要一致性策略”，在不影响功能的前提下显著降低返回体积并提升可读性。

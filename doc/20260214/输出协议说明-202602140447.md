# 输出协议说明-202602140447

## 1. 总体结构
统一输出协议：`meta` / `result` / `decision` / `summary`。

## 2. 字段说明
1. `meta`：步骤元信息。
2. `result`：结构化主结果，来自结构化提取器；可能为空或降级。
3. `decision`：决策信息（如下一步动作、工具选择等）。
4. `summary`：语义摘要，仅作为额外上下文使用。
5. `refs`：引用集合，包含 rawRef 以及分阶段 rawRef。
6. `rawRef`：原始输出引用，仅调试可见，不进入主流程输出。

## 3. 字段细则（建议）
1. `meta.stepId`：步骤标识。
2. `meta.type`：步骤类型。
3. `meta.status`：步骤状态。
4. `meta.attempt`：尝试次数。
5. `meta.toolName`：实际工具名。
6. `result.kind`：结构化结果语义类型。
7. `result.schemaVersion`：结构化结果版本。
8. `result.data`：结构化结果数据。
9. `result.quality`：结构化质量信息。
10. `result.refs`：结构化引用信息。
11. `decision`：由决策层产出，字段可扩展。
12. `summary.text`：语义摘要文本。
13. `summary.highlights`：高亮信息列表。
14. `summary.openQuestions`：待澄清问题列表。
15. `summary.risks`：风险提示列表。
16. `summary.sourceRefs`：摘要来源引用列表。
17. `summary.quality`：摘要质量评分与覆盖率。
18. `summary.truncated`：摘要是否截断。

## 4. 约束与回退
1. `summary` 开关仅影响额外上下文，不影响 `result` 主路径。
2. `summary` 关闭时，可为空对象或被序列化层省略。
3. 结构化结果校验失败时，`result` 可降级为错误类型并保留 `data.message`。
4. 原始输出仅保留 `rawRef` 引用，调试路径可回溯原文。

## 5. 示例一：正常工具执行
```json
{
  "meta": {
    "stepId": "step-1",
    "type": "TOOL",
    "status": "SUCCESS",
    "attempt": 1,
    "toolName": "web.search"
  },
  "result": {
    "kind": "search",
    "schemaVersion": 1,
    "data": {
      "items": [
        {"title": "示例", "url": "..."}
      ]
    },
    "quality": {"score": 0.92}
  },
  "decision": {
    "nextAction": "CALL_TOOL",
    "tool": "web.search"
  },
  "summary": {
    "text": "已完成搜索并得到可用结果。",
    "highlights": ["命中 1 条结果"],
    "openQuestions": [],
    "risks": [],
    "sourceRefs": [{"type": "rawRef", "value": "rawref:xxx"}],
    "truncated": false
  }
}
```

## 6. 示例二：结构化校验失败降级

```json
    "kind": "error",

  }
}
```

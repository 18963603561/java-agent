# governance 包 P1 具体改造任务清单

## 1. 任务来源与目标

- 来源文档：`doc/governance包设计合理性与坏味道评估-202602091720.md`
- 对齐问题：
  - P1-A：内存状态容器缺乏生命周期治理。
  - P1-B：`ReplayService` 异常语义被宽泛捕获后统一改写。
- 改造目标：
  - 消除长期运行内存膨胀风险。
  - 恢复异常语义分层，提升线上可观测与排障效率。

## 3. 具体任务清单

### GOV-P1-01 治理状态容器统一生命周期策略设计

**改造范围**
- `src/main/java/com/example/agent/governance/approval/ApprovalService.java`
- `src/main/java/com/example/agent/governance/replay/ReplayService.java`
- `src/main/java/com/example/agent/governance/ratelimit/RateLimitService.java`
- `src/main/java/com/example/agent/governance/circuitbreaker/CircuitBreakerManager.java`

**任务内容**
- 统一定义状态容器三类约束：`ttl`、`maxSize`、`cleanupIntervalSeconds`。
- 统一约定清理触发点：请求入口惰性清理 + 周期性清理二选一或组合。
- 输出配置键规范，全部可通过配置中心覆盖。

**验收标准**
- 四个组件均具备可配置生命周期参数，且参数具备默认值。
- 文档中明确清理策略与触发机制，不出现“仅增长不回收”。

---

### GOV-P1-02 `ApprovalService` 待审批池增加 TTL 与清理

**改造范围**
- `src/main/java/com/example/agent/governance/approval/ApprovalService.java`

**任务内容**
- 为 `pendingApprovals` 增加过期淘汰逻辑。
- 为单租户或全局待审批数量增加容量上限保护，超过上限返回明确错误码。
- 保留超时决策语义，与 `awaitDecision` 超时逻辑一致。

**验收标准**
- 待审批请求在超过 TTL 后不会长期驻留内存。
- 高并发下容器大小可控，不会无限增长。
- 超限与超时日志可区分，且包含 `tenantId/workflowId/requestId`。

---

### GOV-P1-03 `ReplayService` 会话状态清理与容量保护

**改造范围**
- `src/main/java/com/example/agent/governance/replay/ReplayService.java`

**任务内容**
- 为 `sessions` 增加显式生命周期管理。
- 如果会话仅用于过程内临时状态，评估并移除长期持有；如需保留，补齐过期清理与上限控制。
- 为回放会话状态流转增加最小必要日志。

**验收标准**
- `sessions` 不再出现只写不清理。
- 内存占用随回放量增长后可回落。
- 可通过日志追踪会话创建、完成、清理三个关键节点。

---

### GOV-P1-04 `RateLimitService` 计数窗口过期清理

**改造范围**
- `src/main/java/com/example/agent/governance/ratelimit/RateLimitService.java`

**任务内容**
- 增加历史窗口计数过期回收。
- 增加最大键数保护，防止恶意 key 打爆内存。
- 增加限流命中日志与指标（含租户与工具维度标签）。

**验收标准**
- 长期压测后 `counters` 大小稳定在阈值内。
- 限流命中可通过日志与指标双重观测。

---

### GOV-P1-05 `CircuitBreakerManager` 状态过期与恢复治理

**改造范围**
- `src/main/java/com/example/agent/governance/circuitbreaker/CircuitBreakerManager.java`

**任务内容**
- 增加长期未访问断路状态回收。
- 增加状态跃迁日志：关闭→打开、打开→恢复。
- 可选：引入半开探测窗口，避免“到时立即全量放开”。

**验收标准**
- 熔断状态可过期回收，不产生永久驻留键。
- 熔断开启与恢复有可检索日志与计数指标。

---

### GOV-P1-06 `ReplayService` 异常语义分层改造

**改造范围**
- `src/main/java/com/example/agent/governance/replay/ReplayService.java`

**任务内容**
- `resolveTask` 不再 `catch (RuntimeException)` 后统一映射 `REPLAY_NOT_FOUND`。
- 区分三类异常：
  - 业务不存在：`REPLAY_NOT_FOUND`。
  - 依赖不可用：`SERVICE_UNAVAILABLE` 或项目既有统一错误码。
  - 非预期异常：`INTERNAL_SERVER_ERROR`。
- 保留原始异常堆栈并补充上下文（`tenantId/taskId/workflowId/traceId`）。

**验收标准**
- 异常码能反映真实故障类型，不再全部落为“未找到”。
- 日志可用于定位下游依赖失败与业务数据缺失的差异。

### GOV-P1-07 P1 关键路径日志与指标补齐

**改造范围**
- `src/main/java/com/example/agent/governance/**`

**任务内容**
- 覆盖以下观测点：
  - 状态容器清理执行次数、清理数量、当前大小。
  - 限流命中次数。
  - 熔断打开次数、恢复次数、拒绝次数。
  - 回放异常分层统计。
- 指标命名统一使用 `governance.*` 前缀。

**验收标准**
- 每个 P1 改造点至少有一条 `info/warn/error` 级业务日志与一项指标。
- 关键日志带租户与请求上下文。

## 4. 交付门槛（P1 完成定义）

- 内存状态容器具备“可过期 + 可限容 + 可观测”。
- 回放异常具备“语义分层 + 上下文日志 + 原因可追踪”。
- 单测覆盖 P1 新增逻辑且可稳定复现。
- 文档更新：
  - 运行参数说明。
  - 错误码映射说明。
  - 关键指标说明。

## 5. 风险与回滚建议

- 风险点：清理策略过于激进可能导致状态提前回收。
- 控制手段：先以宽松默认值上线，灰度观察容器曲线后再收紧参数。
- 回滚策略：保留旧行为开关，支持快速关闭清理与新异常映射策略。

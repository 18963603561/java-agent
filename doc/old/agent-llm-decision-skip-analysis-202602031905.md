# 关闭直达工具路径时是否可跳过 LLM 决策的分析

## 1. 问题背景
当前分支在 `executeLlmStep(...)` 中调用 `llmStepService.run(...)`，即使已经确认了工具与参数，也会先走一次模型决策。

## 2. 结论
在未启用“直达工具路径”的前提下，不建议直接跳过 LLM 决策并执行工具，除非你愿意补齐以下能力并确保输出一致。

## 3. 为什么不能简单跳过决策
即使“工具名与参数已确认”，`llmStepService.run` 仍承担以下职责：
- 工具调用失败的统一错误码映射与重试策略。
- 工具调用结果的二次总结（输出结构统一，便于反思与最终输出）。
- 上下文回写（例如 `lastToolResult`、`selectedTools` 等）。

如果直接跳过：
- 需要在执行器侧补齐总结输出结构（`mode/tool/toolStatus` 等）。
- 需要复用或重新实现工具失败处理逻辑，否则行为不一致。
- 反思与最终输出链路可能读取不到一致字段。

## 4. 什么时候可以考虑跳过
仅当满足以下条件并可接受行为变化时：
- 工具参数完整且已通过校验。
- 工具调用失败/超时有一致的重试与错误处理方案。
- 输出结构与 LLM 路径完全一致。
- 上下文回写逻辑与 LLM 路径一致。

## 5. 建议做法
- 如果不启用“直达工具路径”，建议继续保留 LLM 决策流程，避免行为不一致。
- 若确实需要跳过决策，应将其视为“直达工具路径”的一种实现，并通过统一的开关与回退逻辑管理。

## 6. 结语
因此，在当前配置未启用直达路径时，继续走 `llmStepService.run` 的决策流程更符合一致性与可维护性要求。

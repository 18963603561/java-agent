## 问题定位与修复

- 现象：接口 `POST /api/v1/tasks` 返回 `404`。
- 原因：启动类位于 `com.example.agent.bootstrap`，默认组件扫描范围不包含 `com.example.agent.api` 等包，导致控制器未被注册。
- 修复：在 `AgentApplication` 增加 `scanBasePackages = "com.example.agent"`，确保全包扫描。
- 修复：对齐 `application-docker.yml` 数据库端口为 `5433`，与 `docker/compose.yaml` 一致。
- 修复：补齐本地 `user_query` 工具与本地模型兜底逻辑，确保无远端依赖也能返回可用结果。

## 结论与优化点

结论：接口在本地模型兜底与本地工具模式下可稳定返回结果，并在并发 2/4/6/10/15/20 场景下完成压测。

优化点：

- 建议补齐 `agent.model.routes.llm_step` 配置，避免 `LLM_STEP` 场景隐式落到回退模型。
- 建议为模型调用增加“远端失败回退本地兜底”的可控开关，提升离线与故障场景可用性。
- 建议将步骤摘要用于最终输出时携带必要结果字段，避免最终汇总阶段缺少证据。
- 建议为压测环境单独配置 `agent.rate-limit.max-per-minute`，避免工具限流误伤吞吐。
- 建议为工具执行链路补充更细粒度耗时指标（工具列表、工具调用、总结阶段），便于定位瓶颈。

# 注释完善计划（基于 comment-audit-20260131）

生成时间: 2026-01-31 13:08
来源: doc/comment-audit-20260131.md
目标: 以最小代价提升关键路径可读性与风险可控性，按 p0-p5 优先级分阶段落地。
范围: src/main/java 优先；src/test/java 仅补齐类型注释与关键块注释。

## 优先级定义
- p0: 关键业务链路与高风险组件（安全/执行/外部调用/审批/运行时调度），无注释将导致误改或事故。
- p1: 核心业务流程与主干服务（规划/反思/执行/研究/多智能体），无注释影响维护效率与回归概率。
- p2: 基础设施与框架层（上下文、事件、模型路由、预算/压缩、观测），需保证可追溯与可扩展。
- p3: 次要业务与辅助组件（插件/技能/工具管理、历史/记忆等），保证可理解性。
- p4: 其他包与低密度但影响较低的文件，补齐类型注释即可。
- p5: 测试代码的类型注释与关键场景块注释（避免误用测试意图）。

## p0（高风险/关键路径，必须优先）
范围包:
- com.example.agent.agentcore
- com.example.agent.auth
- com.example.agent.approval
- com.example.agent.runtime
- com.example.agent.gateway.controller

重点文件（示例，来自审计清单）：
- agentcore: EnforcementGateway, ToolExecutor, ToolArgumentValidator, ToolCache, ToolRegistry
- auth: ApiKeyAuthenticator, TenantContextFilter, TenantResolver
- approval: ApprovalService
- runtime: 多数核心服务（解析/执行/调度相关）
- gateway.controller: 所有 Controller（对外接口）

工作内容:
- 类注释：用途、输入输出、边界条件、异常行为
- 公共方法注释：入参/返回/失败路径
- 关键块注释：安全校验、外部调用、审批分支、异常回退

验收标准:
- p0 范围内文件“类型注释缺失”清零
- 外部接口调用与异常捕获处均有块注释


## p1（核心业务流程）
范围包:
- com.example.agent.planning
- com.example.agent.reflection
- com.example.agent.reasoning
- com.example.agent.research
- com.example.agent.multiagent
- com.example.agent.orchestrator

重点文件:
- PlannerService / ReflectionService / ChainOfThoughtService / ResearchPipeline / DebateCoordinator / MultiAgentCoordinator / TaskOrchestrator

工作内容:
- 核心流程方法补齐注释（流程步骤、状态转换、回退逻辑）
- JSON 解析/修复/回退处补注释，说明失败策略与默认值

验收标准:
- p1 包缺失方法注释比例显著下降（>70%补齐）
- 关键解析与回退处都有中文块注释


## p2（基础设施与可观测性）
范围包:
- com.example.agent.context
- com.example.agent.streaming
- com.example.agent.model
- com.example.agent.budget
- com.example.agent.observability
- com.example.agent.security
- com.example.agent.sandbox

重点文件:
- Context* 相关类、EventStreamService、ModelInvocationService、预算/压缩控制类

工作内容:
- 事件与上下文对象的字段注释（来源、用途、约束）
- 流程入口/发布事件处补块注释

验收标准:
- p2 包字段注释缺失显著减少
- 事件发布/消费关键点有注释说明


## p3（辅助能力与扩展）
范围包:
- com.example.agent.tools
- com.example.agent.tools.hook
- com.example.agent.tools.plugin
- com.example.agent.tools.skill
- com.example.agent.memory
- com.example.agent.history
- com.example.agent.governance

工作内容:
- 类型注释补齐
- 关键扩展点（插件加载、Hook 调度、技能路由）补块注释

验收标准:
- p3 包类型注释缺失清零
- 扩展点具备清晰注释


## p4（低影响补齐）
范围包:
- com.example.agent.common
- com.example.agent.contracts
- com.example.agent.policy
- 其余低密度但低风险文件

工作内容:
- 以类型注释与公共方法注释为主

验收标准:
- p4 包类型注释缺失清零


## p5（测试代码）
范围:
- src/test/java 下所有 noncompliant 文件

工作内容:
- 类注释：测试范围/假设/覆盖点
- 关键块注释：复杂测试场景（如审批链路、异常路径、集成流）

验收标准:
- 所有测试类具备类型注释
- 关键测试场景（流程性测试）补齐块注释


## 执行顺序与交付节奏
1) p0：先完成，预计 2-3 个迭代批次
2) p1：紧随 p0，按业务域拆分批次
3) p2：基础设施完善
4) p3-p4：集中补齐
5) p5：最后统一补齐测试

## 输出产物与检查
- 每个批次输出变更清单与覆盖包
- 运行 scripts/comment_audit.py 复核缺失项是否下降
- 如有新增关键类/方法，保证注释同步添加

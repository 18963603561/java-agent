# budget 包设计合理性 P3 具体改造任务清单

## 1. 任务背景

- 输入依据：`doc/budget-包设计合理性与坏味道评估-202602091221.md`
- 对应问题等级：`P3（低优先级）`
- 本清单目标：将评估文档中的 `P3` 问题转为可排期、可实施、可验收的工程任务。

## 2. P3 问题范围

### 2.1 问题 7：`allocate` 通过 `null` 表示“未启用”语义不清晰

- 目标：将“无分配”语义从 `null` 改为显式对象语义，消除调用侧泛滥判空分支。

### 2.2 问题 8：命名语义与 Spring 角色不完全一致

- 目标：统一编排类命名，避免 `Controller` 与 `@Service` 角色错位造成理解偏差。

### 2.3 持续演进建议：统一命名规范与契约级测试

- 目标：将命名规范、预算语义、压缩触发语义通过守卫与契约测试固化，防止回退。

## 3. 总体目标与完成定义

### 3.1 总体目标

- 提升 `budget` 包语义清晰度与 API 易用性，降低误用风险。
- 降低调用侧无意义判空与分支噪音，提升主链路可读性。
- 将命名规范与契约测试前置，避免结构性小问题持续累积。

### 3.2 完成定义

- 架构完成定义：
  - `ContextBudgetAllocator.allocate` 不再返回 `null`。
  - 压缩编排类命名与职责保持一致（`Service` 或 `Orchestrator` 语义）。
  - 关键调用链路（预算分配 -> 裁剪 -> 压缩）不再依赖 `null` 判定语义。
- 质量完成定义：
  - 新增预算语义契约测试、命名守卫测试、端到端回归测试均通过。
  - 每个阶段执行全量 `mvn test` 并通过。

## 5. 具体任务清单

### P3-T01 建立 P3 行为与契约基线

- 改造目标：形成改造前后行为对照，避免语义漂移。
- 主要动作：
  - 固化当前预算分配、裁剪、压缩相关测试结果。
  - 梳理 `allocate` 返回 `null` 的调用链路清单。
  - 输出命名不一致类清单及影响面。
- 验收标准：
  - 形成可复用基线记录，可用于重构后行为对比。

### P3-T02 设计显式预算分配语义模型

- 改造目标：消除 `null` 语义歧义，建立统一“无分配”表达方式。
- 主要动作：
  - 在 `ContextBudgetAllocation` 中补充显式状态字段（示例：`allocationState`）。
  - 定义状态枚举（示例：`ENABLED`、`DISABLED_BY_REQUEST`、`DISABLED_BY_CONFIG`）。
  - 明确“禁用时 sectionTokens、totalTokens、reservedTokens”的标准取值。
- 验收标准：
  - 预算分配结果可区分“禁用”“启用但预算为 0”“正常分配”。

### P3-T03 落地 `allocate` 非空返回改造

- 改造目标：将 `allocate` 改为永远返回对象，避免调用方判空。
- 主要动作：
  - 改造 `DefaultContextBudgetAllocator.allocate`，删除返回 `null` 分支。
  - 新增工厂方法构建禁用态分配对象（示例：`ContextBudgetAllocation.disabled(...)`）。
  - 统一日志输出禁用原因与状态编码。
- 验收标准：
  - 所有调用路径中 `allocate` 返回值非空。

### P3-T04 清理调用侧判空分支与语义对齐

- 改造目标：移除历史判空噪音，统一按状态字段驱动分支。
- 主要动作：
  - 清理 `allocation == null` 相关分支判断。
  - 调整裁剪与压缩入口逻辑，使用分配状态字段判断是否执行。
  - 将指标与日志标签由“null/非null”改为“allocationState”。
- 验收标准：
  - 核心链路不再依赖 `null` 作为控制信号。

### P3-T05 压缩编排类命名与职责对齐改造

- 改造目标：使类名与 Spring 角色一致，降低理解成本。
- 主要动作：
  - 将 `ContextCompressionController` 重命名为 `ContextCompressionService` 或 `ContextCompressionOrchestrator`。
  - 同步更新注入点、测试类命名、日志前缀。
  - 确保命名不改变原有业务行为。
- 验收标准：
  - 编排类命名与 `@Service` 语义一致。

### P3-T06 命名守卫与架构规则补充

- 改造目标：防止命名与职责退化回流。
- 主要动作：
  - 在 `BudgetArchitectureGuardTest` 增加命名守卫规则。
  - 约束预算编排类命名后缀（`Service` 或 `Orchestrator`）及包放置规范。
  - 增加“禁止重新引入 `null` 语义契约破坏”的静态扫描守卫。
- 验收标准：
  - 守卫规则可拦截违规命名与语义回退。

### P3-T07 预算语义与压缩触发契约测试补齐

- 改造目标：通过契约测试固化 `P3` 语义改造成果。
- 主要动作：
  - 新增预算分配契约测试：
    - 请求禁用时返回禁用态对象。
    - 配置禁用时返回禁用态对象。
    - 启用态下状态/预算字段一致性。
  - 新增压缩触发契约测试：
    - 禁用态预算分配不触发压缩。
    - 启用态预算分配按触发策略执行。
  - 补齐边界输入测试（空请求、零预算、仅保留区预算）。
- 验收标准：
  - 契约测试稳定通过，重复执行结果一致。

### P3-T08 端到端回归与文档收口

- 改造目标：保证发布可交接、可回归、可运维。
- 主要动作：
  - 执行端到端链路回归：预算分配 -> 裁剪 -> 压缩 -> 指标/事件。
  - 更新 `budget` 包结构文档与命名规范说明。
  - 输出 `P3` 实施记录（改造点、风险、回滚点、验证结果）。
- 验收标准：
  - 全量回归通过，文档可直接用于评审与交接。

## 8. 风险与应对

- 风险 1：`allocate` 非空改造影响调用链路判断逻辑。
  - 应对：先补契约测试再改实现，采用状态字段替代判空语义。
- 风险 2：类重命名导致注入失败或测试失效。
  - 应对：同步批量更新注入点与测试引用，优先编译校验再全量回归。
- 风险 3：守卫规则过严导致误报。
  - 应对：守卫规则先最小化落地，结合实际违规案例逐步收紧。

## 9. 预期收益

- 预算 API 语义清晰，调用侧分支显著减少。
- 编排类命名一致性提升，代码可读性与维护效率提升。
- 通过契约测试与守卫规则固化语义，降低后续迭代回退概率。

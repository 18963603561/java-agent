## 1. 目标与范围

本次按 `doc/llm包设计与坏味道复评-202602080919.md` 执行落地，覆盖：

1. 阶段2：大类职责拆分与结构重排。
2. 阶段3：协议一致性与编码治理。
3. 每阶段执行完整构建与全量测试，失败先修复再继续。

---

## 2. 阶段2落地结果

## 2.1 `ModelInvocationService` 职责拆分

已完成：

1. 新增 `LlmEventPublisher`，收口提示词事件、解析事件、追踪事件发布。
2. 新增 `RawRefAttachmentService`，收口 `rawRef` 挂载规则与异常日志。
3. 新增 `LlmFailureRecorder`，收口失败结果构造与指标打点。
4. `ModelInvocationService` 保留编排职责，不再内聚过多明细逻辑。

效果：

1. 关键链路语义更清晰。
2. 后续扩展事件或 `rawRef` 策略时可独立演进，改动面更小。

## 2.2 `DefaultPromptAssembler` 职责拆分

已完成：

1. 新增 `PromptAssemblyContextResolver`，负责输入解析与字段补齐。
2. 新增 `PromptTrimEngine`，负责预算裁剪与预算使用回填。
3. 新增 `PromptTrimMetricsRecorder`，负责裁剪指标记录。
4. `DefaultPromptAssembler` 仅负责编排与消息输出组装。

效果：

1. 裁剪策略从组装器中解耦，后续优化可独立测试。
2. 组装器规模显著下降，阅读成本降低。

## 2.3 `LocalFallbackStrategy` 结构重构

已完成：

1. 从长链式 `if (prompt.contains(...))` 重构为“标记路由 + 处理器注册表”。
2. 处理器顺序显式化，优先级清晰。
3. 保持原行为语义不变，未引入历史兼容分支。

效果：

1. 新增场景时仅需注册 handler。
2. 避免继续扩大条件分支。

## 3. 阶段3落地结果

## 3.1 事件 metadata 覆盖风险治理

已完成：

1. `LlmEventPayloadMapper` 增加保留键集合。
2. `putAllIfPresent` 遇到冲突键时写入 `ext_` 前缀键，避免覆盖核心字段。

## 3.2 请求键名规范治理

已完成：

1. `ModelRequestBodyBuilder` 移除 `toolChoice` 并存写入。
2. OpenAI 兼容请求仅输出 `tool_choice`。
3. 对应测试已同步调整。

## 3.3 Provider 识别强类型化

已完成：

1. 新增 `ProviderType` 枚举。
2. `ModelDefinition` 增加 `providerType` 与 `resolveProviderType()`。
3. `OpenAiProviderAdapter` / `OllamaProviderAdapter` 改为基于强类型识别，不再做 `contains` 判断。

## 3.4 编码治理与守卫

已完成：

1. 新增 `LlmSourceEncodingGuardTest`。
2. 清理 `llm` 目录一批注释乱码与私有区字符文件。
3. 守卫测试通过，可持续阻止编码问题回流。

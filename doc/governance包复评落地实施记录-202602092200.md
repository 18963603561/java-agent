# governance包复评落地实施记录

## 1. 背景与目标

- 依据 `doc/governance包设计合理性与坏味道复评-202602092119.md` 的结论，按阶段推进 `governance` 包重构。
- 本次目标为完成复评方案的代码落地闭环，且不保留历史兼容分支。
- 重点关注统一依赖注入、规则语义清晰化、输入校验收敛、指标口径统一、测试全链路可回归。

## 2. 分阶段落地结果

### 2.1 P1：输入校验与异常收敛（已完成）

- `ReplayTaskResolver` 增加强校验：`tenantContext` 与 `taskId` 必填。
- `ReplayTaskResolver` 收敛 `REPLAY_NOT_FOUND` 告警出口，避免同类错误重复打点。
- `ReplayTaskResolver` 对 `BAD_REQUEST` 直接透传，不做二次包装。
- `PolicyEngine` 增加 `tenant/action/resource` 校验，统一错误码：
  - `POLICY_TENANT_MISSING`
  - `POLICY_COMMAND_MISSING`
  - `POLICY_ACTION_MISSING`
  - `POLICY_RESOURCE_MISSING`
- 测试覆盖补齐：
  - 新增 `PolicyEngineTest`
  - 扩展 `ReplayServiceTest`

### 2.2 P2：场景语义与指标命名收敛（已完成）

- `CapabilityEvaluationInput` 引入显式字段 `scene`。
- `PlanningContextKeys` 增加 `SCENE`。
- `PlanningCapabilityService` 组装评估输入时统一写入 `scene`，默认值为 `default`。
- `CapabilityBoundaryEvaluator` 的场景解析改为读取 `input.scene`，不再复用 `planSummary`。
- 指标统一到 `GovernanceTelemetry`：
  - 删除审批历史指标通道：`approval_requested_total`、`approval_decision_total`、`approval_wait_duration_ms`
  - 删除回放历史指标：`replay.count`
- 清理无效接口：删除 `GovernanceTelemetry.metricName(...)`。

### 2.3 P3：结构收敛与兼容构造器清理（本轮完成闭环）

- 主代码已移除历史兼容构造器，仅保留显式依赖注入构造器：
  - `ApprovalService`
  - `ReplayService`
  - `RateLimitService`
  - `CircuitBreakerManager`
  - `CapabilityBoundaryEvaluator`
- 本轮补齐测试侧构造方式，全部改为新方案：
  - `CapabilityBoundaryEvaluatorTest`
  - `PlannerServiceTest`
  - `AgentRuntimeApprovalIntegrationTest`
- 测试构造统一通过 `CapabilityRuleRegistry` 注入规则，不再在 `CapabilityBoundaryEvaluator` 传入规则列表。

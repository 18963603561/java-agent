# governance 包 P2 具体改造任务清单

## 1. 任务来源与目标

- 来源文档：`doc/governance包设计合理性与坏味道评估-202602091720.md`
- 对齐问题：
  - P2-C：`ApprovalService`、`ReplayService` 职责聚合过重。
  - P2-D：治理子模块可观测性不一致。
  - P2-E：`CapabilityBoundaryEvaluator` 规则硬编码较多，扩展性不足。
  - 分层合理性问题：`governance` 与 `api/http` DTO 边界不清。
- 改造原则：
  - 该项目按新方案直接落地，不保留历史兼容分支。
  - 通过结构重构解决根因，不做临时修补。
  - 保持通用性、可复用性、可测试性。

## 3. 具体任务清单

### GOV-P2-01 明确分层边界与包结构重绘

**改造范围**
- `src/main/java/com/example/agent/governance/**`
- `src/main/java/com/example/agent/api/http/**`

**任务内容**
- 明确四层边界：接口层、应用编排层、领域策略层、基础设施适配层。
- 在 `governance` 内重组子包，建议结构：
  - `governance.<domain>.application`
  - `governance.<domain>.domain`
  - `governance.<domain>.infrastructure`
- 输出依赖方向约束：接口层只依赖应用层，应用层依赖领域层与基础设施抽象。

**验收标准**
- 包结构图与依赖规则可落地到代码目录。
- `governance` 不再直接承担 HTTP DTO 职责。

---

### GOV-P2-02 治理接口 DTO 全量迁移到 `api/http/dto`

**改造范围**
- 迁移对象：
  - `ToolApprovalDecisionRequest`
  - `ToolApprovalDecisionResponse`
  - `ReplayRequest`
  - `ReplayResponse`
  - `PolicyRequest`
  - `PolicyDecision`
- 控制器：
  - `ToolApprovalController`
  - `ReplayController`
  - `PolicyController`

**任务内容**
- 将所有 HTTP 入参/出参类迁移至 `api/http/dto/governance`。
- `governance` 层新增领域命令与领域结果模型，不直接暴露 HTTP 语义。
- 删除旧路径 DTO 类，统一引用新路径。

**验收标准**
- 控制器仅依赖 `api/http/dto`。
- `governance` 包无 `Request/Response` 型 HTTP DTO。
- 编译与测试通过，无重复类。

---

### GOV-P2-03 `ApprovalService` 拆分为应用编排与领域组件

**改造范围**
- `src/main/java/com/example/agent/governance/approval/**`

**任务内容**
- 拆分目标组件：
  - `ApprovalOrchestrator`：审批流程编排。
  - `PendingApprovalStore`：待审批状态存取与清理。
  - `ApprovalDecisionRecorder`：决策写入与一致性处理。
  - `ApprovalArgsDigestBuilder`：参数摘要生成。
  - `ApprovalMetrics`：指标与日志封装。
- 旧 `ApprovalService` 删除或降级为门面，不保留重复职责。

**验收标准**
- 单类长度与复杂度显著下降，职责边界清晰。
- 状态、摘要、指标逻辑可独立单测。

---

### GOV-P2-04 `ReplayService` 拆分为查询、装配、发布、会话组件

**改造范围**
- `src/main/java/com/example/agent/governance/replay/**`

**任务内容**
- 拆分目标组件：
  - `ReplayTaskResolver`：任务查询与异常语义转换。
  - `ReplayItemAssembler`：事件与步骤融合排序。
  - `ReplayEventPublisher`：回放事件发布。
  - `ReplaySessionStore`：会话状态管理。
- 删除 `ReplayService` 中多职责内聚代码。

**验收标准**
- 回放主流程仅负责编排，不直接处理细节实现。
- 各组件具备独立测试入口。

---

### GOV-P2-05 能力评估规则外置与策略插件化

**改造范围**
- `src/main/java/com/example/agent/governance/evaluation/**`

**任务内容**
- 将风险评分权重、关键词、策略映射外置到配置对象。
- 引入策略插件接口，例如：
  - `CapabilityRiskRule`
  - `CapabilityStrategyRule`
- `CapabilityBoundaryEvaluator` 只负责规则执行编排，不再持有硬编码规则细节。

**验收标准**
- 无硬编码业务词表与核心权重常量散落在主逻辑。
- 可通过新增规则类实现扩展，不修改核心编排。

---

### GOV-P2-06 治理统一可观测框架抽象

**改造范围**
- `src/main/java/com/example/agent/governance/**`

**任务内容**
- 抽象统一观测组件，例如：`GovernanceTelemetry`。
- 统一治理日志字段与指标前缀，避免模块各自定义。
- 统一异常记录模板，保证上下文完整。

**验收标准**
- 治理模块日志字段一致。
- 指标命名一致且可批量检索。

---

### GOV-P2-07 无效模型与重复实现清理

**改造范围**
- `src/main/java/com/example/agent/governance/**`

**任务内容**
- 清理无效或重复对象，例如未使用的 `RateLimitRule`。
- 清理拆分后遗留的旧方法、旧字段、旧注释。
- 清理完成后执行无引用检查，确保无僵尸代码。

**验收标准**
- 目标包不存在未被引用的旧模型。
- 静态检查无死代码告警。

---

### GOV-P2-08 全流程回归与重构验收测试

**改造范围**
- `src/test/java/com/example/agent/**`

**任务内容**
- 新增或重构以下测试：
  - 分层契约测试：控制器 DTO 与治理层模型解耦验证。
  - 审批编排组件测试。
  - 回放编排组件测试。
  - 能力评估规则插件测试。
- 每阶段完整执行全量测试。

**验收标准**
- `mvn test` 全量通过。
- 核心治理链路的正反向场景均有覆盖。

## 4. P2 完成定义

- `governance` 包完成“接口协议剥离 + 业务职责拆分 + 规则可扩展化”。
- 关键类不再承担多重职责，包依赖方向单向清晰。
- 所有迁移以“新方案替换旧方案”为准，历史实现已删除。
- 文档、配置、测试三者与新结构保持一致。

## 5. 实施建议与风险控制

- 实施顺序：先做分层与 DTO 迁移，再做服务拆分，最后做规则插件化。
- 风险点：重构期引用路径变化较大，容易出现遗漏。
- 控制手段：每完成一个任务编号即执行一次全量测试，不积压问题。
- 交付建议：按 `GOV-P2-02`、`GOV-P2-03`、`GOV-P2-04` 作为三个里程碑验收。

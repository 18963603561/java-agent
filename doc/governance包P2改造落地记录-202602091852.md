# governance 包 P2 改造落地记录

## 1. 本次改造目标
- 按 `doc/governance包P2具体改造任务清单-202602091804.md` 落地 P2 阶段要求。
- 新项目直接采用新方案，不保留历史兼容分支。
- 聚焦四个方向：审批服务拆分可用性、回放服务拆分稳定性、能力评估规则插件化、无效模型清理。

## 2. 已完成改造项

### 2.1 GOV-P2-03：ApprovalService 拆分后可用性修复
- 修复 Spring 构造器装配冲突：为 `ApprovalService` 的五参构造器补充 `@Autowired`，避免容器尝试无参实例化失败。
- 保留两参构造器用于单元测试快速构建。
- 新增审批诊断接口：
  - `ApprovalService#findAnyPendingRequestId(String tenantId, String workflowId)`
  - `PendingApprovalStore#findRequestId(...)`
- 审批测试从反射读取内部字段改为走公开能力：
  - `ApprovalServiceTest` 使用 `pendingCount()` 校验清理。
  - `HighRiskToolApprovalFlowTest` 使用 `findAnyPendingRequestId(...)` 等待审批请求。

### 2.2 GOV-P2-05：能力评估规则插件化落地
- `CapabilityBoundaryEvaluator` 从“硬编码规则”改为“规则编排器”：
  - 新增依赖：`List<CapabilityRiskRule>`、`List<CapabilityStrategyRule>`。
  - 风险评分逻辑改为：`baseRiskScore + Σrule.score(...)`，并统一夹紧到 `[0,1]`。
  - 策略选择逻辑改为：按顺序执行策略规则，命中即返回，否则回退默认策略。
- 保留三参构造器用于现有单测与最小依赖场景，并内置默认规则集合。
- 添加规则命中 debug 日志，便于评估链路观测。
- 清理 `CapabilityBoundaryEvaluator` 内部关键词硬编码与固定权重写死逻辑。

### 2.4 GOV-P2-07：无效模型清理

## 3. 测试适配

  - `src/test/java/com/example/agent/planning/PlannerServiceTest.java`

## 4. 设计收益
- `ApprovalService` 领域职责边界更清晰，存储可观察能力更好，单测不再依赖反射读取私有状态。
- `CapabilityBoundaryEvaluator` 成为稳定编排层，新增风险/策略规则可通过新增类扩展，不改核心编排代码。
- 配置驱动能力增强，权重与关键词调整无需改 Java 代码即可生效。
- 删除无效模型，降低维护噪音与歧义。

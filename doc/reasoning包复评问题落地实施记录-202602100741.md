# reasoning 包复评问题落地实施记录

## 1. 背景与目标

依据 `doc/reasoning包设计合理性与坏味道复评-202602100718.md`，对 `reasoning` 包中 P1/P2 坏味道进行分阶段落地：

1. 策略规则配置化，消除硬编码。
2. 执行计划不可变，减少非法状态。
3. 推理输入强类型化，降低字符串键访问风险。
4. 思维树规则组件化，降低服务类耦合。

本次按阶段执行并在每个阶段后运行完整测试流程。

## 2. 阶段一：规则配置化 + 执行计划不可变

### 2.1 代码改造

- `src/main/java/com/example/agent/reasoning/common/config/ReasoningExecutionProperties.java`
  - 新增 `Selection` 配置域：复杂度阈值、不同主策略的降级顺序、默认降级顺序。

- `src/main/java/com/example/agent/reasoning/common/config/ReasoningConfigValidator.java`
  - 新增复杂度阈值校验。
  - 新增降级顺序合法化与去重校验。

- `src/main/java/com/example/agent/reasoning/common/config/ReasoningConfigResolver.java`

## 5. 结果评估

1. 已完成复评文档中的主要问题收敛：规则硬编码、输入弱类型、计划可变性、规则耦合。
2. 代码通用性与可复用性提升：

3. 所有阶段均执行完整测试流程，未引入回归失败。

## 6. 风险与回滚

### 6.1 风险

1. 配置驱动后若配置异常，会影响策略选择与降级顺序。
2. 输入强类型化后，依赖原始 `Map` 行为的新增代码需要按新接口接入。

### 6.2 回滚方式

1. 可按阶段回滚以下文件组：
   - 阶段一：`selection/*`、`ReasoningExecutionPlan`、`ReasoningExecutionProperties`、`ReasoningConfigResolver`、`ReasoningConfigValidator`、三个执行器。
   - 阶段二：`ReasoningInput`、`ReasoningRequest` 及其消费链路。
   - 阶段三：`ThoughtTreeScoringPolicy`、`ThoughtTreeTerminalPolicy`、`ThoughtTreeService`。
2. 回滚后必须执行：

```bash
mvn test
```

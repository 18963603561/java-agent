# 运行时对象流转详图（对象流程 + 中间过程流转）

> 说明：本图基于当前主链路 `WorkflowRouter.route -> AgentRuntime.run -> StepRuntimeService.completeStep -> RuntimeFinalizationService.finalizeRun`，覆盖你指定的全部对象：
> `RuntimeContext`、`StepSpec`、`stepInput`、`StepRecord`、`StepExecutionRequest`、`StepExecutionOutput`、`ReflectionResult`、`StepResult`、`RuntimeResult`、`StepResultMeta`、`RawRef`、`StepResultRaw`、`StructuredResult`、`StepResultSummary`、`StepResultRefSet`。

```mermaid
graph TB
    A0[TaskRequest + TenantContext + workflowId + taskId] --> A1[WorkflowRouter.route]
    A1 --> A2[AgentRuntime.run]

    subgraph P0[准备与规划阶段]
        A2 --> P1[RuntimePreparationService.prepare]
        P1 --> P2[RuntimeContext 跨步骤共享上下文]
        P1 --> P3[effectiveRequest]
        P3 --> P4[PlannerService.plan]
        P4 --> P5[PlanResult]
        P5 --> P6[StepSpec 列表]
    end

    subgraph L0[步骤循环阶段（每个 StepSpec）]
        P6 --> L1[当前 StepSpec]
        P2 --> L2[mergeStepInput]
        L1 --> L2
        L2 --> L3[stepInput Map_String_Object]

        L3 --> L4[StepRuntimeService.startStep]
        L4 --> L5[StepRecord status=STARTED]

        L1 --> L6[构造 StepExecutionRequest]
        L3 --> L6
        P2 --> L6
        L5 --> L6
        A0 --> L6
        L6 --> L7[StepExecutionRequest]

        L7 --> L8[StepExecutionDelegate.execute]
        L8 --> L9[StepExecutionOutput]

        L9 --> L10[enrichOutputSummaryForReflection]
        L10 --> L11[ReflectionService.reflect]
        L11 --> L12[ReflectionResult]

        L12 -->|retryRequested=true| L13[StepRuntimeService.failStep errorCode=REFLECTION_RETRY]
        L13 --> L14[RetryPolicy.sleepBeforeRetry]
        L14 --> L2

        L12 -->|retryRequested=false| L15[StepRuntimeService.completeStep]
        L15 --> L16[StepRecord status=COMPLETED + output=StepResult]
        L16 --> L17[recordStepOutput]
        L17 --> L18[stepOutputs: List_StepResult]

        L16 --> L19[updateRuntimeContext]
        L19 --> P2

        L9 --> L20[异常分支: StepFailureRecoveryService.recover]
        L20 -->|FALLBACK_SUCCESS| L15
        L20 -->|RETRY| L14
        L20 -->|REPLAN| L21[StepOutcome.REPLAN]
    end

    L21 --> P4

    subgraph F0[收口阶段]
        L18 --> F1[RuntimeFinalizationService.finalizeRun]
        P5 --> F1
        F1 --> F2[buildRuntimeResult]
        F2 --> F3[RuntimeResult]
        F3 --> F4[planId + planSummary + steps + finalOutput]
        F1 --> F5[memoryWriteService.saveTaskMemory]
    end
```

## 三、关键对象的一句话定位（便于读图）

- `RuntimeContext`：跨步骤共享的运行态上下文容器，承接上一轮步骤关键信息并参与下一轮 `stepInput` 合并。
- `StepSpec`：规划输出的步骤定义对象，是每轮执行请求的静态配置源。
- `stepInput`：`StepSpec + RuntimeContext` 的动态合并视图，是本轮步骤真实执行输入。
- `StepRecord`：步骤运行轨迹实体，承接 `STARTED/COMPLETED/FAILED` 状态流转与 `StepResult` 回写。
- `StepExecutionRequest`：步骤执行器消费的标准输入对象，封装执行所需全部上下文。
- `StepExecutionOutput`：步骤执行器产出的标准输出对象，后续会拆解为 `StepResult` 各子对象。
- `ReflectionResult`：反思阶段决策对象，决定继续完成、重试或进入异常恢复分支。
- `StepResult`：步骤最终对外输出聚合对象，包含 `meta/rawRef/raw/structured/summary/refs`。
- `RuntimeResult`：整次运行收口对象，包含 `planId/planSummary/steps/finalOutput`。

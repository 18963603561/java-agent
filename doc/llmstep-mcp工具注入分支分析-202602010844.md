# executeLlmStep 独立 LLM 分支注入 MCP 工具分析

## 目标
当请求 `toolChoice.mode = AUTO`（或默认）时，在 `AgentRuntime.executeLlmStep` 中走独立 LLM 分支并注入 MCP 工具，而不是调用 `FinalOutputService.finalizeOutput`。

## 现状梳理
1) 触发点
- `AgentRuntime.executeStep(...)` 在步骤类型为 `LLM/ANSWER` 或未指定工具时走 `executeLlmStep(...)`。

2) 当前 `executeLlmStep(...)` 行为
- 直接调用 `FinalOutputService.finalizeOutput(...)`。
- `FinalOutputService` 不调用 `ModelToolResolver.applyTooling(...)`，因此不注入任何工具。
- 即使 MCP 工具已同步到 `ToolRegistry`，在 LLM 步骤中也不会进入模型请求。

3) MCP 工具加载的现有入口
- `DefaultContextBuilder.buildToolState(...)` -> `DefaultToolCatalog.listSummaries(...)` -> `McpToolSyncService.refreshIfNeeded(...)`。
- 该链路只影响“上下文快照中的工具摘要”，不影响 `executeLlmStep` 的模型请求。

## 结论
- 如果继续调用 `FinalOutputService.finalizeOutput`，则无法在 LLM 步骤注入工具。
- 需要新增“LLM 步骤专用模型调用分支”，并在该分支中调用 `ModelToolResolver.applyTooling(...)`。

## 建议改造方案（不改 FinalOutputService）
### 新增独立 LLM 分支
在 `AgentRuntime.executeLlmStep(...)` 中改为：
1) 构建 LLM 步骤 prompt（可复用现有 PromptAssembler 或新增模板）。
2) 构建 `ModelRequest`。
3) 调用 `ModelToolResolver.applyTooling(...)` 注入工具。
4) 调用 `ModelInvocationService.invoke(...)` 触发模型生成。
5) 解析模型输出并返回结构化结果（不要走最终合并逻辑）。

## 需要修改的关键点
### 1) AgentRuntime
- 新增 `executeLlmStepWithTools(...)` 分支或在 `executeLlmStep(...)` 中注入条件逻辑。
- 当满足以下条件时走新分支：
  - `toolChoice.mode = AUTO` 或 `toolChoice` 为空（默认）
  - 工具未被显式禁用（如 `toolChoice.mode = NONE` 或 `disableTools=true`）

### 2) 新增 LLM 步骤服务（推荐）
建议新建 `LlmStepService`：
- 负责构建 prompt、注入工具、调用模型、解析输出。
- 在 `AgentRuntime` 中调用该服务，保持职责清晰。

### 3) ModelToolResolver
- 直接复用，不需要修改。
- 调用点从 `PlannerService/ReactLoopService` 扩展到新 LLM 步骤分支。

### 4) Prompt 生成与解析
- 可新增 `ModelScene.LLM_STEP` 或复用 `ModelScene.REFLECT`（不建议复用最终合并场景）。
- 建议新增独立的 prompt 模板与解析逻辑，避免与最终合并结果混用。

## 工具注入触发条件建议
- 默认启用工具：当 `toolChoice` 为空或 `AUTO` 时注入。
- 显式禁用：`toolChoice.mode = NONE` 时不注入。
- 可选：允许通过 `context.disableTools=true` 强制禁用。

## 需要新增/修改的文件清单（建议）
- `src/main/java/com/example/agent/runtime/AgentRuntime.java`
  - 增加 LLM 步骤新分支调用。
- `src/main/java/com/example/agent/runtime/LlmStepService.java`（新增）
  - 独立处理 LLM 步骤模型调用与工具注入。
- `src/main/java/com/example/agent/model/ModelScene.java`
  - 新增 `LLM_STEP` 场景（可选但推荐）。
- `src/main/java/com/example/agent/model/PromptAssembler.java` 或新增模板类
  - 增加 LLM 步骤 prompt 生成。

## 注意事项
- MCP 工具同步与注入是两个环节：
  - 同步：`McpToolSyncService` 负责拉取与写入注册表。
  - 注入：`ModelToolResolver.applyTooling` 才会加入模型请求。
- 新分支需要明确是否解析工具调用并执行（如果需要，需引入 `ToolExecutor` 或 `McpToolClient` 的调用逻辑）。

## 下一步建议
- 明确 LLM 步骤 prompt 的结构与返回格式。
- 决定是否需要支持模型返回工具调用（否则只注入工具而不执行，效果有限）。

# runtime 复核整改下一批实施记录

## 1. 目标与范围

- 执行依据：`doc/runtime包设计合理性与坏味道复核评估-202602071851.md`
- 本批目标：落地 P1 中“`step <-> summary` 契约化收敛”，降低 `summary` 包对 `step` 内部对象耦合。
- 变更范围：
  - `src/main/java/com/example/agent/runtime/summary`
  - `src/main/java/com/example/agent/runtime/step`
  - `src/main/java/com/example/agent/runtime/engine`
  - `src/test/java/com/example/agent/runtime`

## 2. 设计落地点

### 2.1 新增摘要输入契约对象

- 新增 `StepSummaryBuildInput`，作为 `StepOutputSummaryBuilder` 的唯一入参契约。
- 契约字段覆盖摘要所需最小信息：
  - `stepId`、`stepType`、`status`、`attempt`
  - `stepInput`、`inputSource`
  - `output`、`toolName`、`error`
- 通过 `Builder` 组装，避免长参数列表，提升可读性与可复用性。

### 2.2 摘要构建器签名收敛

- `StepOutputSummaryBuilder` 改为：
  - `Map<String, Object> build(StepSummaryBuildInput input)`
- 删除 `summary` 包对 `StepRecord` 的直接依赖。
- 保持摘要结果结构与既有键名不变，确保上游消费者兼容。

### 2.3 调用方改造

- `StepRuntimeService.completeStep(...)`
  - 由 `StepRecord` 提取字段构造 `StepSummaryBuildInput`
  - `inputSource` 固定写入 `record`
- `StepExecutionCoordinator.enrichOutputSummaryForReflection(...)`
  - 使用实时 `stepInput` 构造 `StepSummaryBuildInput`
  - `inputSource` 固定写入 `stepInput`

## 3. 质量守门与测试

### 3.1 更新测试

- 更新 `StepOutputSummaryBuilderTest`
  - 全部测试用例改为通过 `StepSummaryBuildInput` 调用 `build(...)`

### 3.2 新增守门测试

- 新增 `SummaryDependencyGuardTest`
  - 扫描 `src/main/java/com/example/agent/runtime/summary`
  - 禁止 `summary` 包引入以下越级依赖：
    - `com.example.agent.runtime.step.*`
    - `com.example.agent.runtime.engine.*`
    - `com.example.agent.runtime.recovery.*`

### 3.3 执行结果

- 定向测试通过：
  - `mvn -q "-Dtest=StepOutputSummaryBuilderTest,StepRuntimeServiceTest,StepExecutionCoordinatorTest,SummaryDependencyGuardTest" test`
- 全量测试通过：
  - `mvn -q test`

## 4. 本批收益

- 消除 `summary -> step` 的直接模型依赖，边界更清晰。
- 摘要构建入参完成契约化，调用方可按场景装配，复用性提升。
- 增加依赖方向守门，后续迭代可持续防回退。

## 5. 后续建议

- 继续推进复核文档剩余项：
  - `output <-> summary` 的单向装配化收敛
  - 超大类拆分（`StepRuntimeService`、`FinalOutputService`、`ReactLoopService`、`LlmStepService`）

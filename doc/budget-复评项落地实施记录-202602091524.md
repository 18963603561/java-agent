# budget 复评项落地实施记录

## 1. 实施背景

- 输入依据：`doc/budget-包设计合理性与坏味道复评-202602091457.md`
- 实施目标：落地复评中识别的 P2/P3/P4 改进项，提升预算域可维护性与可扩展性。
- 实施原则：
  - 新项目直接采用新方案，不保留历史兼容分支。
  - 以通用性、复用性、设计合理性为优先。
  - 每阶段完成后执行全量 `mvn test` 回归。

## 2. 分阶段改造结果

### 阶段 A：收敛 `ContextBudgetAllocation` 单一真值源

- 改造文件：
  - `src/main/java/com/example/agent/budget/core/ContextBudgetAllocation.java`
- 关键改造：
  - 删除派生预算字段的可变 setter（系统/任务/工作记忆/召回/证据/工具/余量）。
  - 保留 getter，但改为基于 `sectionTokens` 动态计算。
  - `sectionTokens` 默认不可变空映射，`setSectionTokens` 统一做防御性复制和非负归一化。
  - `disabled(...)` 统一使用空映射，避免可变空容器外泄。
- 目标达成：消除“双重事实来源”风险，预算分段成为唯一真值源。

### 阶段 B：拆分 `ContextTokenEstimator` 为子估算器

- 新增文件：
  - `src/main/java/com/example/agent/budget/trim/ContextTextTokenEstimator.java`
  - `src/main/java/com/example/agent/budget/trim/ContextMemoryTokenEstimator.java`
  - `src/main/java/com/example/agent/budget/trim/ContextKnowledgeTokenEstimator.java`
  - `src/main/java/com/example/agent/budget/trim/ContextToolTokenEstimator.java`
- 改造文件：
  - `src/main/java/com/example/agent/budget/trim/ContextTokenEstimator.java`
- 关键改造：
  - `ContextTokenEstimator` 转为门面聚合层，保留对外 API 不变。
  - 具体估算职责下沉到文本/记忆/知识/工具四类子估算器。
  - 外部调用方无感知迁移，兼容现有裁剪/压缩处理链路。
- 目标达成：降低单类复杂度与改动冲突概率，提升估算逻辑可维护性。

### 阶段 C：`DefaultContextPruner` 迁移为 handler 注册模式

- 改造文件：
  - `src/main/java/com/example/agent/budget/trim/DefaultContextPruner.java`
- 关键改造：
  - 增加 `PruneHandler` 内部接口。
  - 增加 `pruneHandlers` 映射和初始化注册逻辑。
  - 主流程由 `switch` 分派改为 handler 查表调用。
- 目标达成：新增分段裁剪时无需修改主流程 `switch`，开放封闭性增强。

### 阶段 D：阈值接口收口与守卫增强

- 改造文件：
  - `src/main/java/com/example/agent/budget/token/BudgetThresholdEvaluator.java`
  - `src/main/java/com/example/agent/budget/token/DefaultBudgetThresholdEvaluator.java`
  - `src/main/java/com/example/agent/budget/token/TokenBudgetManager.java`
  - `src/test/java/com/example/agent/budget/BudgetArchitectureGuardTest.java`
- 关键改造：
  - 将 `getThresholdTokens()` 上提到 `BudgetThresholdEvaluator` 接口。
  - `TokenBudgetManager` 删除对 `DefaultBudgetThresholdEvaluator` 的具体实现依赖。
  - 守卫测试新增“禁止 `TokenBudgetManager` 回退依赖具体阈值实现”的规则。
- 目标达成：编排层依赖抽象接口，降低具体实现耦合。

# 新工程：语义摘要替换与结构化强化改造评估

**依据文档**
`doc/20260213/agent上下文-对比分析-202602132030.md`  
`doc/20260213/整改范围-变种评估-202602132134.md`

**目标说明**
删除现有“结构快照型 summary”，引入真正的语义摘要；强化结构化结果为主流程通道；用新的反思与回归机制替代现有依赖 summary 的路径。项目为新工程，不考虑历史兼容。

---

## 一、现状与问题定位（聚焦 summary）

1. 现有 summary 主要是“结构快照 + 截断样例”，并非语义摘要。
2. summary 被反思链路与最终输出使用，但无法稳定表达关键语义结论。
3. 记忆写入依赖最终输出序列化，缺少“语义摘要主通道”。
4. 结构化结果虽存在，但不是主流程唯一来源，仍有原始输出主路径问题。

---

## 二、目标方案（新工程推荐）

**核心设计**
1. 输出协议统一为 `meta/result/decision/summary`，其中 `result` 为结构化主数据。
2. `summary` 改为语义摘要（可由模型或规则生成），仅用于记忆与上下文压缩。
3. 删除“结构快照型 summary”，保留必要的诊断指标为独立观测字段。
4. 反思与回归机制基于 `result` 与语义摘要进行，禁止读取原始输出。

**输出协议数据结构（建议）**
```json
{
  "meta": {
    "task_id": "string",
    "step_id": "string",
    "step_type": "string",
    "status": "string",
    "attempt": 1,
    "timestamp": "2026-02-13T21:16:00Z",
    "model_id": "string",
    "tool_name": "string",
    "raw_ref": "string"
  },
  "result": {
    "schema_version": 1,
    "kind": "string",
    "data": {}
  },
  "decision": {
    "next_action": "string",
    "need_more_data": false,
    "call_tool": null,
    "retry": false,
    "reason": "string",
    "confidence": 0.0
  },
  "summary": {
    "text": "string",
    "highlights": [
      "string"
    ],
    "open_questions": [
      "string"
    ],
    "risks": [
      "string"
    ],
    "source_refs": [
      "rawref:xxx"
    ]
  }
}
```
**字段说明**
1. `meta`：运行时元信息，保证可追踪与可审计。
2. `result`：结构化主数据，`kind` 指语义类型，`schema_version` 用于兼容演进。
3. `decision`：流程控制字段，仅影响下一步动作与重试策略。
4. `summary`：语义摘要，仅用于记忆与上下文压缩，不参与流程控制。

**语义摘要定位**
- 输入：结构化结果、关键决策与必要证据引用。
- 输出：短文本结论、未解决问题、关键约束与风险提示。
- 目标：可压缩、可入库、可复述、可追踪来源。

**反思/回归输入原则**
1. `result` 为主路径，作为反思与回归的核心判断依据。
2. `summary` 为增强项，仅作为额外上下文补充，不改变核心判断逻辑。
3. 摘要开关只影响“额外上下文”是否提供；关闭时仍可基于 `result` 完整工作。

**原始数据调试可见路径**
1. 主流程仅保留 `rawRef`，不直接携带原始输出。
2. 调试开关控制原始数据可见性，生产默认关闭，灰度或调试环境可开启。
3. 原始数据必须经过脱敏与权限控制，避免泄露与越权访问。

## 三、删除与替代清单

**需要删除或下线**
- 结构快照型 summary 生成链路：`StepOutputSummaryBuilder` 及其依赖服务。
- 反思上下文对快照 summary 的依赖：`StepOutputSummaryView` 与 `ReflectionContextMapper` 相关逻辑。

**需要新增或替代**
- 语义摘要生成服务：以 `result/decision` 为输入，输出短文本摘要。
- 语义摘要落库与回填：进入记忆系统与上下文压缩通道。
- 反思与回归替代机制：基于结构化结果与语义摘要进行评分、重试与回归。

## 五、P0-P6 改造任务（新工程视角）

**P0（必须优先落地）**
1. 删除结构快照 summary 链路，替换为语义摘要生成服务。
2. 输出协议统一为 `meta/result/decision/summary`，`result` 为主流程数据源。
3. 反思路径改为读取 `result` 与语义摘要，禁止依赖原始输出。

**P1（主流程一致性）**
1. 语义摘要入库为唯一摘要通道，记忆写入不再序列化原始输出。
2. 最终输出优先使用结构化结果与语义摘要，原始输出仅调试可见。
3. 引入结构化结果 `JSON Schema` 校验与失败降级策略。

**P2（核心能力提升）**
1. 语义摘要质量度量与抽检机制。
2. 结构化结果质量评分与字段完整性检查。
3. 反思策略基于结构化结果的稳定评分模型。

**P3（效率与质量优化）**
1. 语义摘要生成支持场景化配置与长度预算。
2. 语义摘要与结构化结果的引用关系可追踪。

**P4（可观测与运维）**
1. 语义摘要生成耗时、命中率、失败率监控。
2. 结构化结果校验失败率与降级统计。

**P5（体验与配置）**
1. 对外输出协议文档与示例。
2. 请求级配置覆盖语义摘要策略。

**P6（预研与探索）**
1. 多模型摘要对比与一致性评估。
2. 语义摘要与向量记忆协同策略评估。

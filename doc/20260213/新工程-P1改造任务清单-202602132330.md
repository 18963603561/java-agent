# 新工程-P1改造任务清单（包设计合理性）-202602132330

**依据文档**
`doc/20260213/新工程-语义摘要替换-变更评估-202602132202.md`

**目标**
在`P1`阶段完成主流程一致性改造，确保语义摘要成为唯一摘要通道，结构化结果成为主流程数据源，原始输出仅调试可见，并通过`JSON Schema`校验保证结构化结果质量。

**包设计合理性原则**
1. 领域模型下沉到`runtime.model`，各上层仅依赖模型与契约。
2. 语义摘要能力只依赖`runtime.model`与`runtime.contract`，禁止反向依赖`runtime.step`与`runtime.engine`。
3. 结构化结果校验放在`runtime.structured`子包内，保证与执行层解耦。
4. 记忆写入位于`capabilities.memory.write`，只读取`result/summary`，禁止读取`raw`。
5. 原始输出只允许`runtime.raw`路径可见，主流程不携带原始数据。

---

## `P1`具体改造任务清单

1. **语义摘要入库唯一通道**
   目标：记忆写入仅保存语义摘要与结构化结果，不再序列化原始输出。
   涉及包：`com.example.agent.capabilities.memory.write`
   任务：
   - 修改`MemoryWriteService`，写入字段仅包含`result`与`summary`。
   - 修改`MemoryWriteSerializer`，序列化数据结构对齐`meta/result/decision/summary`。
   - 移除对`raw`与旧`summary`快照字段的依赖。

2. **最终输出主流程一致性**
   目标：最终输出优先使用结构化结果与语义摘要，原始输出仅调试可见。
   涉及包：`com.example.agent.runtime.output`、`com.example.agent.runtime.finalize`
   任务：
   - 在`FinalOutputService`中以`result`为主输出，`summary`作为增强项。
   - 在`RuntimeFinalizationService`中统一封装为`meta/result/decision/summary`。
   - 增加对`rawRef`的调试展示路径，避免主流程携带`raw`。

3. **结构化结果`JSON Schema`校验**
   目标：对结构化结果进行`JSON Schema`校验，失败时降级为兜底结果并记录告警。
   涉及包：`com.example.agent.runtime.structured`
   任务：
   - 新增`StructuredResultSchemaRegistry`，管理各`kind`的`JSON Schema`。
   - 新增`StructuredResultValidator`，校验`kind/schemaVersion/data`。
   - 校验失败时返回标准兜底结构，并记录`warnings`与降级原因。

4. **结构化结果降级策略**
   目标：校验失败或结构化结果缺失时给出可追踪兜底结构。
   涉及包：`com.example.agent.runtime.structured`
   任务：
   - 在`StructuredExtractorRegistry`中统一处理失败降级逻辑。
   - 兜底结果必须包含`kind/schemaVersion/data`与`quality`字段。

5. **主流程输出键收敛**
   目标：所有主流程仅使用`meta/result/decision/summary`键集合。
   涉及包：`com.example.agent.runtime.contract`、`com.example.agent.runtime.output`
   任务：
   - 统一`RuntimeOutputKeys`与`OutputKeys`，收敛旧键名。
   - 清理主流程中对旧`summary`快照字段的访问。

6. **反思与回归一致性补齐**
   目标：反思与回归只读取`result`与语义摘要，不再读取原始输出。
   涉及包：`com.example.agent.reflection`
   任务：
   - 在`ReflectionContextMapper`中仅构建结构化主路径输入。
   - 反思评分使用结构化字段与语义摘要文本。

7. **包依赖边界检查**
   目标：防止`summary`与`structured`子包反向依赖执行层。
   涉及包：`com.example.agent.runtime.summary`、`com.example.agent.runtime.structured`
   任务：
   - 新增或更新`ArchUnit`规则，禁止依赖`runtime.step`与`runtime.engine`。
   - 将公共模型集中在`runtime.model`。

8. **可观测性补充**
   目标：记录结构化校验失败与语义摘要写入结果。
   涉及包：`com.example.agent.runtime.structured`、`com.example.agent.capabilities.memory.write`
   任务：
   - 校验失败输出`warn`日志并记录指标。
   - 记忆写入失败输出`error`日志并保留上下文字段。

9. **测试与样例更新**
   目标：测试覆盖主流程一致性，删除旧快照摘要依赖。
   涉及包：`src/test/java/com/example/agent`
   任务：
   - 更新`FinalOutputServiceTest`与`RuntimeFinalizationServiceTest`的断言结构。
   - 更新`MemoryWriteServiceTest`与序列化测试，覆盖`result/summary`。
   - 增加`StructuredResultValidatorTest`与降级策略测试。

## 验收标准
1. 记忆写入数据中不存在原始输出快照字段，仅保留`result/summary/meta`。
2. 最终输出严格符合`meta/result/decision/summary`协议。
3. 结构化结果均通过`JSON Schema`校验，失败时进入兜底路径并记录告警。
4. 反思流程不读取原始输出或快照摘要字段。

## 测试建议
1. 执行全量测试：`mvn test`。
2. 补充`JSON Schema`校验失败用例，验证降级结果。
3. 补充记忆写入序列化一致性用例。

## 风险与回滚
1. 结构化校验可能导致更多降级结果，需要提前确认`kind/schema`覆盖范围。
2. 记忆写入改造影响历史查询字段，需要同步更新查询与展示路径。
3. 回滚策略：保留旧键解析逻辑在测试与灰度环境中对比输出差异。

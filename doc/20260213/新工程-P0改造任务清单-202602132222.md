# 新工程 P0 改造任务清单（基于包设计合理性）

**依据文档**
`doc/20260213/新工程-语义摘要替换-变更评估-202602132202.md`

**目标**
删除旧 summary 快照链路，建立语义摘要与结构化结果为主的稳定主路径，保证核心包职责清晰、依赖方向单一、可演进。

---

## P0 具体改造任务清单

1. **删除旧 summary 包的主流程依赖**
   - 目标：去除 `runtime.summary` 中旧快照摘要的主路径影响，仅保留必要的诊断指标（如需）。
   - 涉及包：`com.example.agent.runtime.summary`
   - 动作：移除 `StepOutputSummaryBuilder` 在执行链路中的调用，删除 `StepOutputSummaryView` 的反思入口依赖。

2. **建立语义摘要服务与包归属**
   - 目标：新增 `SemanticSummaryService` 作为语义摘要生成入口，包归属明确归 `runtime.summary` 或新建 `runtime.semantic` 子包。
   - 涉及包：`com.example.agent.runtime.summary`
   - 动作：新增语义摘要接口、实现与配置，保证仅依赖结构化结果与决策结果。

3. **输出协议统一为 `meta/result/decision/summary`**
   - 目标：强制主流程只使用结构化 `result`，`summary` 仅用于记忆与上下文。
   - 涉及包：`com.example.agent.runtime.output`、`com.example.agent.runtime.contract`
   - 动作：在 `RuntimeOutputKeys` 与 `OutputKeys` 中加入新协议键，收敛旧键使用。

4. **StepResult 与 StepExecutionOutput 数据结构收敛**
   - 目标：删除旧 summary 结构，替换为语义摘要结构体。
   - 涉及包：`com.example.agent.runtime.model`、`com.example.agent.runtime.step.contract`
   - 动作：调整 `StepResultSummary` -> `SemanticSummary`，`StepExecutionOutput` 移除旧 summary 字段或改为语义摘要字段。

5. **反思链路改为结构化主路径**
   - 目标：反思只使用 `result` + 语义摘要，不依赖原始输出与快照摘要。
   - 涉及包：`com.example.agent.reflection`
   - 动作：重写 `ReflectionContextMapper`，输入改为 `result` + `summary`；反思策略改为结构化字段评估。

6. **最终输出与记忆写入收敛**
   - 目标：最终输出与记忆写入主通道只使用 `result/summary`。
   - 涉及包：`com.example.agent.runtime.output`、`com.example.agent.capabilities.memory.write`
   - 动作：`FinalOutputService` 输出优先结构化结果；`MemoryWriteService` 仅写入语义摘要与必要结构化字段。

7. **原始输出改为调试可见路径**
   - 目标：主流程不携带原始输出，仅保留 `rawRef`。
   - 涉及包：`com.example.agent.runtime.raw`、`com.example.agent.runtime.output`
   - 动作：新增调试读取接口或开关控制，默认关闭原始输出回传。

8. **包依赖方向约束**
   - 目标：确保 `runtime.summary` 只依赖 `runtime.model` 与 `runtime.contract`，不反向依赖执行层。
   - 涉及包：`com.example.agent.runtime.summary`
   - 动作：清理跨层依赖，防止 summary 侵入执行核心路径。

---

## 验收标准（P0）

1. 主流程不再依赖旧 summary 快照链路。
2. 输出协议稳定为 `meta/result/decision/summary`，无旧键混用。
3. 反思/回归完全基于 `result` + 语义摘要运行。
4. 原始输出不进入主流程与记忆主路径，仅通过 `rawRef` 调试可见。

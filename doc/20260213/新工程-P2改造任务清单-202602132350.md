# 新工程-P2改造任务清单（包设计合理性）-202602132350

**依据文档**
`doc/20260213/新工程-语义摘要替换-变更评估-202602132202.md`

**目标**
在`P2`阶段完成语义摘要质量度量与抽检、结构化结果质量评分与完整性检查、反思稳定性评分模型三项核心能力提升，形成可评估、可回溯、可扩展的质量治理闭环。

**包设计合理性原则**
1. 质量度量与评分能力下沉到`runtime.summary`与`runtime.structured`子包内，避免跨层依赖执行层。
2. 反思评分模型位于`reflection.strategy`或`reflection.scoring`子包，严禁读取原始输出。
3. 质量结果通过`StructuredQuality`与语义摘要扩展字段承载，保持协议向后兼容。
4. 抽检与审计写入独立子包，主流程仅携带`rawRef`，不携带原始输出。
5. 所有质量评分与抽检逻辑具备配置开关与阈值，避免硬编码。

---

## `P2`具体改造任务清单

1. **语义摘要质量度量模型**
   目标：对语义摘要给出可量化的质量评分与维度解释。
   涉及包：`com.example.agent.runtime.summary`
   任务：
   - 新增`SemanticSummaryQuality`模型，包含`score/coverage/coherence/missingFields`等维度。
   - 新增`SemanticSummaryQualityScorer`，输入`result/decision/summary`，输出质量评分与说明。
   - 在`StepOutputSummaryBuilder`或语义摘要生成链路中写入质量字段（建议`summary.quality`）。
   - 若评分低于阈值，写入`summary.warnings`并标记`summary.truncated/summary.quality`。

2. **语义摘要抽检与审计机制**
   目标：支持按比例抽检摘要质量，形成可回放的审计数据。
   涉及包：`com.example.agent.runtime.summary.audit`
   任务：
   - 新增`SemanticSummarySampler`，支持按比例或规则抽样。
   - 新增`SemanticSummaryAuditRecord`与持久化接口（仅存`rawRef/result/summary/quality`引用）。
   - 增加抽检开关与阈值配置（例如`agent.summary.audit.*`）。
   - 抽检结果只在调试或灰度环境可见，生产默认关闭详情。

3. **结构化结果质量评分与字段完整性检查**
   目标：基于`kind/schemaVersion/data`对结构化结果质量打分。
   涉及包：`com.example.agent.runtime.structured`
   任务：
   - 新增`StructuredQualityScorer`，根据`kind`定义字段完整性与一致性规则。
   - 在`StructuredExtractorRegistry`校验通过后追加质量评分与完整性告警。
   - 当字段缺失或不一致时写入`StructuredQuality.warnings`，降低`confidence`。
   - 评分与字段覆盖率写入`StructuredQuality`可扩展字段（保持序列化兼容）。

4. **反思稳定性评分模型**
   目标：以结构化结果为主依据建立稳定性评分，决定重试/回归策略。
   涉及包：`com.example.agent.reflection.strategy`
   任务：
   - 新增`ReflectionStabilityScorer`，输入`result/summary`生成稳定性评分与原因。
   - 在`ReflectionStrategySelector`中引入稳定性评分阈值判断。
   - 当评分过低触发回归或重试时，记录评分原因到`ReflectionResult.reason`。

5. **配置与契约收敛**
   目标：为质量评分与抽检提供统一配置与契约约束。
   涉及包：`com.example.agent.runtime.summary`、`com.example.agent.runtime.structured`、`com.example.agent.reflection`
   任务：
   - 新增`SemanticSummaryQualityProperties`与`StructuredQualityProperties`。
   - 统一在`RuntimeOutputKeys`中补充质量字段常量（如`summary.quality`）。
   - 确保新增字段不影响`meta/result/decision/summary`主协议兼容性。

6. **测试与样例补齐**
   目标：覆盖质量评分与抽检的核心路径。
   涉及包：`src/test/java/com/example/agent`
   任务：
   - 新增语义摘要质量评分单测。
   - 新增结构化结果质量评分单测。
   - 新增反思稳定性评分单测。
   - 新增抽检开关与比例抽样单测。

## 验收标准
1. 语义摘要包含质量评分字段，且评分规则可配置。
2. 结构化结果包含完整性评分与告警，缺失字段能触发告警。
3. 反思策略基于稳定性评分控制重试/回归路径。
4. 抽检机制仅存引用与结构化结果，不存原始输出。

## 测试建议
1. 执行全量测试：`mvn test`。
2. 增加低质量摘要与缺失字段的回归用例。
3. 覆盖抽检开关与比例阈值边界场景。

## 风险与回滚
1. 质量评分阈值设置不合理可能导致过度告警。
2. 抽检比例过高可能引起存储压力，需要控制上限。
3. 回滚策略：关闭评分与抽检开关，保留既有主流程。

# budget 包设计合理性 P2 具体改造任务清单

## 1. 任务背景

- 输入依据：`doc/budget-包设计合理性与坏味道评估-202602091221.md`
- 对应问题等级：`P2（中优先级）`
- 本清单目标：将评估文档中的 P2 问题转为可排期、可实施、可验收的工程任务。

## 2. P2 问题范围

### 2.1 问题 3：内存仓储并发与可变对象泄漏风险

- 目标：修复 `InMemoryTokenUsageRepository` 并发写入风险与返回可变集合风险。

### 2.2 问题 4：`ContextCompressionController` 多职责

- 目标：将触发判定、压缩执行、摘要回填等职责分离，降低类复杂度。

### 2.3 问题 5：估算逻辑重复导致一致性漂移风险

- 目标：确保压缩链路、裁剪链路统一走同一估算能力，并补齐一致性守卫测试。

### 2.4 问题 6：`TokenBudgetManager` 职责过重

- 目标：拆分记录、阈值判定、事件发布职责，形成可替换组件边界。

## 3. 总体目标与完成定义

### 3.1 总体目标

- 降低 `budget` 包中等风险问题带来的维护成本与演进风险。
- 将核心链路中的“并发安全、职责边界、一致性保障”提升到可持续扩展水平。
- 在不引入历史兼容分支的前提下，以新方案替换旧实现。

### 3.2 完成定义

- 架构完成定义：
  - `InMemoryTokenUsageRepository` 写路径线程安全，读返回不可变快照。
  - `ContextCompressionController` 仅保留编排职责，核心子能力已组件化。
  - `TokenBudgetManager` 拆成清晰职责组件，主类仅做流程编排。
- 质量完成定义：
  - 新增并发测试、估算一致性测试、架构守卫测试均通过。
  - 每个阶段执行全量 `mvn test` 并通过。

## 5. 具体任务清单

### P2-T01 建立 P2 回归与性能基线

- 改造目标：为后续重构提供客观对照。
- 主要动作：
  - 固化当前 `budget` 相关单测执行结果。
  - 记录 `TokenBudgetManager`、`ContextCompressionController` 关键流程耗时样本。
  - 导出当前关键类的方法数量、代码行数、依赖关系。
- 验收标准：
  - 产出可复用基线记录，能支撑重构前后对比。

### P2-T02 改造 InMemory 仓储为并发安全结构

- 改造目标：消除并发写风险。
- 主要动作：
  - `taskIndex` 的 value 改为线程安全容器。
  - 避免 `computeIfAbsent(...).add(...)` 的并发竞态隐患。
  - 明确幂等写入行为与任务索引写入顺序。
- 验收标准：
  - 并发写入不出现异常、丢写、重复写超预期。

### P2-T03 仓储查询返回不可变快照

- 改造目标：避免外部修改内部状态。
- 主要动作：
  - `findByTask` 返回集合副本并不可变包装。
  - 禁止直接暴露内部引用。
- 验收标准：
  - 调用侧修改返回集合不影响仓储内部状态。

### P2-T04 增加仓储并发与幂等测试

- 改造目标：用测试固化并发语义。
- 主要动作：
  - 增加高并发写入测试（同 task、多 usageId）。
  - 增加重复 usageId 幂等测试。
  - 增加查询结果不可变性测试。
- 验收标准：
  - 测试稳定通过，且重复运行结果一致。

### P2-T05 抽取压缩触发判定策略组件

- 改造目标：从 `ContextCompressionController` 中移出触发判定职责。
- 主要动作：
  - 新建触发策略接口与默认实现（示例：`CompressionTriggerPolicy`）。
  - 承载 `OVER_TOTAL`、`OVER_SECTION` 判定与原因编码逻辑。
  - 冷却判定能力独立封装（示例：`CompressionCooldownService`）。
- 验收标准：
  - `ContextCompressionController` 不再内联复杂触发判定分支。

### P2-T06 抽取压缩执行组件

- 改造目标：隔离外部依赖调用与异常语义。
- 主要动作：
  - 新建压缩执行组件（示例：`CompressionExecutionService`）。
  - 包含 `memoryStore.compress` 调用、耗时统计、失败日志。
  - 统一执行结果对象，减少控制器内条件分支。
- 验收标准：
  - 控制器中外部调用细节显著减少，异常路径可单测。

### P2-T07 抽取摘要回填组件

- 改造目标：隔离摘要回填与快照变更逻辑。
- 主要动作：
  - 新建回填组件（示例：`CompressionSummaryApplier`）。
  - 承担 `applyCompressedSummary` 与相关字段映射。
  - 明确回填边界：工作记忆、长期记忆引用、版本字段。
- 验收标准：
  - 回填逻辑可独立测试，控制器仅做调用编排。

### P2-T08 统一估算链路并补一致性守卫

- 改造目标：彻底杜绝“同快照不同估算结果”。
- 主要动作：
  - 强制压缩、裁剪链路全部使用统一估算组件。
  - 补充一致性守卫测试：
    - 有 trimReport 情况。
    - 无 trimReport 情况。
    - 边界输入（空快照、空字段、仅单分段）。
- 验收标准：
  - 关键场景下估算结果一致，测试覆盖到边界条件。

### P2-T09 拆分 TokenBudgetManager 记录职责

- 改造目标：抽离记录构建与保存职责。
- 主要动作：
  - 抽取记录构建组件（示例：`TokenUsageRecordFactory`）。
  - 抽取记录持久化组件（示例：`TokenUsageRecorder`）。
  - 保持 `TokenBudgetManager` 主流程行为不变。
- 验收标准：
  - `TokenBudgetManager` 不再直接承担记录对象细节拼装。

### P2-T10 拆分 TokenBudgetManager 阈值与事件职责

- 改造目标：拆出阈值判定与事件发布能力。
- 主要动作：
  - 抽取阈值判定组件（示例：`BudgetThresholdEvaluator`）。
  - 抽取事件发布组件（示例：`BudgetEventPublisher`）。
  - 模型降级决策调用收敛到专用协作类。
- 验收标准：
  - `TokenBudgetManager` 聚焦流程编排，依赖职责单一组件。

### P2-T11 补充架构守卫与端到端回归

- 改造目标：防止职责回流与架构退化。
- 主要动作：
  - 增加 `budget` 包架构守卫测试：
    - 控制器不得直接调用底层外部适配器实现细节。
    - 业务编排类不得回落到大而全实现。
  - 增加端到端回归测试：预算分配→裁剪→压缩→事件/指标。
- 验收标准：
  - 守卫规则可拦截违规代码，回归用例稳定通过。

### P2-T12 完善文档与发布说明

- 改造目标：保障可交接、可运维、可回滚。
- 主要动作：
  - 更新包结构说明、组件职责图、调用时序图。
  - 输出配置影响面与风险说明。
  - 输出灰度与回滚步骤。
- 验收标准：
  - 文档可直接用于评审、发布、运维排障。

## 6. 执行顺序建议

- 第一批（并发安全优先）：`P2-T01 -> P2-T02 -> P2-T03 -> P2-T04`
- 第二批（压缩职责拆分）：`P2-T05 -> P2-T06 -> P2-T07 -> P2-T08`
- 第三批（预算管理拆分）：`P2-T09 -> P2-T10`
- 收口批：`P2-T11 -> P2-T12`

## 8. 风险与应对

- 风险 1：组件拆分后 Bean 装配歧义或循环依赖。
  - 应对：优先接口注入，严格单向依赖，必要时显式 `@Qualifier`。
- 风险 2：阈值触发逻辑在重构中行为漂移。
  - 应对：先补基线测试，再拆分；拆分后保留行为对照断言。
- 风险 3：并发测试偶发不稳定导致误判。
  - 应对：采用可重复并发测试模式，控制线程池与等待策略。

## 9. 预期收益

- `budget` 包中等风险问题消除后，结构稳定性与可维护性明显提升。
- 关键链路可测试性增强，后续 P3/P4 优化成本降低。
- 预计整体包设计等级可从 `B+` 进一步提升至 `A-` 区间。

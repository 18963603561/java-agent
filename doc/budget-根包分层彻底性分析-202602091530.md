# budget 根包分层彻底性分析

## 1. 结论先行

- 结论：`com.example.agent.budget` 当前分层 **有明显进步，但仍不彻底**。
- 分层彻底性等级（仅针对“根包分层维度”）：`B+`。
- 风险等级：`P3（低风险）`。
- 判断依据：
  - 已建立 `core -> token/trim` 的主方向，且有守卫测试兜底。
  - 但仍存在“同层混放多角色职责”“核心层混入框架配置语义”“目录残留”等结构信号，说明分层尚未完全收口。

## 2. 结构现状快照

### 2.1 根包目录

- 当前目录：`core`、`cost`、`token`、`trim`。
- 其中 `cost` 目录已无 Java 源码（源码已迁移到 `token/pricing`），但根目录仍残留空层级。

### 2.2 主要优点（已完成的分层改进）

- `token` 与 `trim` 已不再互相直接依赖，主要通过 `core` 模型协作。
- `budget` 已有守卫测试约束依赖方向与命名语义：
  - `src/test/java/com/example/agent/budget/BudgetArchitectureGuardTest.java`
- 预算分配语义已从判空迁移为显式状态对象，降低了跨层分支噪音。

## 3. 为什么说“还不彻底”

### 3.1 `core` 仍混入框架配置语义（核心层纯度不足）

- 证据：
  - `src/main/java/com/example/agent/budget/core/ContextBudgetProperties.java`
  - 该类同时使用 `@Component` 与 `@ConfigurationProperties`。
- 分析：
  - `core` 本应偏稳定模型与规则抽象；配置装配语义属于框架适配层。
  - 当前会导致“核心层携带运行时框架语义”，影响核心层可移植性与纯度。

### 3.2 `token` 子包仍是“多角色同层并排”

- 证据（同一包同时存在多类角色）：
  - 应用编排：`TokenBudgetManager`
  - 仓储接口：`TokenUsageRepository`
  - 仓储实现：`InMemoryTokenUsageRepository`、`JdbcTokenUsageRepository`
  - 事件发布接口/实现：`BudgetEventPublisher`、`DefaultBudgetEventPublisher`
  - 领域数据模型：`TokenUsageRecord`、`TokenUsageSummary`
  - 定价组件：`token/pricing/CostCalculator`
- 分析：
  - 虽然职责已经拆出来了，但包层次仍未把“接口/实现/模型/编排”完全分层。
  - 目前是“类级解耦优于包级解耦”。

### 3.3 `trim` 子包同样存在“编排+模型+处理器+配置”混放

- 证据：
  - 编排服务：`ContextCompressionService`、`DefaultContextTrimmer`、`DefaultContextPruner`
  - 请求结果模型：`ContextTrimRequest`、`ContextTrimReport`、`ContextCompressionResult`
  - 处理器实现：`WorkingMemoryTrimHandler`、`TaskAndSystemTrimHandler` 等
  - 配置类：`ContextCompressionProperties`
  - 估算组件：`ContextTokenEstimator` 及多个子估算器
- 分析：
  - 已具备组件拆分基础，但“包层次”尚未将 application/domain/infrastructure/support 拉开。

### 3.4 根包存在历史残留空目录信号

- 证据：`src/main/java/com/example/agent/budget/cost` 目录仍存在（无源码）。
- 分析：
  - 虽然不影响运行，但会给阅读者传达“仍有独立子域”的错误预期。

## 4. 结论解释（为什么仍评为 B+ 而非更低）

- 不彻底 ≠ 不可用。
- 当前结构已经具备：
  - 明确的预算核心模型。
  - 主链路组件化与守卫测试。
  - 关键坏味道（循环依赖、null 语义、命名错位）已治理。
- 因此问题更多是“包层次整洁度与长期演进形态”，不是“阻塞性架构问题”。

## 5. 建议的收口方向（按投入产出排序）

### 5.1 快速收口（低成本）

- 删除空目录：`src/main/java/com/example/agent/budget/cost`。
- 在守卫测试中增加“根包禁止空历史目录回流”的规则。

### 5.2 中成本优化（推荐）

- 将 `ContextBudgetProperties` 从 `core` 移到更贴近配置装配的子层（如 `budget/config` 或 `budget/token/config`）。
- 将 `token` 拆出更清晰层次：
  - `token/model`
  - `token/application`
  - `token/repository`
  - `token/pricing`
  - `token/event`

### 5.3 进一步演进（可选）

- 将 `trim` 拆出层次：
  - `trim/model`
  - `trim/application`
  - `trim/handler`
  - `trim/estimator`
  - `trim/config`
- 保持现有 API 对外不变，通过包内重组持续演进。

## 6. 最终判断

- 你问“根包是不是分层还不彻底”：**是，确实还不彻底**。
- 但这已经是“结构收口阶段问题”，不是“架构失稳阶段问题”。
- 当前最值得做的是：
  - 清理历史空层级。
  - 把 `core` 的框架配置语义迁出。
  - 对 `token/trim` 做包级分层细化。

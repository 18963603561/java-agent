# `com.example.agent.capabilities.llm` 包设计合理性与坏味道评审

## 1. 评审范围

- 评审目录：`src/main/java/com/example/agent/capabilities/llm`
- 评审对象：`llm` 包及其 `repair` 子包全部 Java 文件
- 评审维度：包结构、职责边界、可维护性、可扩展性、可测试性、可观测性、代码坏味道
- 评审方式：静态代码审阅 + 关键实现抽样 + 现有测试覆盖面核对

## 2. 总体结论与等级

### 2.1 总体等级

- **总体等级：B（72/100）**
- 结论：当前实现具备可运行的工程基础和较好的日志观测能力，但核心类过大、上下文强依赖 `Map<String, Object>`、部分策略开关语义不一致，导致后续演进成本与回归风险偏高。

### 2.2 分维度评分

- 职责分层：7/10
- 抽象设计：8/10
- 模块内聚：5/10
- 扩展能力：6/10
- 可观测性：8/10
- 可测试性：6/10
- 稳定性与防御性：5/10

## 4. 主要坏味道与分级

###[高] 4.1 “巨石类”与职责混杂：`DefaultModelProvider`

- 现象：单类 1492 行、46 个方法、分支密度高，混合了“提供商路由 + HTTP 调用 + 请求组装 + 响应解析 + 本地兜底策略 + 多场景本地协议”。
- 证据：
  - 类规模：`src/main/java/com/example/agent/capabilities/llm/DefaultModelProvider.java:40`
  - 提供商选择：`src/main/java/com/example/agent/capabilities/llm/DefaultModelProvider.java:161`
  - 本地兜底分发：`src/main/java/com/example/agent/capabilities/llm/DefaultModelProvider.java:677`
  - 多场景本地响应构造：`src/main/java/com/example/agent/capabilities/llm/DefaultModelProvider.java:994`
  - `LLM_STEP` 工具总结硬编码业务文案：`src/main/java/com/example/agent/capabilities/llm/DefaultModelProvider.java:1145`
- 风险：需求增加时，改动面广、回归点多、语义耦合深，容易引入隐藏回归。

###[高] 4.2 事件发布逻辑“注释失活”，文档语义与实际行为不一致

- 现象：`ModelInvocationService` 中提示词事件与输出解析事件构建完 payload 后未实际发布。
- 证据：
  - 被注释调用：
    - `src/main/java/com/example/agent/capabilities/llm/ModelInvocationService.java:224`
    - `src/main/java/com/example/agent/capabilities/llm/ModelInvocationService.java:262`
- 风险：上游以为有事件流，实际丢观测；排障与审计链路会出现“看似可追踪，实则缺数据”。

###[中] 4.3 配置语义不一致：`fallbackEnabled` 与实际路由行为脱节

- 现象：配置对象定义了 `fallbackEnabled`，但 `ModelRouter` 路由时无条件尝试回退模型。
- 证据：
  - 配置项定义：`src/main/java/com/example/agent/capabilities/llm/ModelConfigProperties.java:26`
  - 路由逻辑未检查该开关：`src/main/java/com/example/agent/capabilities/llm/ModelRouter.java:49`
- 风险：运维配置与实际行为不一致，灰度/故障切换策略不透明。

###[中] 4.4 强 `Map` 协议与字符串键泛滥，类型约束偏弱

- 现象：多处依赖 `Map<String, Object>` + 魔法键（例如 `toolChoice`、`allowTools`、`disableTools`、`promptTrace`）。
- 证据：
  - `ModelToolResolver`：`src/main/java/com/example/agent/capabilities/llm/ModelToolResolver.java:110`
  - `ModelInvocationService`：`src/main/java/com/example/agent/capabilities/llm/ModelInvocationService.java:129`
  - `JsonOutputRepairService`：`src/main/java/com/example/agent/capabilities/llm/repair/JsonOutputRepairService.java:61`
- 风险：键名拼写错误与类型漂移在编译期无法发现，问题只能在运行时暴露。

###[中] 4.5 防御性不足的空值处理点

- 现象：少量路径对关键参数缺少防御，存在潜在空指针风险。
- 证据：
  - `DefaultLlmClient.generate` 未防御 `request == null`：
    - `src/main/java/com/example/agent/capabilities/llm/DefaultLlmClient.java:73`
  - `ModelFallbackPolicy.evaluate` 直接访问 `tenantContext.getTenantId()`：
    - `src/main/java/com/example/agent/capabilities/llm/ModelFallbackPolicy.java:48`
- 风险：边界场景（异常重试、修复链路、测试桩）可能触发运行时错误。

###[低] 4.6 可测试性小瑕疵：模板解析器未纳入容器注入

- 现象：`DefaultPromptTemplate` 内部直接 `new PromptTemplateResolver()`。
- 证据：
  - `src/main/java/com/example/agent/capabilities/llm/DefaultPromptTemplate.java:35`
- 风险：替换策略、模拟注入、跨模板复用会受限。

## 5. 包结构合理性评价

当前 `llm` 包里既有：

- 配置与路由（`ModelConfigProperties` / `ModelRouter` / `ModelRegistry`）
- 调用入口与编排（`LlmClient` / `ModelInvocationService`）
- 提示词构建（`Prompt*`）
- 工具治理（`ModelToolResolver` / `ModelTool*`）
- 修复流程（`repair`）
- 供应商适配与本地兜底（`DefaultModelProvider`）

**评价：整体功能完整，但聚合度偏高。**
建议按职责拆子包，避免继续在 `llm` 根包叠加实现细节。

## 6. 优先级整改建议

### P0（立即，1 个迭代内）

1. 拆分 `DefaultModelProvider`：
   - 建议拆为 `ProviderRouter`、`OpenAiProviderAdapter`、`OllamaProviderAdapter`、`LocalFallbackStrategy`、`ResponseParser`。

2. 处理事件发布失活问题：
   - 明确“是否发布事件”的统一策略。
   - 若需要开关，改为可配置并显式日志说明；避免注释掉核心行为。

3. 统一 `fallbackEnabled` 语义：
   - 在 `ModelRouter` 和 `ModelFallbackPolicy` 上保持一致，避免“配置可写但行为无效”。

### P1（短期，1~2 个迭代）

1. 将高频 `Map` 协议替换为强类型对象（尤其是工具约束与修复元数据）。
2. 为 `ModelInvocationService`、`JsonOutputRepairService` 补齐独立单测。
3. 补充关键空值保护与参数校验。

### P2（中期）

1. 目录重构建议：
   - `llm.client`
   - `llm.provider`
   - `llm.prompt`
   - `llm.tooling`
   - `llm.repair`
   - `llm.config`
2. 输出统一协议与错误码映射规范，减少跨类重复分支。

## 7. 最终评级结论

- **当前可用性：中上（B）**
- **持续演进风险：中高**
- **推荐策略：优先做“提供商层拆分 + 事件链路修复 + 配置语义统一”，再做类型化改造。**

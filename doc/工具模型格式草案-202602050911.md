# 工具模型格式草案（StepInput/StepOutput/EvidencePack）

**设计目标**
面向新工程统一 `Step` 输入输出与 `EvidencePack` 格式，保证可编排、可审计、可回放、可扩展。

**核心原则**
`raw` 可追溯，`structured` 可编排，`summary` 可读，`refs` 可审计。
证据写入单入口：仅 `Hook` 写入 `EvidencePack`，业务层禁止直接写证据。
证据包为索引层，不存大文本，仅存 `ref` 与 `digest`。
`structured` 使用统一外壳 `kind/schemaVersion/data/quality/refs`，后续步骤仅依赖 `structured`。
版本兼容只新增字段，不改变语义，不删除字段。

**通用约定**
字段命名使用小驼峰，枚举使用大写英文常量。
时间统一为 `ISO-8601` 字符串，例如 `2026-02-05T09:11:00Z`。
`null` 表示未知，空集合表示已知为空，缺失字段表示不适用。
禁止在 `StepOutput` 与 `EvidencePack` 中携带完整 `raw` 正文。

**StepInput 结构**
用于执行单个步骤的稳定输入契约，后续步骤依赖 `upstream.structured` 与 `upstream.refs`。

`StepInput` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`question` | string | 是 | 本步骤要解决的问题或目标。
`stepId` | string | 否 | 上游可填，运行时可重写。
`stepType` | string | 是 | 例如 `LLM`、`TOOL`、`RESEARCH`、`REACT`。
`dependsOn` | array<string> | 否 | 依赖的上一步 `stepId` 列表。
`contextRefs` | array<string> | 否 | 上下文引用列表，如 `ep:pack-xxx`。
`upstream` | object | 否 | 依赖步骤输出映射，键为 `stepId`。
`constraints` | object | 否 | 约束信息，如 `maxRows`、`maxTokens`。
`policy` | object | 否 | 运行策略，如 `retryMax`、`timeoutMs`。
`debug` | object | 否 | 调试字段，运行时可忽略。

`StepUpstream` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`structured` | object | 是 | 上一步 `structured.data` 的镜像或子集。
`refs` | object | 否 | `rawRef`、`evidenceRef`、`memoryRef` 等引用。
`summary` | string | 否 | 供模型理解的简短摘要。

`StepInput` 示例
```json
{
  "question": "查找包含手机号字段的表",
  "stepId": "step-2",
  "stepType": "TOOL",
  "dependsOn": ["step-1"],
  "contextRefs": ["ep:pack-001"],
  "upstream": {
    "step-1": {
      "structured": {
        "tablesWithMobile": ["t_user", "t_order"]
      },
      "refs": {
        "rawRef": "raw:tool:abc",
        "evidenceRef": "ev:tool:001"
      },
      "summary": "命中2张表：t_user,t_order"
    }
  },
  "constraints": {
    "maxRows": 50
  },
  "policy": {
    "timeoutMs": 10000,
    "retryMax": 1
  }
}
```

**StepOutput 结构**
用于落库与回放的稳定输出契约，必须包含 `meta`，建议包含 `rawRef`。

`StepOutput` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`meta` | object | 是 | 步骤元信息。
`rawRef` | object | 否 | 原始结果引用，`tool/llm` 步骤应填写。
`structured` | object | 是 | 结构化结果，供后续步骤依赖。
`summary` | object | 否 | 摘要层，供模型与审计使用。
`refs` | object | 否 | 补充引用，例如 `memoryRef`、`citationRef`。
`errors` | array<object> | 否 | 错误列表，失败时必须填充。

`StepMeta` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`stepId` | string | 是 | 步骤标识。
`seq` | integer | 是 | 运行序号。
`type` | string | 是 | `TOOL/LLM/RESEARCH/REACT`。
`status` | string | 是 | `COMPLETED/FAILED`。
`toolName` | string | 否 | 工具名称。
`modelId` | string | 否 | 模型标识。
`attempt` | integer | 否 | 重试次数。
`timings` | object | 否 | `startedAt/endedAt/durationMs`。

`StructuredResult` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`kind` | string | 是 | 语义类型，例如 `TABLE_MATCHES`。
`schemaVersion` | integer | 是 | 数据结构版本。
`data` | object | 是 | `kind` 专属结构，必须稳定。
`quality` | object | 否 | `confidence/warnings/truncated`。
`refs` | object | 否 | `rawRef/evidenceIds` 等。

`StepSummary` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`text` | string | 否 | 短文本摘要。
`json` | object | 否 | 可选结构化摘要。
`truncation` | object | 否 | 截断状态与原因。

`StepError` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`code` | string | 是 | 错误码。
`message` | string | 是 | 错误描述。
`retryable` | boolean | 否 | 是否可重试。

`StepOutput` 示例
```json
{
  "meta": {
    "stepId": "step-2",
    "seq": 2,
    "type": "TOOL",
    "status": "COMPLETED",
    "toolName": "fmdb.search",
    "attempt": 1,
    "timings": {
      "startedAt": "2026-02-05T09:11:00Z",
      "endedAt": "2026-02-05T09:11:01Z",
      "durationMs": 1000
    }
  },
  "rawRef": {
    "store": "object",
    "key": "raw:tool:abc",
    "size": 2048,
    "mediaType": "application/json",
    "createdAt": "2026-02-05T09:11:01Z",
    "hash": "sha256:xxxx"
  },
  "structured": {
    "kind": "TABLE_MATCHES",
    "schemaVersion": 1,
    "data": {
      "items": [
        {
          "table": "t_user",
          "column": "mobile",
          "matchType": "NAME",
          "score": 0.92,
          "reason": "列名包含 mobile"
        }
      ],
      "topTables": ["t_user"],
      "missingRequiredFields": []
    },
    "quality": {
      "confidence": 0.92,
      "warnings": [],
      "truncated": false
    },
    "refs": {
      "rawRef": "raw:tool:abc"
    }
  },
  "summary": {
    "text": "命中1张表：t_user，字段 mobile",
    "truncation": {
      "truncated": false
    }
  },
  "refs": {
    "evidenceIds": ["ev:tool:001"]
  },
  "errors": []
}
```

**EvidencePack 结构**
用于审计与回放的证据索引层，严格 `append-only`。

`EvidencePack` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`packId` | string | 是 | 证据包标识。
`tenantId` | string | 是 | 租户标识。
`workflowId` | string | 是 | 工作流标识。
`snapshotId` | string | 否 | 快照标识。
`createdAt` | string | 是 | 创建时间。
`evidences` | array<object> | 是 | 证据项列表。
`stats` | object | 否 | 统计信息。
`index` | object | 否 | 二级索引，加速查询。

`EvidenceItem` 字段定义
字段 | 类型 | 必填 | 说明
---|---|---|---
`evidenceId` | string | 是 | 证据标识。
`type` | string | 是 | `TOOL_RESULT/MEMORY/RESEARCH/CONTEXT_TRUNCATION`。
`stepId` | string | 否 | 关联步骤。
`source` | string | 否 | 工具名或来源标识。
`ref` | string | 是 | 指向 `rawRef`、`memoryId` 或引用地址。
`digest` | string | 否 | 简短摘要。
`createdAt` | string | 是 | 写入时间。

`EvidencePack` 示例
```json
{
  "packId": "ep-001",
  "tenantId": "t1",
  "workflowId": "wf-1",
  "snapshotId": "snap-1",
  "createdAt": "2026-02-05T09:11:00Z",
  "evidences": [
    {
      "evidenceId": "ev:tool:001",
      "type": "TOOL_RESULT",
      "stepId": "step-2",
      "source": "fmdb.search",
      "ref": "raw:tool:abc",
      "digest": "rows=120, cols=8",
      "createdAt": "2026-02-05T09:11:01Z"
    },
    {
      "evidenceId": "ev:memory:010",
      "type": "MEMORY",
      "stepId": "step-1",
      "source": "memory_store",
      "ref": "memory:m-77",
      "digest": "summaryVersion=v1",
      "createdAt": "2026-02-05T09:11:02Z"
    },
    {
      "evidenceId": "ev:research:100",
      "type": "RESEARCH",
      "stepId": "step-3",
      "source": "https://example.com/doc",
      "ref": "citation:abc",
      "digest": "snippet=...",
      "createdAt": "2026-02-05T09:11:03Z"
    }
  ],
  "stats": {
    "toolCount": 1,
    "memoryCount": 1,
    "researchCount": 1,
    "approxChars": 180
  },
  "index": {
    "byStepId": {
      "step-2": ["ev:tool:001"],
      "step-1": ["ev:memory:010"]
    },
    "byType": {
      "TOOL_RESULT": ["ev:tool:001"],
      "MEMORY": ["ev:memory:010"],
      "RESEARCH": ["ev:research:100"]
    }
  }
}
```

**Java DTO 草案**
`StepInput` 与 `StepOutput`
```java
public class StepInput {
    private String question;
    private String stepId;
    private String stepType;
    private List<String> dependsOn;
    private List<String> contextRefs;
    private Map<String, StepUpstream> upstream;
    private Map<String, Object> constraints;
    private Map<String, Object> policy;
    private Map<String, Object> debug;
}

public class StepUpstream {
    private Map<String, Object> structured;
    private Map<String, String> refs;
    private String summary;
}

public class StepOutput {
    private StepMeta meta;
    private RawRef rawRef;
    private StructuredResult structured;
    private StepSummary summary;
    private Map<String, Object> refs;
    private List<StepError> errors;
}

public class StepMeta {
    private String stepId;
    private long seq;
    private String type;
    private String status;
    private String toolName;
    private String modelId;
    private Integer attempt;
    private StepTiming timings;
}

public class StepTiming {
    private String startedAt;
    private String endedAt;
    private Long durationMs;
}

public class StepError {
    private String code;
    private String message;
    private Boolean retryable;
}
```

`RawRef` 与 `StructuredResult`
```java
public class RawRef {
    private String store;
    private String key;
    private Long size;
    private String mediaType;
    private String createdAt;
    private String hash;
}

public class StructuredResult {
    private String kind;
    private Integer schemaVersion;
    private Map<String, Object> data;
    private StructuredQuality quality;
    private StructuredRefs refs;
}

public class StructuredQuality {
    private Double confidence;
    private List<String> warnings;
    private Boolean truncated;
}

public class StructuredRefs {
    private String rawRef;
    private List<String> evidenceIds;
}
```

`StepSummary`
```java
public class StepSummary {
    private String text;
    private Map<String, Object> json;
    private SummaryTruncation truncation;
}

public class SummaryTruncation {
    private Boolean truncated;
    private String reason;
}
```

`EvidencePack`
```java
public class EvidencePack {
    private String packId;
    private String tenantId;
    private String workflowId;
    private String snapshotId;
    private String createdAt;
    private List<EvidenceItem> evidences;
    private EvidenceStats stats;
    private EvidenceIndex index;
}

public class EvidenceItem {
    private String evidenceId;
    private String type;
    private String stepId;
    private String source;
    private String ref;
    private String digest;
    private String createdAt;
}

public class EvidenceStats {
    private Integer toolCount;
    private Integer memoryCount;
    private Integer researchCount;
    private Integer approxChars;
}

public class EvidenceIndex {
    private Map<String, List<String>> byStepId;
    private Map<String, List<String>> byType;
}
```

**ResultKind 建议枚举**
`TABLE_MATCHES`、`SQL`、`RECORDSET`、`ENTITY_LIST`、`DECISION`、`DIAGNOSIS`、`DOCUMENT_CITATIONS`、`ERROR`。

**校验与约束建议**
`StepOutput.meta` 必须存在，`StepOutput.structured` 必须存在。
`rawRef` 必须可回溯且不可直接嵌入 `raw`。
`summary.text` 需受 `maxChars` 控制，默认建议不超过 `512` 字符。
`EvidencePack` 仅 `append-only`，禁止覆盖或删除历史证据项。

**版本策略**
`StructuredResult.schemaVersion` 仅递增。
`EvidencePack` 版本由 `packId` 旁路字段 `version` 管理，默认 `v1`。
兼容策略为“只增不改”，必要时提供双写过渡。

# governance 可观测规范与告警基线

## 1. 背景与目标

- 本文档用于收敛 `governance` 模块在审批、回放、限流、熔断四个域的日志与指标规范。
- 输出统一日志字段模板与指标命名词典，减少观测口径漂移。
- 给出可直接落地的最低告警基线，支撑日常值班与故障演练。

## 2. 统一日志字段模板

### 2.1 必填字段

- `tenantId`：租户标识。
- `workflowId`：工作流标识，若当前无工作流可填 `null`。
- `taskId`：任务标识，若当前不涉及任务可填 `null`。
- `requestId`：请求标识。
- `traceId`：链路标识。
- `domain`：治理领域，取值建议：`approval/replay/ratelimit/circuit/evaluation`。
- `action`：动作语义，取值建议：`request/decide/await/run/allow/record_failure/evaluate`。
- `result`：结果语义，取值建议：`started/completed/approved/rejected/timeout/failed`。

### 2.2 日志级别规范

- `info`：关键流程开始、结束、状态切换。
- `debug`：规则命中、分支细节、耗时细节。
- `warn`：可恢复异常或保护性拒绝（限流、熔断、参数缺失）。
- `error`：不可恢复异常，必须携带上下文字段与堆栈。

## 3. 统一指标命名词典

### 3.1 命名约束

- 前缀统一：`governance.`。
- 结构建议：`governance.<domain>.<action>.<metric>`。
- 计数指标统一后缀：`.total`。
- 耗时指标统一后缀：`.duration_ms`。

### 3.2 当前治理核心指标

- 审批域
  - `governance.approval.request.total`
  - `governance.approval.decide.total`
  - `governance.approval.decision.total`
  - `governance.approval.await.duration_ms`
- 回放域
  - `governance.replay.run.total`
  - `governance.replay.resolve_task.total`
- 限流域
  - `governance.ratelimit.allow.total`
- 熔断域
  - `governance.circuit.allow.total`
  - `governance.circuit.record_failure.total`
  - `governance.circuit.state_change.total`
- 能力评估域
  - 事件日志中输出命中规则摘要（`ruleHits`），可作为审计证据。

## 4. 最低告警基线建议

### 4.1 限流拒绝率

- 指标：`governance.ratelimit.allow.total`
- 统计窗口：5 分钟滚动窗口。
- 告警口径：`result in [rejected_threshold,rejected_capacity,rejected_blank_key] / 全量 allow`。
- 建议阈值：`>= 20%` 连续 3 个窗口触发告警。

### 4.2 熔断打开频率

- 指标：`governance.circuit.state_change.total`
- 统计窗口：10 分钟。
- 告警口径：`result=closed_to_open` 的计数。
- 建议阈值：单租户 `>= 5` 次触发，或全局 `>= 20` 次触发。

### 4.3 审批超时率

- 指标：`governance.approval.decision.total`
- 统计窗口：15 分钟。
- 告警口径：`result=timeout / 全量 decision`。
- 建议阈值：`>= 10%` 且样本数 `>= 30` 时触发。

### 4.4 回放失败率

- 指标：`governance.replay.resolve_task.total`
- 统计窗口：15 分钟。
- 告警口径：`result in [failed,exception] / 全量 resolve_task`。
- 建议阈值：`>= 5%` 连续 2 个窗口触发。

## 5. 演练与排障建议

- 先看 `result` 分布，再按 `domain/action` 下钻；避免直接从异常堆栈切入。
- 回放故障优先检查 `resolve_task` 的 `not_found/failed/exception` 分布，快速区分业务不存在与系统异常。
- 审批故障优先看 `decision.total` 中 `timeout` 占比，并联动 `await.duration_ms` 判断是否为审批链路拥塞。
- 限流/熔断波动优先看是否集中在单租户，必要时加上 `tenantId` 维度限流与熔断阈值调优。

- 在值班手册中补充“告警 -> 指标 -> 日志 -> 处置”标准流程。

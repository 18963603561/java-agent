# 按里程碑的验收检查清单

**使用说明**
- 每个里程碑包含“必验项”和“可选项”。
- 必验项必须全部通过，才视为该里程碑完成。
- 可选项用于增强质量与可观测性，不影响里程碑基础验收。

## 里程碑一：`runtime.raw` 与 `runtime.structured` 落地
**目标**：形成可回溯 `rawRef` 与可编排 `structured`，输出稳定 `StepOutput` 契约。

必验项
- `StepOutput` 结构稳定，包含 `meta + rawRef + structured + summary + errors`（允许 `summary/errors` 为空）。
- `raw` 不再直接进入 `StepOutput` 或上下文，统一通过 `rawRef` 引用。
- `StructuredResult` 外壳字段完整：`kind/schemaVersion/data/quality/refs`。
- `StructuredExtractorRegistry` 能按 `tool/model` 选择 extractor，并在失败时输出 `ERROR` kind。
- `StepRuntimeService` 完成步骤时输出 `StepOutput`，不再仅返回 `Map`。

可选项
- 为 `ResultKind` 提供最小 `data` 校验与单元测试。
- `rawRef` 具备 `hash/size/mediaType` 字段。
- 输出摘要优先基于 `structured`，`raw` 仅用于统计补充。

验收证据
- 关键流程的 `StepOutput` 样例（至少 `TOOL` 与 `LLM` 各 1 份）。
- `StructuredExtractorRegistry` 的选择逻辑与失败兜底示例。

## 里程碑二：`context.evidence` 改造与 `tools.hook` 收口
**目标**：证据写入单入口，`EvidencePack` 为索引层。

必验项
- `EvidencePack` 结构完成迁移：`packId/evidences/stats/index` 为主结构。
- `EvidenceItem` 字段统一为 `evidenceId/type/stepId/source/ref/digest/createdAt`。
- 证据写入仅发生在 `Hook`，业务层不再直接调用 `EvidencePackService`。
- `HookType` 增加 `POST_RECALL/POST_RESEARCH/POST_TRIM`。
- `EvidencePackService` 仅负责追加与统计，不判断写入时机。

可选项
- `EvidencePack` 增加 `index.byStepId/byType`。
- `EvidencePackHookHandler` 支持 `EvidenceDigest` 复用，避免重复解析。

验收证据
- Hook 事件触发后证据项落地记录。
- 业务层（Tool/Memory/Research）无 `EvidencePack` 写入调用。

## 里程碑三：`model` 与 `context.assembly` 注入对齐
**目标**：提示词注入顺序与证据注入一致，保证上下文可审计。

必验项
- `DefaultContextAssembler` 按顺序注入 `structured → summary → refs`。
- `DefaultPromptAssembler` 支持 `EvidencePack` 注入文本或引用列表。
- `PromptAssemblyInput` 能承载 `evidence` 相关字段。

可选项
- `EvidencePackFormatter` 提供可配置格式模板。
- 提示词裁剪策略对 `EvidencePack` 有明确预算上限。

验收证据
- Prompt 组装输出中包含可审计的证据提示段。

## 里程碑四：`streaming` 与回放统计对齐
**目标**：证据统计字段一致，回放与审计链路完整。

必验项
- `ContextEventPublisher` 使用新 `EvidenceStats` 字段口径输出。
- `ContextSnapshotEventPayload` 统计字段与 `EvidencePack` 一致。
- 回放接口能读取 `StepOutput` 并展示 `structured/summary/refs`。

可选项
- 事件中附带 `evidencePackVersion` 与 `approxChars`。
- 关键事件保留 `stepId` 与 `evidenceId` 关联。

验收证据
- 事件流样例含 `evidencePackPresent/ToolCallsCount/CitationsCount` 等字段。
- 回放结果可追溯 `rawRef` 与证据索引。

**附录：验收常见失败模式**
- `raw` 仍出现在步骤输出或上下文中。
- `EvidencePack` 被业务层直接写入。
- `structured` 缺失或 `data` 结构不稳定。
- Hook 未覆盖 `memory/research/trim` 证据写入。

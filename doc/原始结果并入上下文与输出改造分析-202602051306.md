# 原始结果并入上下文与输出改造分析

## 一、需求理解
- 目标：在“上下文”和“任务输出结果”中同时包含原始结果，不再只有摘要信息。
- 现状：当前主链路对外暴露以摘要为主，原始结果大多未进入运行上下文和任务结果。

## 二、现状定位（代码事实）

### 1. 运行上下文当前只保留摘要
- `AgentRuntime.updateRuntimeContext(...)` 仅写入 `lastStepSummary`，并显式移除 `lastStepOutput`。
- 位置：`src/main/java/com/example/agent/runtime/AgentRuntime.java:1291`
- 位置：`src/main/java/com/example/agent/runtime/AgentRuntime.java:1292`

### 2. 任务结果中的 `steps` 当前是摘要结构
- `recordStepOutput(...)` 将 `entry.output` 固定为 `buildStepOutputSummary(...)` 的结果。
- 位置：`src/main/java/com/example/agent/runtime/AgentRuntime.java:1319`
- 任务持久化时直接写入 `runtimeResult.getSteps()`。
- 位置：`src/main/java/com/example/agent/orchestrator/TaskOrchestrator.java:564`

### 3. 步骤落库输出虽有 `rawRef` 能力，但不含原始结果体
- `StepOutput` 有 `rawRef` 字段，但没有 `rawResult/rawData` 字段。
- 位置：`src/main/java/com/example/agent/runtime/io/StepOutput.java:21`
- `StepRuntimeService` 仅从 `rawOutput.rawRef` 读取引用，不回写原始结果体。
- 位置：`src/main/java/com/example/agent/runtime/StepRuntimeService.java:368`

### 4. 摘要构建器提供的是“摘要+样本”，不是完整原始结果
- `StepOutputSummaryBuilder` 产出 `outputSummary/toolResultSummary/stepSummary/outputDigest` 等摘要层。
- 位置：`src/main/java/com/example/agent/runtime/StepOutputSummaryBuilder.java:163`

## 三、核心问题
- 问题1：上下文链路缺少原始结果，后续步骤只能依赖摘要。
- 问题2：任务结果 `steps` 无原始结果，外部排障与复盘能力不足。
- 问题3：若直接塞完整原始结果，容易导致上下文膨胀与提示词超限。

## 四、建议方案（推荐）

### 方案目标
- 同时保留“摘要层”和“原始层”。
- 原始层优先使用 `rawRef`，再附带受控裁剪后的 `rawData`。

### 方案结构
- 上下文新增字段：
- `lastStepRawRef`: 原始结果引用键。
- `lastStepRawOutput`: 裁剪后的原始结果对象。
- `lastStepRawTruncated`: 是否裁剪。

- 输出结果 `steps[*]` 新增字段：
- `summary`: 保持现有摘要结构。
- `raw`: 新增原始结构对象。

示例：
```json
{
  "stepId": "s-1",
  "type": "TOOL",
  "attempt": 1,
  "summary": {
    "stepSummary": {"summary": "工具执行成功"},
    "outputDigest": {"keyCount": 8, "truncated": false}
  },
  "raw": {
    "rawRef": "raw:tool_xxx",
    "data": {"result": {"...": "..."}},
    "truncated": true
  }
}
```

## 五、实现策略（避免上下文失控）
- 策略1：引用优先。
- 原始结果一律先写 `rawRef`，`data` 仅放受控裁剪内容。

- 策略2：统一裁剪器。
- 新增一个专用构建器统一做原始结果裁剪，避免在多个服务重复写截断逻辑。
- 推荐新增：`com.example.agent.runtime.RawOutputEnvelopeBuilder`。

- 策略3：上下文与输出分层。
- 上下文只放“最近一步”的原始层。
- 任务输出 `steps` 放每一步的原始层（受控裁剪后）。

## 六、涉及改动文件清单

### P0（必须）
- `src/main/java/com/example/agent/runtime/AgentRuntime.java`
- 改造 `updateRuntimeContext(...)`：写入 `lastStepRawRef/lastStepRawOutput/lastStepRawTruncated`。
- 改造 `recordStepOutput(...)`：`steps[*]` 同时输出 `summary` 与 `raw`。
- 改造 `buildStepOutputSummary(...)` 调用关系，避免把 `summary` 和 `raw` 混在同一层。

- `src/main/java/com/example/agent/runtime/StepSummaryProperties.java`
- 增加原始输出裁剪配置，例如：
- `rawEnable`
- `rawMaxChars`
- `rawMaxFieldChars`
- `rawMaxListItems`

- `src/main/java/com/example/agent/runtime/RawOutputEnvelopeBuilder.java`（新增）
- 负责构建 `raw` 结构：`rawRef + data + truncated`。
- 统一供 `AgentRuntime` 与 `StepRuntimeService` 复用。

### P1（建议）
- `src/main/java/com/example/agent/runtime/io/StepOutput.java`
- 增加 `raw` 字段，便于 `/timeline/steps` 直接返回原始层。

- `src/main/java/com/example/agent/runtime/StepRuntimeService.java`
- `buildStepOutput(...)` 中写入 `raw` 字段。
- `resolveRawRef(...)` 兼容多路径读取：`rawRef`、`rawResult.rawRef`、`result.rawRef`。

- `src/main/java/com/example/agent/runtime/RuntimeResult.java`
- 可选增强为强类型结构，减少 `Map<String,Object>` 无约束带来的扩散。

- `src/main/java/com/example/agent/orchestrator/TaskOrchestrator.java`
- `buildResultPayload(...)` 同步写入新结构（保持对外结果字段一致）。

### P2（可选增强）
- `src/main/java/com/example/agent/runtime/FinalOutputService.java`
- 可按配置选择是否在最终总结阶段读取 `steps[*].raw.data`（默认关闭，避免 token 激增）。

- `src/main/java/com/example/agent/reasoning/ChainOfThoughtService.java`
- 可增加对 `lastStepRawOutput` 的受控读取（默认只读摘要）。

## 八、落地顺序
1. 先落 `RawOutputEnvelopeBuilder + StepSummaryProperties`。
2. 再改 `AgentRuntime`（上下文与任务输出双链路）。
3. 再改 `StepOutput/StepRuntimeService`（时间线与落库输出一致）。
4. 最后补 `FinalOutputService` 与推理服务的可选读取能力。

## 九、结论
- 当前确实是“摘要优先，原始缺失”的状态。
- 建议采用“摘要层 + 原始层（引用优先 + 受控裁剪）”的双层设计。
- 这样既能满足你要的“上下文和输出都带原始结果”，又能避免提示词与上下文体积失控。

## 2. 总体结论与等级

### 总等级：**C+（可用，但存在高优先级整改项）**

分项评分（5 分制）：

| 维度 | 得分 | 结论 |
|---|---:|---|
| 包边界与分层 | 3.8 | 子包按策略拆分清晰（`cot/debate/thoughttree`） |
| 职责内聚 | 2.6 | `Service` 类偏胖，职责混合明显 |
| 正确性与鲁棒性 | 2.4 | 思维树路径计算存在算法风险，辩论提示词文本可读性异常 |
| 可观测性 | 3.0 | COT 较好，Debate 与 ThoughtTree 一致性一般 |
| 可维护性 | 2.5 | 重复逻辑与文本编码问题影响后续维护 |

> 说明：部分结论为**基于源码静态推断**，已在条目中标注。

## 3. 设计合理性分析

### 3.1 合理点

1. **按推理策略拆包**：`cot`、`debate`、`thoughttree` 对应不同推理范式，语义直观。
2. **运行时接入方式统一**：通过 `runtime/step/executor` 适配，调用链可追踪。
3. **COT 模块工程化较完整**：具备 JSON 解析、修复、事件发布与最终答案清洗能力。
4. **结果对象边界清楚**：`*Result`/`*Round` 作为输出载体，调用方接入简单。

### 3.2 不足点

1. **缺少统一的策略抽象层**：三个策略没有共同接口（如 `ReasoningStrategy`），导致调用契约散落在各 `StepExecutor`。
2. **跨模块通用逻辑重复**：`cot` 与 `debate` 都有 prompt trace、JSON repair、事件发布拼装，但未下沉复用。
3. **复杂度集中在单类**：`ChainOfThoughtService` 达 1105 行，维护成本较高。
4. **文本质量不一致**：`DebateCoordinator` 和 `ThoughtNode` 存在明显乱码文本，影响可维护性与提示词质量。

## 4. 主要坏味道清单（含等级）

| ID | 等级 | 位置 | 现象 | 影响 | 建议 |
|---|---|---|---|---|---|
| S1 | 严重 | `src/main/java/com/example/agent/reasoning/debate/DebateCoordinator.java:149` | `buildPrompt` 中中文指令大面积乱码 | 模型提示词语义受损，辩论结论稳定性下降 | 统一按 UTF-8 重写模板文本，并补充回归测试 |
| S2 | 严重（静态推断） | `src/main/java/com/example/agent/reasoning/thoughttree/ThoughtTreeService.java:244`、`:256`、`:269` | `findBestPath` 使用栈+`path.pop`，无法保持完整根到叶路径 | 可能选出非真实路径，导致 `bestPath`/`bestSolution` 偏差 | 改为递归 DFS 或显式“节点+路径”栈结构，并新增路径正确性测试 |
| M1 | 中等 | `src/main/java/com/example/agent/reasoning/cot/ChainOfThoughtService.java:43` | 单类过大（1105 行），集成调用、解析、修复、清洗、事件等多职责 | 变更耦合高，回归范围大 | 拆分 `PromptBuilder`、`DecisionParser`、`AnswerSanitizer`、`ReasoningEventPublisher` |
| M2 | 中等 | `src/main/java/com/example/agent/reasoning/cot/ChainOfThoughtService.java:363`、`:435` | 构建上下文 JSON 的逻辑在 `buildPrompt` 与 `tryRepairDecision` 重复 | 规则变更易漏改 | 提取 `buildCotContext(...)` 复用 |
| M3 | 中等 | `src/main/java/com/example/agent/reasoning/debate/DebateCoordinator.java:130` | 存在 `debate(String topic)` 旧入口，仅返回 `pending` | 语义不一致，易被误调用 | 标记废弃或删除，并统一仅保留带上下文签名 |
| M4 | 中等（静态推断） | `src/main/java/com/example/agent/reasoning/thoughttree/ThoughtTreeService.java:80` | `explored += branches.size()` 在剪枝前计数且可超预算 | `explorationBudget` 与 `totalThoughts` 统计偏差 | 仅对实际保留节点计数，并在生成前按剩余额度截断 |
| M5 | 中等 | `src/main/java/com/example/agent/reasoning/debate/DebateCoordinator.java:225`、`:236`、`:238` | `parseConclusion` 解析失败时直接返回原文 | 原始噪声/长文本外泄到下游 | 增加 `sanitize` 和长度限制，统一输出结构 |
| L1 | 低 | `src/main/java/com/example/agent/reasoning/thoughttree/ThoughtNode.java:6` | 注释文本乱码 | 文档可读性差，违背注释规范 | 修复注释编码并重写中文注释 |
| L2 | 低 | `src/main/java/com/example/agent/reasoning/cot/ChainOfThoughtService.java:1008`、`src/main/java/com/example/agent/reasoning/debate/DebateCoordinator.java:241` | 事件对象拼装逻辑重复 | 维护成本增加 | 提取通用事件发布组件 |

## 5. 子包分级

| 子包 | 等级 | 结论 |
|---|---|---|
| `reasoning.cot` | **B** | 功能完整、观测相对充分，但复杂度偏高 |
| `reasoning.debate` | **C-** | 结构简单但文本乱码与输出治理不足，存在语义风险 |
| `reasoning.thoughttree` | **C** | 可运行，但路径算法与预算统计有正确性隐患 |

---

## 6. 优先级整改建议

### P0（立即）

1. 修复 `DebateCoordinator` 提示词与日志乱码（先保功能正确性）。
2. 修复 `ThoughtTreeService.findBestPath` 路径计算逻辑，并补测试覆盖。

### P1（短期）

1. 为 Debate 增加 `conclusion` 清洗与截断策略，避免原始噪声外泄。
2. 移除或弃用 `debate(String topic)` 旧入口，统一契约。
3. 提取 COT 上下文构建复用函数，降低重复。

### P2（中期）

1. 在 `reasoning` 层引入统一策略接口与公共基类（或组合组件）。
2. 下沉事件发布与 trace 记录的共性逻辑，减少跨策略重复代码。

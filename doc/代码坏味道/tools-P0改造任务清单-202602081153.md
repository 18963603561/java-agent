# `tools` 包 P0 改造任务清单

## 1. 目标

基于 `doc/tools包设计合理性与坏味道分析-202602081143.md` 的 P0 结论，形成可以直接进入迭代排期的任务清单。

P0 总目标：

1. 降低 `mcp` 与 `execution` 大类复杂度。
2. 消除 `ToolRegistry` 并发一致性风险。
3. 清理并明确沙箱与预热路径的真实语义。

---

## 2. 实施原则

1. **先保行为一致，再做结构调整**：先补测试与契约，再分拆实现。
2. **小步提交**：每个任务都应独立可回滚。
3. **全链路可观测**：关键步骤必须补齐 `info/warn/error` 日志与指标。
4. **优先风险收敛**：先做并发与路径语义，再做深层重构。

---

## 3. P0 任务拆解总览

| 任务编号 | 任务主题 | 优先级 | 预计工作量 | 前置依赖 |
|---|---|---|---|---|
| P0-1 | `McpToolClient` 拆分设计与适配层落地 | 高 | 2.5~3.5 人日 | 无 |
| P0-2 | `ToolRegistry` 并发模型统一 | 高 | 1.0~1.5 人日 | 无 |
| P0-3 | 沙箱执行路径恢复或收敛 | 高 | 0.5~1.0 人日 | P0-1（建议） |
| P0-4 | 启动预热路径恢复与保护 | 高 | 0.5~1.0 人日 | P0-1（建议） |
| P0-5 | 注释残留清理与文档同步 | 高 | 0.5 人日 | P0-3、P0-4 |

---

## 4. 具体任务清单

## 4.1 P0-1 `McpToolClient` 拆分设计与适配层落地

### 4.1.1 目标

将 `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolClient.java` 从“超大编排类”拆为多组件协作，保留对外接口不变。

### 4.1.2 子任务

1. 新建调用策略解析组件。
   - 建议新增：`mcp/strategy/McpCallStrategyResolver.java`
   - 迁移内容：`resolveCallStrategy`、`isFallbackTrigger`、`isRetryable` 等策略判断。
2. 新建远程传输网关组件。
   - 建议新增：`mcp/transport/McpHttpTransport.java`
   - 迁移内容：`post`、`postWithJdkHttpClient`、`readResponseBytes`、`readResponseAsMap`。
3. 新建协议适配组件。
   - 建议新增：
     - `mcp/protocol/McpJsonRpcAdapter.java`
     - `mcp/protocol/McpRestAdapter.java`
   - 迁移内容：`listToolsRemote`、`callToolRemote` 的协议分支。
4. 新建 SSE 会话管理组件。
   - 建议新增：`mcp/session/McpSseSessionManager.java`
   - 迁移内容：`ensureSseSession`、`runSseLoop`、`extractSessionId`、刷新逻辑。
5. 在 `McpToolClient` 保留“编排入口”职责。
   - 保留：`listTools`、`callTool`。
   - 删除：可下沉的细节方法，改为组合调用。

### 4.1.3 验收标准

1. 对外行为保持一致：`McpToolClient` 公开方法签名不变。
2. `McpToolClient.java` 行数控制到 500 行以内（目标值，允许小幅浮动）。
3. `McpToolClientTest` 全量通过，并新增至少 2 个拆分后回归用例。
4. 关键日志节点完整：开始、成功、降级、失败。

### 4.1.4 风险与回滚

1. 风险：拆分过程可能造成 fallback 行为变化。
2. 回滚：保留旧实现分支一段过渡期，通过配置开关切回。

---

## 4.2 P0-2 `ToolRegistry` 并发模型统一

### 4.2.1 目标

消除 `ToolRegistry` 当前“写有锁、读无策略”的并发不一致风险。

### 4.2.2 子任务

1. 将核心存储结构切换为线程安全实现。
   - `handlers`、`definitions`、`definitionSources` 优先改为 `ConcurrentHashMap`。
2. 统一读写可见性策略。
   - 对 `listDefinitions` 返回快照。
   - 对批量注册与清理使用原子流程。
3. 补充并发测试。
   - 新增并发读写场景测试：注册、读取、按来源清理交叉执行。

### 4.2.3 涉及文件

1. `src/main/java/com/example/agent/capabilities/tools/registry/ToolRegistry.java`
2. `src/test/java/com/example/agent/tools/...`（新增并发测试文件）

### 4.2.4 验收标准

1. 并发压测型单测可稳定通过（重复执行无偶发失败）。
2. `registerDefinitions` 与 `removeDefinitionsBySourceExcept` 在并发下无数据错乱。
3. 不引入额外死锁。

---

## 4.3 P0-3 沙箱执行路径恢复或收敛

### 4.3.1 目标

明确 `ToolExecutor` 中沙箱执行链路语义，避免“字段存在但流程未生效”。

### 4.3.2 子任务

1. 决策：恢复沙箱执行，或正式移除沙箱调用点。
2. 若恢复执行：
   - 在 `executeInternal` 中恢复 `sandboxExecutor.execute`。
   - 定义沙箱输出合并规则（字段命名、冲突策略）。
3. 若暂不执行：
   - 删除未使用字段与注释残留。
   - 在类注释中明确当前策略与后续计划。
4. 补充单测覆盖。
   - 至少覆盖“沙箱允许”和“沙箱拒绝”两条路径。

### 4.3.3 涉及文件

1. `src/main/java/com/example/agent/capabilities/tools/execution/ToolExecutor.java`
2. `src/main/java/com/example/agent/capabilities/tools/sandbox/*.java`
3. `src/test/java/com/example/agent/agentcore/ToolExecutorTest.java`

### 4.3.4 验收标准

1. 代码中不再存在与沙箱主流程相关的长段注释逻辑。
2. 行为与文档一致，且日志能标识沙箱是否生效。

---

## 4.4 P0-4 启动预热路径恢复与保护

### 4.4.1 目标

让 `McpToolStartupWarmup` 的预热逻辑成为“可控且真实执行”的能力。

### 4.4.2 子任务

1. 恢复 `toolSyncService.refreshAll(true, "startup")` 调用。
2. 增加预热开关。
   - 建议配置：`agent.mcp.tool-refresh.startup-enabled`。
3. 增加超时与异常保护日志。
4. 补充启动预热测试。

### 4.4.3 涉及文件

1. `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolStartupWarmup.java`
2. `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolSyncService.java`
3. `src/test/java/com/example/agent/tools/...`（新增 warmup 测试）

### 4.4.4 验收标准

1. 开关开启时可观测到预热开始与结束日志。
2. 预热失败不阻断主流程。
3. 开关关闭时不触发远程调用。

---

## 4.5 P0-5 注释残留清理与文档同步

### 4.5.1 目标

清理影响理解的注释残留，确保代码状态与文档状态一致。

### 4.5.2 子任务

1. 清理 `ToolExecutor` 与 `McpToolStartupWarmup` 中无效注释代码。
2. 为关键类补充最新中文注释，写清楚输入、输出、边界与注意事项。
3. 更新设计文档与变更记录。

### 4.5.3 验收标准

1. 不存在“被注释掉的主流程代码”。
2. 关键类注释与真实行为一致。

---

## 5. 建议实施顺序

1. 先做 `P0-2`（并发风险最高，改动局部）。
2. 再做 `P0-1`（结构性拆分，工作量最大）。
3. 然后做 `P0-3` 与 `P0-4`（路径语义收敛）。
4. 最后做 `P0-5`（清理与文档收口）。

## 7. 完成定义

满足以下条件判定 P0 完成：

1. 上述 P0-1 至 P0-5 全部通过验收。
2. `tools` 包关键类复杂度下降，并发风险关闭。
3. 沙箱与预热路径不再存在“注释态主流程”。
4. 回归测试通过且无新增高优先级缺陷。

# `tools` 包 P1 改造任务清单

## 1. 目标

基于 `doc/tools包设计合理性与坏味道分析-202602081143.md` 的 P1 项，形成可直接排期执行的改造任务清单。

P1 总目标：

1. 收敛目录接口语义，消除重复接口带来的维护成本。
2. 让 `ToolQuery.allowedScopes` 与 `ToolQuery.locale` 从“声明字段”变成“真实生效”。
3. 统一工具域入口参数前置校验，消除隐式空值约束。

---

## 2. 设计取舍（新项目策略）

1. 不保留历史兼容分支，不做双轨接口。
2. 对重复能力直接收敛为单一实现。
3. 字段要么删除，要么落地；本轮选择“落地实现”。

---

## 3. P1 任务总览

| 任务编号 | 任务主题 | 优先级 | 预计工作量 | 前置依赖 |
|---|---|---|---|---|
| P1-1 | `ToolCatalog`/`ToolCatalogService` 接口收敛 | 高 | 0.5~1.0 人日 | 无 |
| P1-2 | `ToolQuery` 未生效字段落地 | 高 | 1.0~1.5 人日 | P1-1 |
| P1-3 | 工具域入口参数校验统一 | 高 | 1.0~1.5 人日 | 无 |
| P1-4 | 测试补齐与文档收口 | 中 | 0.5~1.0 人日 | P1-1~P1-3 |

---

## 4. 具体任务清单

## 4.1 P1-1 接口收敛：保留单一目录服务接口

### 4.1.1 目标

消除 `ToolCatalog` 与 `ToolCatalogService` 重复职责，统一为单一入口接口，避免调用方困惑。

### 4.1.2 实施方案

1. 选择 `ToolCatalogService` 作为唯一服务接口（命名更偏应用服务语义）。
2. 将 `ToolCatalog` 能力并入 `ToolCatalogService`，统一方法命名。
3. 删除重复方法与重复接口引用。
4. `DefaultToolCatalog` 只实现一个接口。

### 4.1.3 涉及文件

1. `src/main/java/com/example/agent/capabilities/tools/ToolCatalog.java`
2. `src/main/java/com/example/agent/capabilities/tools/ToolCatalogService.java`
3. `src/main/java/com/example/agent/capabilities/tools/DefaultToolCatalog.java`
4. 所有注入与调用 `ToolCatalog`/`ToolCatalogService` 的类

### 4.1.4 验收标准

1. 代码中不存在同一语义的双接口并行注入。
2. `DefaultToolCatalog` 单接口实现，公开方法无重复别名。
3. 编译与现有测试全部通过。

---

## 4.2 P1-2 字段落地：`allowedScopes` 与 `locale` 真正参与筛选

### 4.2.1 目标

让 `ToolQuery` 中当前闲置字段转为可观测、可测试的真实筛选条件。

### 4.2.2 实施方案

1. 扩展工具定义模型，增加可筛选元数据。
   - 建议新增字段：
     - `authScope`（字符串）
     - `supportedLocales`（字符串列表）
2. 扩展摘要模型映射。
   - `ToolSummary.authScope` 从定义映射而来。
   - 增加 `localeMatched` 或沿用现有字段并在文档说明规则。
3. 在目录查询逻辑中实现组合筛选。
   - 标签筛选：保持现有逻辑。
   - 范围筛选：`allowedScopes` 与 `authScope` 匹配。
   - 语言筛选：`locale` 命中 `supportedLocales`。
4. 明确默认行为。
   - `allowedScopes` 为空：不按范围过滤。
   - `locale` 为空：不按语言过滤。
   - 定义缺失字段：按“保守过滤”或“宽松放行”固定为一种策略并文档化。

### 4.2.3 涉及文件

1. `src/main/java/com/example/agent/capabilities/tools/ToolQuery.java`
2. `src/main/java/com/example/agent/capabilities/tools/ToolSummary.java`
3. `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolDefinition.java`
4. `src/main/java/com/example/agent/capabilities/tools/DefaultToolCatalog.java`
5. `src/main/java/com/example/agent/capabilities/tools/plugin/PluginLoader.java`（定义反序列化联动）

### 4.2.4 验收标准

1. `allowedScopes` 与 `locale` 有明确筛选效果。
2. 为上述规则补齐单元测试，覆盖命中与不命中场景。
3. 接口返回字段与查询语义一致，不再出现“配置了但不生效”。

---

## 4.3 P1-3 参数前置校验统一

### 4.3.1 目标

将工具域入口的空值与非法值校验统一收敛，避免散落式判空与潜在空指针。

### 4.3.2 实施方案

1. 新增统一校验组件。
   - 建议新增：`tools/validation/ToolRequestValidator`。
2. 在关键入口统一接入前置校验。
   - `McpToolClient.listTools`
   - `McpToolClient.callTool`
   - `ToolExecutor.execute/executeWithArguments`
   - `EnforcementGateway.execute/executeWithArguments`
3. 统一错误语义。
   - 统一返回 `INVALID_REQUEST`（`HttpStatus.BAD_REQUEST`）。
   - 错误消息包含最小上下文：缺失参数名。
4. 删除重复判空代码。

### 4.3.3 涉及文件

1. `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolClient.java`
2. `src/main/java/com/example/agent/capabilities/tools/execution/ToolExecutor.java`
3. `src/main/java/com/example/agent/capabilities/tools/enforcement/EnforcementGateway.java`
4. `src/main/java/com/example/agent/capabilities/tools/validation/*`

### 4.3.4 验收标准

1. 关键入口不存在“默认上游一定非空”的隐式假设。
2. 非法入参错误码、状态码、错误消息风格统一。
3. 新增参数校验测试覆盖空请求、空租户、空工具名等典型场景。

---

## 4.4 P1-4 测试与文档收口

### 4.4.1 目标

确保 P1 改造可回归、可维护、可持续迭代。

### 4.4.2 子任务

1. 补齐目录筛选测试。
   - `DefaultToolCatalogTest` 增加 `allowedScopes/locale` 用例。
2. 补齐参数校验测试。
   - `McpToolClientTest`、`ToolExecutorTest` 增加空值入参断言。
3. 补齐接口收敛后的装配测试。
   - 验证容器中无重复 Bean 语义冲突。
4. 更新改造记录文档与验收文档。

### 4.4.3 验收标准

1. `mvn -q -DskipTests compile` 通过。
2. `mvn -q test` 全量通过。
3. 文档中明确 P1 选择策略与最终行为。

---

## 5. 建议实施顺序

1. 先做 `P1-1`（接口收敛，减少后续改动面）。
2. 再做 `P1-2`（字段落地，保证语义一致）。
3. 然后做 `P1-3`（参数校验统一，收敛边界风险）。
4. 最后做 `P1-4`（测试补齐与文档收口）。

---

## 6. 完成定义

满足以下条件判定 P1 完成：

1. 目录能力对外仅保留单一服务接口。
2. `ToolQuery.allowedScopes` 与 `ToolQuery.locale` 在查询链路真实生效。
3. 工具域关键入口前置校验统一，非法请求失败行为一致。
4. 全量测试通过，且文档与代码行为一致。

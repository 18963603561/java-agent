## 2. 落地概览

### 2.1 架构拆分结果

已完成 `planning` 规划链路分层，依赖方向为 `PlannerService -> engine/builder/parser/telemetry/context`。

新增组件：

- `planning/engine/LlmPlanEngine`：模型调用、解析、修复、trace 记录。
- `planning/builder/HeuristicPlanBuilder`：规则规划与策略分支。
- `planning/parser/PlanParser`：模型输出解析、步骤构建、参数校验。
- `planning/telemetry/PlanTelemetry`：规划遥测、提示词 trace、上下文阶段事件。
- `planning/context/PlanningContext`：强类型上下文访问与提示词摘要收口。
- `planning/context/PlanningContextMapper`：`TaskRequest.context` 到 `PlanningContext` 的统一映射。
- `planning/PlanningFieldKeys`：规划结构字段统一常量源。

### 2.2 编排层收敛结果

- `PlannerService` 已收敛为编排职责：
  - 能力评估。
  - LLM 规划调用。
  - 规则回退。
  - 审批注入。
- 已补齐核心路径日志（开始、LLM 成功、回退成功、回退禁用失败）。

## 4. 关键改造点

### 4.1 上下文强类型能力增强

`PlanningContext` 新增并统一了如下能力：

- 工具选择解析统一走 `ModelToolChoice.fromRaw`。
- 记忆数量读取：`getMemoryCount()`。
- 证据数量读取：`getEvidenceCount()`。
- 证据包读取：`getEvidencePack()`。
- 提示词摘要收口：`toPromptSummary()`。

### 4.2 契约字段收口

`PlanningFieldKeys` 新增统一字段：

- `QUESTION`、`PROMPT`、`CRITICAL`
- `ID`、`NAME`、`FROM`、`TO`
- `CONTEXT_SUMMARY`、`PROMPT_ASSEMBLY_INPUT`
- `TOKEN_BUDGET`、`MEMORY_ITEMS`、`EVIDENCE_COUNT`
- `TOTAL`、`SCENE_PLANNER`

`PlanningContextKeys` 新增：

- `EVIDENCE_PACK`

### 4.3 遗留清理

- 删除 `src/main/java/com/example/agent/planning/Plan.java`
- 删除 `src/main/java/com/example/agent/planning/PlanRequest.java`
- 全仓检索确认无引用残留。

# planning 包 P0 改造任务清单

## 1. 依据与目标
- 依据文档：`doc/planning包设计合理性评审-202602081543.md`
- 对齐范围：仅覆盖评审文档中的三项 P0
  1. 修复 `PlannerService` 中文文本编码
  2. 异常日志统一输出堆栈
  3. 抽离 `buildPlanPrompt(...)` 为独立组件
- 目标：在不改变现有业务语义的前提下，先解决可读性、可观测性、可维护性最低保障问题。

## 2. 执行顺序（建议）
1. 先做编码修复（避免后续改造在乱码文本上继续扩散）
2. 再做日志改造（确保改造期问题可定位）
3. 最后抽离提示词组件（最容易引入行为变化，放在可观测增强后）

## 4. 任务拆解说明

### 4.1 编码修复最小范围
- 优先修复以下文本类型：
  1. 日志消息文本
  2. `buildPlanPrompt(...)` 模板正文
  3. JavaDoc 与关键行内注释
- 不在 P0 处理内容：策略模型重构、上下文强类型化、类职责大拆分。

### 4.2 日志规范（P0 统一口径）
- 失败日志统一包含：`tenantId`、`workflowId`、`planId`、`scene`、`reason`。
- `warn/error` 必须传入异常对象：
  - 示例：`log.warn("规划解析失败, tenantId={}, planId={}", tenantId, planId, ex);`
- 外部调用节点必须有：开始日志、结束摘要日志、失败日志。

### 4.3 提示词抽离设计约束
- `PlannerService` 只负责组织入参与调用，不再维护超长模板内容。
- 模板内容放在资源文件，组件仅负责：加载、占位替换、默认值回退。
- 保持现有 `PromptAssembler` 与 `ModelInvocationService` 链路不变，避免横向扩散。

## 5. 验收清单

### 5.1 必须通过
1. `mvn -q -Dtest=PlannerServiceTest test`
2. `mvn -q -Dtest=PlanningSourceEncodingGuardTest test`
3. `mvn -q -Dtest=PlanningPromptBuilderTest test`

### 5.2 人工检查
1. `PlannerService` 日志中文可读，无乱码符号。
2. 关键异常日志可直接看到堆栈。
3. `PlannerService` 不再包含大段多行提示词常量。

## 6. 风险与回滚
- 风险点 1：提示词抽离后模型输出分布可能变化。
  - 对策：保留回退模板与灰度开关（配置控制是否使用新模板组件）。
- 风险点 2：日志量增加可能影响存储。
  - 对策：开始/结束用 `info`，细节用 `debug`，异常用 `warn/error`。
- 回滚策略：
  1. 保留旧 `buildPlanPrompt(...)` 兼容实现一个版本周期
  2. 新组件通过配置 `agent.planner.prompt-builder-enabled` 控制启停

# reasoning 包 P1 改造任务清单

## 1. 目标与范围

基于 `doc/reasoning包设计与坏味道评估-202602092219.md` 与 `doc/reasoning包P0改造任务清单-202602092228.md`，P1 目标从“先止血”升级为“可复用、可维护、可扩展”。

本轮 P1 原则：

1. 不为历史兼容保留复杂分支，按新方案直接收敛。
2. 以通用能力下沉和职责拆分为主，避免继续堆积大类。
3. 保持外部行为稳定，优先通过接口抽象实现内部替换。

P1 聚焦范围：

- `src/main/java/com/example/agent/reasoning/cot`
- `src/main/java/com/example/agent/reasoning/debate`
- `src/main/java/com/example/agent/reasoning/thoughttree`
- `src/main/java/com/example/agent/runtime/step/executor`
- `src/test/java/com/example/agent/reasoning`

## 3. 具体改造任务

### P1-RSN-01 COT 上下文构建器抽取

**目标**

- 消除 `ChainOfThoughtService` 中上下文组装重复逻辑，提高复用性与一致性。

**改造范围**

- `src/main/java/com/example/agent/reasoning/cot/ChainOfThoughtService.java`
- 新增：`src/main/java/com/example/agent/reasoning/cot/CotContextBuilder.java`

**具体工作项**

1. 将 `buildPrompt(...)` 与 `tryRepairDecision(...)` 中重复的上下文组装逻辑抽为单一构建器。
2. 构建器对输入字段做统一裁剪策略（`question`、`memorySummary`、`recentObservation`、`previousSteps`）。
3. 构建器同时提供：
   - 结构化对象输出（供内部逻辑复用）；
   - JSON 字符串输出（供提示词与修复服务使用）。
4. 删除 `ChainOfThoughtService` 中重复字段提取代码段，确保唯一事实来源。

**交付物**

- `CotContextBuilder` 新增并在 COT 主流程接入。
- COT 上下文组装逻辑在代码中只保留一份实现。

**验收标准**

- `ChainOfThoughtService` 中不再存在两套上下文拼装代码。
- 相关单测通过，且提示词上下文结构不回退。

---

### P1-RSN-02 COT 决策解析与答案清洗组件化

**目标**

- 缩减 `ChainOfThoughtService` 职责体积，提升解析与清洗逻辑复用能力。

**改造范围**

- `src/main/java/com/example/agent/reasoning/cot/ChainOfThoughtService.java`
- 新增：
  - `src/main/java/com/example/agent/reasoning/cot/CotDecisionParser.java`
  - `src/main/java/com/example/agent/reasoning/cot/CotAnswerSanitizer.java`

**具体工作项**

1. 将 `parseDecision`、`resolveBoolean`、`resolveString`、`resolveDouble` 等解析逻辑下沉到 `CotDecisionParser`。
2. 将 `sanitizeFinalAnswer` 及其相关标记剥离逻辑下沉到 `CotAnswerSanitizer`。
3. `ChainOfThoughtService` 仅负责编排：请求、循环、事件、结果装配。
4. 补充解析器与清洗器独立单测，覆盖异常 JSON、代码块包裹、推理文本污染场景。

**交付物**

- COT 主服务方法复杂度降低。
- 解析逻辑与清洗逻辑可在其他推理策略复用。

**验收标准**

- `ChainOfThoughtService` 行数显著下降（目标降幅不少于 25%）。
- 现有 COT 测试全部通过，新组件测试新增并通过。

---

### P1-RSN-03 推理层通用 JSON 解析/修复工具下沉

**目标**

- 去除 `cot` 与 `debate` 中重复的 JSON 清洗与解析模式，实现通用组件复用。

**改造范围**

- 新增：`src/main/java/com/example/agent/reasoning/common/JsonPayloadNormalizer.java`
- 新增：`src/main/java/com/example/agent/reasoning/common/ReasoningParseSupport.java`
- 适配：`ChainOfThoughtService`、`DebateCoordinator`

**具体工作项**

1. 抽取“代码块去包裹 + JSON 片段截取”的标准能力。
2. 抽取“字段解析安全访问”能力，统一字符串、布尔、数值解析规则。
3. 统一解析失败错误分类（如 `empty_output`、`json_parse_error`）并复用。
4. 删除原类中的重复私有工具方法，保留最小适配代码。

**交付物**

- 推理通用解析支撑组件。
- `cot/debate` 代码重复率下降。

**验收标准**

- `cot` 与 `debate` 不再各自维护重复 JSON 清洗函数。
- 解析失败日志与指标字段命名保持一致。

---

### P1-RSN-04 推理策略统一执行契约落地

**目标**

- 为 `cot/debate/thoughttree` 建立统一策略抽象，提升扩展性与替换成本。

**改造范围**

- 新增：
  - `src/main/java/com/example/agent/reasoning/common/ReasoningStrategy.java`
  - `src/main/java/com/example/agent/reasoning/common/ReasoningRequest.java`
  - `src/main/java/com/example/agent/reasoning/common/ReasoningResult.java`
  - `src/main/java/com/example/agent/reasoning/common/ReasoningStrategyRegistry.java`
- 适配：`ChainOfThoughtService`、`DebateCoordinator`、`ThoughtTreeService`

**具体工作项**

1. 定义统一执行入口（如 `execute(ReasoningRequest)`）。
2. 抽象统一输入要素：主题/问题、上下文、租户、链路标识、序列计数器。
3. 抽象统一输出要素：状态、摘要、置信度、停止原因、原始引用。
4. 在策略注册表中按类型路由，替代分散的直接调用。

**交付物**

- reasoning 层完成“策略接口 + 注册路由”基础架构。
- 新增推理策略时无需修改执行器业务代码。

**验收标准**

- 三种推理策略均可通过统一契约调用。
- 不引入额外历史兼容分支。

---

### P1-RSN-05 执行器层参数映射与配置治理收敛

**目标**

- 清理 `StepExecutor` 层重复参数提取逻辑，统一输入映射与配置入口。

**改造范围**

- `src/main/java/com/example/agent/runtime/step/executor/ChainOfThoughtStepExecutor.java`
- `src/main/java/com/example/agent/runtime/step/executor/DebateStepExecutor.java`
- `src/main/java/com/example/agent/runtime/step/executor/ThoughtTreeStepExecutor.java`
- 新增：`src/main/java/com/example/agent/runtime/step/executor/ReasoningInputResolver.java`

**具体工作项**

1. 抽取通用输入解析器，统一 `question/topic/query/prompt` 归一化规则。
2. 执行器层统一处理空输入兜底策略，避免各自实现差异。
3. 收敛配置读取入口，避免策略参数散落在执行器中硬编码。
4. 保持执行器职责单一：编排调用与输出装配。

**交付物**

- 输入解析逻辑统一组件。
- 执行器代码重复块明显减少。

**验收标准**

- 三个执行器不再重复实现近似 `resolve*` 方法。
- 推理步骤入参行为在集成测试中一致。

### P1-RSN-06 P1 全链路回归与基线固化

**目标**

- 确保 P1 重构后行为稳定，建立后续 P2 改造对照基线。

**执行清单**

1. 定向测试：

```bash
mvn "-Dtest=ChainOfThoughtServiceTest,DebateCoordinatorTest,ThoughtTreeServiceTest" test
```

2. 推理执行器耦合测试：

```bash
mvn "-Dtest=AgentRuntimeApprovalIntegrationTest" test
```

3. 全量测试：

```bash
mvn test
```

4. 输出重构基线记录：
   - 类体积变化；
   - 重复逻辑删除点；
   - 新增公共组件清单；
   - 风险与回滚策略。

**门禁标准**

- 单测与集成测试全通过。
- `reasoning` 包新增代码无乱码。
- `ChainOfThoughtService` 复杂度下降且行为不回退。
- `Debate` 与 `ThoughtTree` 关键契约保持稳定。

## 4. P1 完成定义（DoD）

1. COT 核心流程完成组件化拆分，主类职责回归编排层。
2. `cot/debate` 的 JSON 清洗解析通用能力完成下沉复用。
3. reasoning 层具备统一策略契约与注册能力。
4. 执行器输入解析统一，重复逻辑显著减少。
5. 全量测试通过，并形成可复用重构基线文档。

---

## 5. 不纳入 P1 的事项（避免范围膨胀）

1. 事件发布总线统一组件化（跨包范围更大），建议纳入 P2。
2. 指标体系统一重命名与历史指标迁移，建议纳入 P2。
3. 推理策略并行执行框架与性能优化，建议纳入 P2。

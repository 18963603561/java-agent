# budget 包设计合理性 P4 具体改造任务清单

## 1. 任务背景

- 输入依据：`doc/budget-包设计合理性与坏味道评估-202602091221.md`
- 对应问题等级：`P4（建议优化）`
- 本清单目标：将评估文档中的 P4 问题转为可排期、可实施、可验收的工程任务。
- 本轮策略：采用单方案收敛，不保留双轨分支，直接执行包粒度优化。

## 2. P4 问题范围

### 2.1 问题 9：`cost` 子包仅有单类，包粒度偏细

- 现状：`src/main/java/com/example/agent/budget/cost/CostCalculator.java`
- 当前影响：调用方仅 1 处，形成低价值目录层级跳转。
- 优化目标：减少冗余包层级，提升预算域代码可读性与聚合度。

### 2.2 持续演进建议：统一命名与边界约束

- 现状：P1~P3 已完成核心结构治理，P4 侧重“结构整洁性”和“演进防回退”。
- 优化目标：补齐命名规范和守卫规则，避免未来再次出现“单类孤岛包”。

## 3. 总体目标与完成定义

### 3.1 总体目标

- 将成本计算能力并入 `token` 子域下的 `pricing` 聚合点，形成统一预算计算视角。
- 清理低价值目录层级，降低开发者跨包导航成本。
- 通过契约测试与架构守卫固化 P4 优化成果，防止结构回退。

### 3.2 完成定义

- 架构完成定义：
  - `budget/cost` 包移除，成本计算类迁移到 `budget/token/pricing`。
  - `token` 侧调用链统一引用新位置，不保留旧路径兼容分支。
  - 包结构文档与命名规范更新完成。
- 质量完成定义：
  - 成本计算契约测试通过。
  - 预算链路回归测试通过。
  - 每阶段执行全量 `mvn test` 且通过。

## 5. 具体任务清单

### P4-T01 建立 P4 包粒度基线

- 改造目标：明确改造影响面与验收边界。
- 主要动作：
  - 统计 `budget/cost` 被引用位置与调用链路。
  - 记录迁移前目录树快照与测试基线。
  - 输出 P4 迁移影响清单（类、包、测试、文档）。
- 验收标准：
  - 基线信息可直接用于迁移前后对照。

### P4-T02 设计成本子域目标结构

- 改造目标：给出单一落地结构，避免后续反复搬迁。
- 主要动作：
  - 目标结构确定为：`src/main/java/com/example/agent/budget/token/pricing`。
  - 明确 `pricing` 子域职责边界：仅承担 token 成本换算与费率策略。
  - 明确命名规则：计算器类、费率策略类、模型类命名约定。
- 验收标准：
  - 形成明确目录结构与职责约束，评审可通过。

### P4-T03 迁移 `CostCalculator` 到 `token/pricing`

- 改造目标：消除单类孤岛包。
- 主要动作：
  - 将 `CostCalculator` 迁移至 `budget/token/pricing`。
  - 保持公开方法签名与计算语义不变。
  - 补齐类注释，明确输入、输出、边界条件。
- 验收标准：
  - 新类可被原调用方无歧义替换。

### P4-T04 清理旧包与引用并更新装配

- 改造目标：彻底完成新方案切换，不保留历史路径。
- 主要动作：
  - 更新 `DefaultTokenUsageRecordFactory` 等调用方 import。
  - 删除 `budget/cost` 目录及其遗留引用。
  - 检查 Spring 装配与构造注入路径无回退。
- 验收标准：
  - 代码库无 `com.example.agent.budget.cost` 引用残留。

### P4-T05 补齐成本计算契约与集成测试

- 改造目标：固化迁移后的行为一致性。
- 主要动作：
  - 新增或更新 `CostCalculator` 单测：
    - 零 token 输入。
    - 大 token 输入。
    - 边界费率精度场景。
  - 增加 `TokenUsageRecordFactory` 集成断言，确保迁移后成本字段一致。
- 验收标准：
  - 契约测试可覆盖核心边界场景并稳定通过。

### P4-T06 增加包结构守卫与命名守卫

- 改造目标：防止包粒度问题回流。
- 主要动作：
  - 在 `BudgetArchitectureGuardTest` 增加规则：
    - 禁止重新引入 `budget/cost` 包。
    - 新增单类包需在守卫白名单说明理由。
  - 补充 `pricing` 子域依赖边界守卫（禁止依赖 `trim` 运行时实现细节）。
- 验收标准：
  - 守卫测试可拦截结构回退。

### P4-T07 补充文档与可观测性说明

- 改造目标：保障迁移后的交接与排障效率。
- 主要动作：
  - 更新 budget 包结构图与职责说明。
  - 记录成本计算日志字段约定（输入 token、费率版本、输出金额）。
  - 记录后续扩展策略（多模型费率、多币种）预留点。
- 验收标准：
  - 文档可直接用于评审、交接与维护。

### P4-T08 全量回归与交付收口

- 改造目标：确保发布质量与可回归性。
- 主要动作：
  - 分阶段执行全量 `mvn test`。
  - 核对目录、守卫、契约测试、文档落盘全部完成。
  - 输出 P4 实施记录（变更点、验证结果、后续建议）。
- 验收标准：
  - 全量测试通过，交付物完整。

## 8. 风险与应对

- 风险 1：包迁移导致 import 漏改。
  - 应对：迁移后全量扫描 `budget.cost` 引用并通过编译回归校验。
- 风险 2：成本计算精度在迁移中出现偏差。
  - 应对：迁移前后保持同一测试向量，对关键费率场景做等值断言。
- 风险 3：P4 优化优先级低，容易被后续需求插队。
  - 应对：将 P4 拆为短任务并绑定守卫测试，降低长期漂移风险。

## 9. 预期收益

- 包结构更紧凑，开发者定位成本计算逻辑的路径更直观。
- 消除单类孤岛包，降低无效层级带来的认知负担。
- 通过守卫与契约测试固化成果，为后续费率扩展保留清晰演进路径。

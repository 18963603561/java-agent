# planning 包 P1 改造任务清单

## 1. 依据与目标
- 依据文档：`doc/planning包设计合理性评审-202602081543.md`
- 对齐范围：仅覆盖评审文档中的 P1 项
  1. 拆分类职责（`LlmPlanEngine`、`HeuristicPlanBuilder`、`PlanParser`、`PlanTelemetry`）
  2. 引入 `PlanningContext` 强类型对象，替代核心链路裸 `Map<String, Object>`
  3. 提取并收口上下文键常量，统一契约
- 目标：将 `planning` 从“单类承载全链路”重构为“编排层 + 组件层 + 领域对象层”的可维护结构。

## 2. 改造原则
1. 新方案直落，不为历史路径增加兼容分支。
2. 对可替代旧逻辑直接删除，不保留重复实现。
3. 组件职责单一，优先高内聚、低耦合、可测试。
4. 所有关键路径保留可观测日志（开始、结束、失败）。
5. 每阶段完成后执行完整测试，未通过不得进入下一阶段。

## 3. 目标结构（P1 落地后）
- `PlannerService`：仅负责流程编排与结果装配。
- `LlmPlanEngine`：负责提示词、模型调用、修复、调用链路日志。
- `HeuristicPlanBuilder`：负责规则规划与策略分支生成。
- `PlanParser`：负责模型输出解析、标准化、输入校验。
- `PlanTelemetry`：负责规划阶段事件、埋点、关键指标发布。
- `PlanningContext`：承载规划上下文字段、默认值与校验逻辑。

## 5. 分阶段执行计划（含强制测试门禁）

### 阶段一：架构拆分骨架（P1-ARCH、P1-LLM、P1-RULE）
1. 建立子包与接口骨架。
2. 抽离 `LlmPlanEngine`、`HeuristicPlanBuilder`。
3. `PlannerService` 改为调用组件。
4. 阶段测试：
   - `mvn -q -Dtest=PlannerServiceTest test`
   - `mvn -q -Dtest=LlmPlanEngineTest,HeuristicPlanBuilderTest test`
   - `mvn -q test`

### 阶段二：解析与上下文强类型化（P1-PARSER、P1-CONTEXT）
1. 抽离 `PlanParser`，合并解析与校验规则。
2. 引入 `PlanningContext` + `PlanningContextMapper`。
3. 将主流程关键字段访问替换为强类型对象。
4. 阶段测试：
   - `mvn -q -Dtest=PlanParserTest,PlanningContextMapperTest test`
   - `mvn -q -Dtest=PlannerServiceTest test`
   - `mvn -q test`

### 阶段三：契约收口与清理验收（P1-CONTRACT、P1-CLEAN、P1-TEST）
1. 完成上下文键统一来源收口。
2. 清理无用模型与遗留重复代码。
3. 增加集成回归断言与稳定性检查。
4. 阶段测试：
   - `mvn -q -Dtest=PlannerServiceTest,AgentRuntimeApprovalIntegrationTest test`
   - `mvn -q test`

## 6. P1 验收标准

### 6.1 架构验收
1. `PlannerService` 只保留编排逻辑，不直接实现模型调用、规则构建、解析细节。
2. 至少形成 4 个可独立复用组件：`LlmPlanEngine`、`HeuristicPlanBuilder`、`PlanParser`、`PlanTelemetry`。
3. 主流程关键字段读取切换为 `PlanningContext`，裸 `Map` 访问仅允许在映射边界层。

### 6.2 质量验收
1. 规划核心组件均有独立单测且通过。
2. 全量测试通过：`mvn -q test`。
3. 日志可读、异常有堆栈、外部调用节点有开始/结束/失败记录。

### 6.3 规模验收（建议门槛）
1. `PlannerService` 行数控制在 600 行以内。
2. `PlannerService` 方法数控制在 15 个以内。
3. 规划主流程圈复杂度显著下降（按静态检查基线对比）。

## 7. 风险与应对
- 风险 1：组件拆分后调用顺序改变导致行为偏差。
  - 应对：先固化现有行为测试，再进行迁移，迁移后逐条回归。
- 风险 2：上下文强类型化遗漏边界字段。
  - 应对：在 `PlanningContextMapperTest` 中补齐缺省/非法/缺失字段场景。
- 风险 3：日志抽象后上下文字段不完整。
  - 应对：`PlanTelemetry` 统一字段模板并增加日志断言测试。

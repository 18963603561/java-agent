## 3. P1 架构项落地

### 3.1 P1-01 解除 `mcp` 与 `registry` 的模型耦合环

- 新增中立模型：`src/main/java/com/example/agent/capabilities/tools/model/ToolDefinition.java`
- 迁移与对齐：
  - `ToolRegistry` 改为持有/输出 `ToolDefinition`。
  - `ToolCatalogService` 的 `getDefinition` 返回类型改为 `ToolDefinition`。
  - `DefaultToolCatalog`、`ToolExecutor`、`ToolArgumentValidatorRuntime`、`PluginLoader`、`ModelToolResolver` 统一改为依赖 `ToolDefinition`。
  - `McpToolListResponse` 的 `tools` 从 `List<McpToolDefinition>` 改为 `List<ToolDefinition>`。
  - `McpToolSyncService` 内部缓存快照类型同步为 `ToolDefinition`。
  - `McpToolDefinition` 保留为 `ToolDefinition` 的兼容子类，避免协议层序列化行为突变。

- 结果：
  - `registry` 不再依赖 `mcp` 模型。
  - `mcp -> registry` 的业务依赖保留（符合调用方向），模型耦合环解除。

### 3.2 P1-02 关键类复杂度收敛

- `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolClient.java`
  - 将大分支拆分为：
    - `executeListByStrategy`
    - `executeListLocalFirst`
    - `executeListRemotePreferred`
    - `executeCallByStrategy`
    - `executeCallLocalFirst`
    - `executeCallRemotePreferred`
    - `unavailableForCall`
  - 保留门面入口不变，策略语义不变，提升可读性与可测试性。

- `src/main/java/com/example/agent/capabilities/tools/hook/HookManager.java`
  - 提取 `buildHookContext`。
  - 提取 `recordSkippedDecision`，收敛 disabled/default 分支重复逻辑。

### 3.3 P1-03 会话/初始化状态回收策略

- `src/main/java/com/example/agent/capabilities/tools/mcp/session/McpSseSessionManager.java`
  - 新增状态清理策略：周期清理 + 空闲超时 + 容量上限回收。
  - 回收时中断 worker、关闭流、清理 lock/state，避免状态表增长失控。

- `src/main/java/com/example/agent/capabilities/tools/mcp/protocol/McpJsonRpcAdapter.java`
  - 初始化缓存从 `Boolean` 升级为 `InitState`（含最近访问时间）。
  - 增加 `cleanupInitState`，按周期、空闲时间和容量上限回收。

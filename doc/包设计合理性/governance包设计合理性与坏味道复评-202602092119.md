## 6. 坏味道清单（按严重度）

### 6.1 B 级：重复日志与异常分支重复处理

- 位置：`src/main/java/com/example/agent/governance/replay/domain/ReplayTaskResolver.java:48`
- 位置：`src/main/java/com/example/agent/governance/replay/domain/ReplayTaskResolver.java:55`
- 位置：`src/main/java/com/example/agent/governance/replay/domain/ReplayTaskResolver.java:67`

问题说明：

- `REPLAY_NOT_FOUND` 在主流程与异常分支都调用 `logReplayNotFound`，会产生重复告警噪音。

影响：

- 告警统计偏高，排障时不利于判断真实异常频率。

建议：

- 统一在单一出口记录一次 `not_found`，其余分支只做错误转换。

### 6.2 B 级：空值防御不完整

- 位置：`src/main/java/com/example/agent/governance/policy/PolicyEngine.java:41`
- 位置：`src/main/java/com/example/agent/governance/replay/domain/ReplayTaskResolver.java:46`

问题说明：

- 关键流程直接使用 `tenantContext.getTenantId()`、`command.getTaskId()`，缺少输入校验与统一失败语义。

影响：

- 在上游上下文缺失场景可能出现空指针或非预期错误码。

建议：

- 在方法入口增加参数校验与标准化异常码，避免隐式空指针失败。

### 6.3 C 级：场景语义混用

- 位置：`src/main/java/com/example/agent/governance/evaluation/CapabilityBoundaryEvaluator.java:256`
- 位置：`src/main/java/com/example/agent/governance/evaluation/CapabilityBoundaryEvaluator.java:260`

问题说明：

- `resolveScene` 当前直接使用 `planSummary` 作为 `scene`，语义不稳定且粒度过细。

影响：

- 场景覆盖配置命中不可预测，配置维护成本上升。

建议：

- 为评估输入增加显式 `scene` 字段，`planSummary` 仅用于描述，不参与规则覆盖键。

### 6.4 C 级：指标命名存在双轨

- 位置：`src/main/java/com/example/agent/governance/replay/ReplayService.java:118`
- 位置：`src/main/java/com/example/agent/governance/approval/ApprovalService.java:175`
- 位置：`src/main/java/com/example/agent/governance/approval/ApprovalService.java:293`
- 位置：`src/main/java/com/example/agent/governance/approval/ApprovalService.java:299`

问题说明：

- 同一领域同时使用 `governance.xxx` 与历史命名（如下划线风格）并存。

影响：

- 仪表盘和告警规则需要做双映射，长期维护成本偏高。

建议：

- 收敛到 `GovernanceTelemetry` 统一词典，保留旧指标做短期兼容窗口后下线。

### 6.5 D 级：小规模僵尸接口迹象

- 位置：`src/main/java/com/example/agent/governance/common/telemetry/GovernanceTelemetry.java:119`

问题说明：

- `metricName` 目前未被项目调用，属于可疑未使用接口。

影响：

- 代码噪音增加，真实可用接口边界不清晰。

建议：

- 若短期不使用则删除；若计划使用则补上调用点与对应测试。

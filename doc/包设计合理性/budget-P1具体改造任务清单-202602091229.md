# budget 包设计合理性 P1 具体改造任务清单

## 1. 任务背景

- 输入依据：`doc/budget-包设计合理性与坏味道评估-202602091221.md`
- P1 问题范围：
  - 问题 1：`token` 与 `trim` 双向依赖（包循环）。
  - 问题 2：`DefaultContextTrimmer` 过大且职责混杂。
- 本清单目标：给出可排期、可执行、可验收的 P1 改造任务。

## 2. 总体目标与完成定义

### 2.1 总体目标

- 消除 `com.example.agent.budget.token` 与 `com.example.agent.budget.trim` 的双向依赖。
- 将 `DefaultContextTrimmer` 从“大而全”重构为“编排层 + 策略执行层 + 估算层 + 统计层”。
- 保持现有业务行为稳定，保障现有预算裁剪与压缩触发链路不回归。

### 2.2 完成定义

- 架构完成定义：
  - `token` 包不再依赖 `trim` 包。
  - `trim` 包不再依赖 `token` 包。
  - 共享模型沉淀到稳定内核包（建议：`com.example.agent.budget.core`）。
- 代码完成定义：
  - `DefaultContextTrimmer` 行数下降到 450 行以内。
  - `DefaultContextTrimmer` 仅保留流程编排职责。
  - 各 section 裁剪逻辑独立成组件类。
- 验证完成定义：
  - 现有测试通过。
  - 新增重构相关单测通过。
  - 增加“禁止循环依赖”的静态守卫检查。

## 4. 具体任务清单

### P1-T01 建立依赖基线与回归基线

- 改造目标：冻结当前行为，避免重构后“无对照”。
- 主要动作：
  - 导出当前 `budget` 包内跨包 import 关系。
  - 执行并记录当前可用单测结果与关键日志样例。
  - 固化一份“重构前基线记录”。
- 产出物：
  - 基线记录文档（建议 `doc/notes/`）。
- 验收标准：
  - 可明确列出当前双向依赖点与关键回归用例。

### P1-T02 抽取 budget 共享内核包

- 改造目标：建立稳定依赖方向，提供 `token` 和 `trim` 公共模型承载位置。
- 主要动作：
  - 新建包建议：
    - `com.example.agent.budget.core`
    - `com.example.agent.budget.core.model`
  - 明确“只允许被依赖，不依赖具体实现包”的规则。
- 产出物：
  - 内核包结构与包说明文档。
- 验收标准：
  - 新包职责清晰，命名与边界得到评审确认。

### P1-T03 迁移预算共享模型并解耦包循环

- 改造目标：彻底消除 `token <-> trim` 的直接互相 import。
- 主要动作：
  - 迁移/下沉以下共享对象到 `budget.core`：
    - `ContextSection`
    - `ContextTrimSection`
    - `ContextBudgetPolicy`
    - `ContextBudgetAllocation`
  - 更新引用方 import，确保：
    - `token` 仅依赖 `budget.core`。
    - `trim` 仅依赖 `budget.core`。
  - 处理构造器与方法签名变更，保证调用链兼容。
- 影响文件（重点）：
  - `src/main/java/com/example/agent/budget/token/ContextBudgetProperties.java`
  - `src/main/java/com/example/agent/budget/token/DefaultContextBudgetAllocator.java`
  - `src/main/java/com/example/agent/budget/trim/ContextTrimRequest.java`
  - `src/main/java/com/example/agent/budget/trim/ContextCompressionRequest.java`
  - `src/main/java/com/example/agent/budget/trim/DefaultContextTrimmer.java`
- 验收标准：
  - 检索结果中不再出现 `token` 对 `trim` 的 import。
  - 检索结果中不再出现 `trim` 对 `token` 的 import。

### P1-T04 加入“禁止循环依赖”守卫检查

- 改造目标：防止后续改动再次引入包循环。
- 主要动作：
  - 新增架构守卫测试或静态检查脚本。
  - 在 CI 中加入检查步骤。
  - 对失败输出给出明确提示文本。
- 验收标准：
  - 人为制造循环依赖时，检查可稳定失败。
  - 清理循环依赖后，检查恢复通过。

### P1-T05 切分 DefaultContextTrimmer 编排层

- 改造目标：让 `DefaultContextTrimmer` 仅负责流程编排。
- 主要动作：
  - 保留入口 `trim(ContextTrimRequest request)`。
  - 将流程拆为明确步骤：
    - 预算超限判定。
    - 按 section 顺序执行裁剪。
    - 裁剪结果聚合。
    - 指标与日志记录。
  - 去除与业务策略细节绑定的内联实现。
- 产出物：
  - 简化后的编排器类。
- 验收标准：
  - `DefaultContextTrimmer` 可读性显著提升，方法复杂度下降。

### P1-T06 抽取 Section 裁剪策略组件

- 改造目标：把不同 section 的裁剪规则解耦成独立策略。
- 主要动作：
  - 设计统一接口（示例命名）：`ContextSectionTrimHandler`。
  - 每个 section 对应独立实现类：
    - `EvidencePackTrimHandler`
    - `RecalledMemoriesTrimHandler`
    - `WorkingMemoryTrimHandler`
    - `ToolSummaryTrimHandler`
    - `TaskAndSystemTrimHandler`
  - 通过顺序列表驱动执行，避免大 `switch` 持续膨胀。
- 验收标准：
  - 新增 section 仅需新增 handler 并注册，不需修改核心编排流程。

### P1-T07 抽取统一 Token 估算组件

- 改造目标：消除 `DefaultContextTrimmer` 与 `ContextCompressionController` 的重复估算逻辑。
- 主要动作：
  - 抽取统一组件（示例命名）：`ContextTokenEstimatorService`。
  - 收敛以下能力到同一组件：
    - `estimateSectionTokens`
    - `estimateTaskIntentTokens`
    - `estimateWorkingMemoryTokens`
    - `estimateEvidencePackTokens`
    - 其他 `estimateXxxTokens`
  - `DefaultContextTrimmer` 与 `ContextCompressionController` 统一改为调用该组件。
- 验收标准：
  - 同一 `ContextSnapshot` 在两条链路上的分段估算结果一致。

### P1-T08 抽取裁剪统计与指标记录组件

- 改造目标：避免业务逻辑与指标逻辑耦合，提升可测试性。
- 主要动作：
  - 抽取 `recordRemoved`、`recordMetrics` 相关逻辑。
  - 统一输出字段与标签命名，减少重复代码。
  - 在异常分支补充必要日志上下文。
- 验收标准：
  - 主流程代码不再直接拼装复杂指标细节。

### P1-T09 重构后回归测试与性能抽样验证

- 改造目标：保证重构不改变行为边界。
- 主要动作：
  - 执行并通过现有预算相关测试。
  - 新增至少三类测试：
    - 包依赖守卫测试。
    - 估算一致性测试（裁剪链路 vs 压缩链路）。
    - 各 section handler 单测。
  - 抽样验证关键路径耗时不劣化明显。
- 验收标准：
  - 所有测试通过。
  - 裁剪与压缩关键流程结果与重构前一致。

### P1-T10 文档与运维发布说明补齐

- 改造目标：保障改造可交接、可运维。
- 主要动作：
  - 更新包结构说明与依赖规则。
  - 更新重构后的类职责图与调用关系图。
  - 输出灰度发布与回滚说明。
- 验收标准：
  - 文档可支持新成员独立理解并定位改造点。

## 5. 任务执行顺序建议

- 第一批（必须先做）：`P1-T01 -> P1-T02 -> P1-T03 -> P1-T04`
- 第二批（并行可做）：`P1-T05 + P1-T06 + P1-T07 + P1-T08`
- 收口批（最后做）：`P1-T09 -> P1-T10`

## 6. 关键风险与应对

- 风险 1：模型迁移引起序列化或反序列化兼容问题。
  - 应对：保留兼容构造与必要转换层，增加契约测试。
- 风险 2：重构 `DefaultContextTrimmer` 后行为偏移。
  - 应对：先补“行为基线测试”，再分步替换。
- 风险 3：估算统一后影响压缩触发阈值。
  - 应对：引入“估算一致性 + 触发阈值回归”组合测试。

## 7. 验收命令建议

- 定向预算模块测试：
  - `mvn "-Dtest=ContextCompressionControllerTest,DefaultContextBudgetAllocatorTest,DefaultContextPrunerPolicyTest,DefaultContextPrunerTest,DefaultContextTrimmerTest" test`
- 全量测试（排期允许时）：
  - `mvn test`

## 8. 预期结果

- 完成 P1 后，包依赖方向稳定，核心类职责清晰，后续 P2 改造难度显著下降。
- 预期整体设计等级可由 `B-` 提升到 `B+`。

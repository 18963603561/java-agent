# 高风险不合理类推进方案

## 1. 目标

围绕当前工程中“明确不合理（高风险）”的超大类，给出可立即执行的推进方案，目标是：

- 降低核心编排层的变更耦合风险。
- 将外部不稳定依赖与业务决策分层隔离。
- 在不改变业务语义的前提下，持续降低单类复杂度。

扫描范围：`src/main/java/**/*.java`，统计实现类总行数大于 1000。

## 3. 明确不合理点（高风险）

### 3.1 AgentRuntime

不合理点：

- 同时承担运行时生命周期编排、步骤分发、审批门禁、失败恢复、输出收口。
- 对 `step/react/recovery/finalize` 多子域存在大量直接依赖。
- 分支密集导致“加一个策略，改多个路径”。

直接风险：

- 任一功能改动都会放大回归面。
- 故障定位路径长，线上恢复慢。

### 3.2 PlannerService

不合理点：

- 规划策略选择、LLM 规划调用、规则回退、结果修复、归一化、校验混在同一服务。
- 规则与模型路径交织，导致测试夹具复杂。

直接风险：

- 策略迭代时易引入联动缺陷。
- 新增规划能力成本持续抬升。

### 3.3 LlmStepService

不合理点：

- 模型调用、工具注入、输出清洗、兼容处理集中在单类。
- 数据转换逻辑与流程控制混排。

直接风险：

- 模型协议变更会影响步骤执行主链路。
- 输出结构的回归验证成本高。

### 3.4 McpToolClient

不合理点：

- 连接初始化、协议适配、重试、降级、异常处理同层实现。
- `catch` 过多，异常路径可读性和一致性不足。

直接风险：

- 外部网络抖动会触发大量分支路径。
- 重试与降级策略难统一，行为不可预测。

## 4. 推进原则

- 先“稳边界”再“拆实现”：先固定门面输入输出契约，再下沉细节。
- 每个 PR 只做一种职责迁移，确保可回滚。
- 先补关键链路契约测试，再动核心分支。
- 新增组件必须带日志埋点：开始、关键分支、结束、异常。

## 5. 分阶段推进方案（可直接排期）

### 阶段A（P0，1-2周）：先稳定运行时主链路

PR-A1：收敛 AgentRuntime 门面职责

- 目标：`AgentRuntime` 只保留生命周期编排与阶段调用。
- 主要改动文件：
  - `src/main/java/com/example/agent/runtime/AgentRuntime.java`
  - `src/main/java/com/example/agent/runtime/prepare/RuntimePreparationService.java`
  - `src/main/java/com/example/agent/runtime/finalize/RuntimeFinalizationService.java`
- 验收：主流程测试与现有行为一致；日志链路完整。

PR-A2：把步骤执行分支全部下沉到 StepRuntimeService

- 目标：`AgentRuntime` 不再持有步骤细节判断。
- 主要改动文件：
  - `src/main/java/com/example/agent/runtime/step/StepRuntimeService.java`
  - `src/main/java/com/example/agent/runtime/step/StepExecutorRouter.java`
  - `src/main/java/com/example/agent/runtime/step/StepExecutionDelegate.java`
- 验收：步骤执行结果结构不变；异常路径有统一上下文日志。

PR-A3：恢复与审批链路隔离

- 目标：把恢复策略和审批判定从主编排路径抽成独立调用点。
- 主要改动文件：
  - `src/main/java/com/example/agent/runtime/recovery/RecoveryStrategyManager.java`
  - `src/main/java/com/example/agent/runtime/control/RuntimeApprovalGate.java`
  - `src/main/java/com/example/agent/runtime/control/RuntimeExecutionGate.java`
- 验收：审批与恢复可独立测试；主流程中仅保留调用。

### 阶段B（P0，1周）：治理外部不稳定依赖

PR-B1：拆分 McpToolClient 为三层

- 目标：形成 `transport + retry + adapter` 分层。
- 建议新增类：
  - `com.example.agent.capabilities.tools.mcp.transport.McpTransport`
  - `com.example.agent.capabilities.tools.mcp.retry.McpRetryPolicy`
  - `com.example.agent.capabilities.tools.mcp.protocol.McpProtocolAdapter`
- 主要改动文件：
  - `src/main/java/com/example/agent/capabilities/tools/mcp/McpToolClient.java`
- 验收：重试与降级策略可单测覆盖；`catch` 数明显下降。

### 阶段C（P1，1-2周）：稳定规划与模型步骤边界

PR-C1：PlannerService 门面化

- 目标：`PlannerService` 只保留“策略选择 + 管线编排”。
- 建议新增类：
  - `PlannerCapabilityEvaluator`
  - `PlannerRepairService`
  - `PlannerResultNormalizer`
  - `PlannerResultValidator`
- 主要改动文件：
  - `src/main/java/com/example/agent/planning/PlannerService.java`
- 验收：规划结果契约不变；失败路径可定位到具体组件。

PR-C2：LlmStepService 拆成调用、注入、归一化三段

- 目标：隔离模型调用协议变化对步骤主流程的冲击。
- 建议新增类：
  - `LlmInvocationFacade`
  - `ToolInjectionService`
  - `LlmOutputNormalizer`
- 主要改动文件：
  - `src/main/java/com/example/agent/runtime/engine/LlmStepService.java`
- 验收：结构化输出与历史样本一致；模型切换回归可控。

## 6. 风险控制与回滚策略

- 每个 PR 保持“行为等价”，禁止混入新需求。
- 每个 PR 合并前必须执行：`mvn test`。
- 对核心链路增加契约快照校验：审批状态迁移、步骤结果结构、最终输出字段。
- 回滚粒度以单 PR 为单位，避免跨阶段回退。

## 7. 里程碑验收标准

- `AgentRuntime` 行数降到 1200 以下，方法数降到 45 以下。
- `PlannerService` 行数降到 1000 以下，方法数降到 35 以下。
- `LlmStepService` 与 `McpToolClient` 的异常处理统一通过策略组件承载。
- 高风险四类全部具备独立组件级测试与统一日志上下文。

## 8. 建议执行顺序

1. 阶段A：先把运行时主链路稳定下来。
2. 阶段B：立即治理外部依赖不稳定点。
3. 阶段C：最后收敛规划与模型步骤边界。

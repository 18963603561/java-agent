# reasoning 包 P2 改造任务清单

## 1. 目标与范围

基于以下文档形成 P2 清单：

- `doc/reasoning包设计与坏味道评估-202602092219.md`
- `doc/reasoning包P0改造任务清单-202602092228.md`
- `doc/reasoning包P1改造任务清单-202602092243.md`
- `doc/reasoning包P1改造落地实施记录-202602092336.md`

P2 定位：在 P1“组件化与统一契约”基础上，继续推进**可观测统一、强类型契约、配置治理与并行能力**，把 `reasoning` 从“可维护”提升到“可演进”。

P2 原则：

1. 新项目按新方案直接收敛，不引入历史兼容分支。
2. 优先消除跨策略重复实现，统一公共能力层。
3. 对高频演进点（输出契约、配置项、可观测字段）先做标准化。
4. 每个阶段必须保留可验证的测试门禁与回滚方案。

P2 聚焦范围：

- `src/main/java/com/example/agent/reasoning/common`
- `src/main/java/com/example/agent/reasoning/cot`
- `src/main/java/com/example/agent/reasoning/debate`
- `src/main/java/com/example/agent/reasoning/thoughttree`
- `src/main/java/com/example/agent/runtime/step/executor`
- `src/test/java/com/example/agent/reasoning`
- `src/test/java/com/example/agent/runtime`

## 3. 具体改造任务

### P2-RSN-01 推理可观测能力统一组件化

**目标**

- 消除 `cot/debate/thoughttree` 在事件发布、trace 记录、指标打点上的重复实现与字段不一致问题。

**改造范围**

- 新增：
  - `src/main/java/com/example/agent/reasoning/common/telemetry/ReasoningEventPublisher.java`
  - `src/main/java/com/example/agent/reasoning/common/telemetry/ReasoningTraceRecorder.java`
  - `src/main/java/com/example/agent/reasoning/common/telemetry/ReasoningMetricsPublisher.java`
- 适配：
  - `src/main/java/com/example/agent/reasoning/cot/ChainOfThoughtService.java`
  - `src/main/java/com/example/agent/reasoning/debate/DebateCoordinator.java`
  - `src/main/java/com/example/agent/runtime/step/executor/ThoughtTreeStepExecutor.java`

**具体工作项**

1. 统一事件元字段：`tenantId/workflowId/seq/strategyType/stepType`。
2. 统一 trace 字段：`parseSuccess/parseErrorType/repairAttempted/repairSuccess/modelId`。
3. 建立统一指标命名规范（例如 `reasoning_*` 前缀），并补齐标签维度。
4. 移除策略类中重复事件拼装与 trace 记录代码，仅保留业务字段装配。

**交付物**

- 一套可复用的推理可观测组件。
- 三个策略调用点统一接入。

**验收标准**

- `ChainOfThoughtService` 与 `DebateCoordinator` 不再各自维护重复 `recordPromptTrace/publishEvent` 细节实现。
- 日志、trace、metrics 字段命名在三个策略中一致。

---

### P2-RSN-02 推理结果契约强类型化收敛

**目标**

- 消除 `ReasoningResult.details(Map)` 的动态键值风险，建立强类型输出契约。

**改造范围**

- `src/main/java/com/example/agent/reasoning/common/ReasoningResult.java`
- 新增：
  - `src/main/java/com/example/agent/reasoning/common/result/ReasoningPayload.java`
  - `src/main/java/com/example/agent/reasoning/common/result/CotPayload.java`
  - `src/main/java/com/example/agent/reasoning/common/result/DebatePayload.java`
  - `src/main/java/com/example/agent/reasoning/common/result/ThoughtTreePayload.java`
- 适配：
  - `ChainOfThoughtService`
  - `DebateCoordinator`
  - `ThoughtTreeService`
  - `ChainOfThoughtStepExecutor`
  - `DebateStepExecutor`
  - `ThoughtTreeStepExecutor`

**具体工作项**

1. 用强类型 `payload` 替换 `details` 动态映射。
2. 为三类策略定义固定字段与可选字段边界，补齐中文注释。
3. 执行器改为消费强类型字段，删除 `toInt/Map.get("xxx")` 等弱类型代码。
4. 明确序列化策略，保证对外输出字段稳定。

**交付物**

- `ReasoningResult` 强类型模型。
- 执行器输出装配逻辑去动态键访问。

**验收标准**

- 推理执行链不再依赖字符串 key 读写 `details`。
- 编译期可发现字段缺失/类型错误。

---

### P2-RSN-03 推理配置中心与参数校验治理

**目标**

- 解决策略参数分散在执行器与服务内部的问题，建立统一配置与校验入口。

**改造范围**

- 新增：
  - `src/main/java/com/example/agent/reasoning/common/config/ReasoningExecutionProperties.java`
  - `src/main/java/com/example/agent/reasoning/common/config/ReasoningConfigValidator.java`
  - `src/main/java/com/example/agent/reasoning/common/config/ReasoningConfigResolver.java`
- 适配：
  - `ThoughtTreeStepExecutor`
  - `ChainOfThoughtService`
  - `DebateCoordinator`

**具体工作项**

1. 建立策略级配置域：超时、重试、预算、温度、并发度等。
2. 将 `ThoughtTree` 参数读取从执行器硬编码迁移到配置解析器。
3. 对非法参数统一校验与降级策略（如负值、超阈值、空配置）。
4. 在日志中输出“配置来源 + 生效值 + 降级原因”。

**交付物**

- 统一推理配置中心组件。
- 三策略核心参数由配置解析器管理。

**验收标准**

- 执行器与服务中不再散落参数默认值魔法数。
- 配置异常场景具备稳定兜底与观测信息。

### P2-RSN-04 多策略并行编排与结果仲裁

**目标**

- 支持在高复杂场景并行执行多个推理策略并进行结果仲裁，提升鲁棒性与输出质量。

**改造范围**

- 新增：
  - `src/main/java/com/example/agent/reasoning/common/orchestrator/ReasoningOrchestrator.java`
  - `src/main/java/com/example/agent/reasoning/common/orchestrator/ReasoningExecutionPlan.java`
  - `src/main/java/com/example/agent/reasoning/common/orchestrator/ReasoningArbitrator.java`
- 适配：
  - `ReasoningStrategyRegistry`
  - `runtime/step/executor`（增加可选并行入口）

**具体工作项**

1. 定义并行执行模型：主策略 + 候选策略集合 + 超时控制。
2. 建立仲裁规则：置信度、完整性、停止原因、质量评分。
3. 增加失败隔离：单策略失败不影响整体结果返回。
4. 增加并行执行观测：每个策略耗时、失败原因、仲裁胜出策略。

**交付物**

- 推理并行编排器与仲裁器。
- 在不改外部契约前提下支持并行结果融合。

**验收标准**

- 至少支持 `COT + DEBATE` 并行执行并稳定返回单一结果。
- 并行模式下仍满足现有步骤输出契约。

---

### P2-RSN-05 策略选择与降级治理闭环

**目标**

- 建立“策略选择-执行结果-降级反馈”闭环，避免固定策略导致的质量波动。

**改造范围**

- 新增：
  - `src/main/java/com/example/agent/reasoning/common/selection/ReasoningStrategySelector.java`
  - `src/main/java/com/example/agent/reasoning/common/selection/ReasoningDegradePolicy.java`
- 适配：
  - `runtime/step/executor`（接入选择器）
  - `ReasoningOrchestrator`（接入降级策略）

**具体工作项**

1. 根据输入复杂度、风险等级、预算约束选择策略或并行组合。
2. 定义降级链路：主策略失败时按优先级切换备用策略。
3. 记录策略选择与降级决策，支持后续评估。
4. 补齐“选择正确性 + 降级稳定性”测试用例。

**交付物**

- 统一策略选择器与降级策略组件。
- 执行器不再硬编码策略选择分支。

**验收标准**

- 失败/超时场景下，能够自动降级并返回有效结果。
- 策略选择决策可追踪、可解释。

---

### P2-RSN-06 P2 全链路回归与基线固化

**目标**

- 确保 P2 改造在扩展能力提升的同时不引入质量回退，并沉淀性能对照基线。

**执行清单**

1. 定向推理测试：

```bash
mvn "-Dtest=ChainOfThoughtServiceTest,DebateCoordinatorTest,ThoughtTreeServiceTest" test
```

2. 运行时耦合集成测试：

```bash
mvn "-Dtest=AgentRuntimeApprovalIntegrationTest" test
```

3. 新增并行与仲裁测试（建议）：

```bash
mvn "-Dtest=ReasoningOrchestratorTest,ReasoningArbitratorTest,ReasoningStrategySelectorTest" test
```

4. 全量回归：

```bash
mvn test
```

5. 性能基线记录（建议至少包含）：
   - 单策略平均耗时 P50/P95；
   - 并行模式端到端耗时；
   - 策略失败率与降级命中率。

**门禁标准**

- 推理相关单测与集成测试全部通过。
- 并行模式下输出契约稳定，不出现字段缺失。
- 可观测字段一致，无乱码与无意义错误码。
- 基线文档记录完整（风险、影响、回滚方式）。

## 4. P2 完成定义（DoD）

1. 推理层可观测能力统一组件化完成，策略实现不再复制粘贴观测代码。
2. 推理结果契约强类型化完成，移除动态 `details` 依赖。
3. 配置中心与参数校验落地，关键策略参数具备统一治理入口。
4. 多策略并行执行与仲裁能力落地，并通过稳定性测试。
5. 策略选择与降级闭环可运行、可追踪。
6. 全链路回归通过并沉淀 P2 基线文档。

---

## 5. 本轮不纳入 P2 的事项（避免范围膨胀）

1. 跨系统统一指标平台改造（超出 `reasoning` 包边界）。
2. 模型供应商侧路由策略重构（属于 `capabilities/llm` 主域优化）。
3. 大规模压测平台建设（建议独立性能专项推进）。

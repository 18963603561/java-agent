# tools P1 改造落地验收记录

## 1. 背景与目标

依据 `doc/tools-P1改造任务清单-202602081327.md` 完成 P1 全量落地，执行策略如下：

1. 新项目直接切换到新方案，不保留历史双轨兼容分支。
2. 按阶段顺序实施：接口收敛 → 字段落地 → 前置校验统一 → 测试补齐。
3. 每阶段结束后执行全流程回归，确认可编译、可测试。

## 2. 分阶段实施结果

### 2.1 P1-1 接口收敛

1. 删除 `ToolCatalog` 接口，目录能力统一收敛到 `ToolCatalogService`。
2. `ToolCatalogService` 统一方法语义，保留：
   - `listSummaries(ToolQuery)`
   - `getDefinition(String)`
   - `getToolSchema(String)`
3. `DefaultToolCatalog` 改为单接口实现，移除重复别名方法。
4. 调用方统一改造：
   - `DefaultContextBuilder` 注入并调用 `ToolCatalogService`。
   - `ModelToolResolver` 去除双接口/回退逻辑，统一使用单一目录服务。

### 2.2 P1-2 `allowedScopes` 与 `locale` 落地

1. `McpToolDefinition` 新增筛选元数据：
   - `authScope`
   - `supportedLocales`
2. `DefaultToolCatalog` 查询链路新增组合筛选：
   - 标签筛选：沿用原逻辑。
   - 范围筛选：`allowedScopes` 命中 `authScope`。
   - 语言筛选：`locale` 命中 `supportedLocales`，支持 `zh_cn` / `zh-CN` 归一化匹配。
3. `ToolSummary.authScope` 从定义映射，避免展示语义与查询语义不一致。
4. 默认行为明确：
   - `allowedScopes` 为空：不按范围过滤。
   - `locale` 为空：不按语言过滤。
   - 定义缺失字段时采用保守过滤（查询指定时不放行）。

### 2.3 P1-3 参数前置校验统一

1. 新增统一入口校验器 `ToolRequestValidator`。
2. 关键入口统一接入：
   - `McpToolClient.listTools` / `callTool`
   - `ToolExecutor.execute` / `executeWithArguments`
   - `EnforcementGateway.execute` / `executeWithArguments`
3. 错误语义统一：
   - 状态码：`HttpStatus.BAD_REQUEST`
   - 错误码：`INVALID_REQUEST`
   - 错误消息包含缺失参数名，例如：`request.toolName 不能为空`
4. 删除入口散落式重复判空，统一收敛到公共组件。

### 2.4 P1-4 测试补齐与收口

1. 更新接口收敛相关测试：`DefaultContextBuilderTest`、`ModelToolResolverTest`。
2. 新增字段落地测试：
   - `DefaultToolCatalogTest#listSummariesFiltersByAllowedScopes`
   - `DefaultToolCatalogTest#listSummariesFiltersByLocale`
3. 新增参数校验测试：
   - `McpToolClientTest`：空请求、空租户、空工具名。
   - `ToolExecutorTest`：空请求、空租户、空工具名。
   - `EnforcementGatewayTest`：空请求、空租户、空工具名、空 `seqCounter`。

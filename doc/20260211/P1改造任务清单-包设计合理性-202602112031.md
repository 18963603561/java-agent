# P1改造任务清单-包设计合理性-202602112031

## 1. 输入与范围
- 依据文档：`doc/20260211/multiagent包设计评审-P0P4分级-202602111841.md`
- 参考实现：`vendor/Shannon/go/orchestrator/internal/workflows`、`vendor/Shannon/go/orchestrator/internal/activities`、`vendor/Shannon/go/orchestrator/internal/streaming`
- 改造范围：`src/main/java/com/example/agent/orchestration/multiagent`
- 本清单目标：只落地 `P1` 高优先级问题，重点解决可维护性、职责分离与应用层耦合。

## 2. P1改造总目标（必须全部达成）
1) `DagActorRuntime` 从“巨型运行时类”拆分为清晰的运行编排、节点执行、依赖传播、收尾归档职责。
2) `MultiAgentEventPublisher` 按领域拆分，避免 handoff/dag/team 事件模板集中在一个超大类。
3) `MultiAgentCoordinator` 引入用例层与策略执行器，去掉一个类承载全链路决策的耦合。
4) 过程坚持新方案直落地，不为历史兼容增加条件分支。
5) 每阶段完成后执行阶段测试，最后执行全量回归。

## 3. P1具体改造任务清单

### T-P1-PKG-01：`DagActorRuntime` 职责拆分
- 问题来源：`P1-1 God Class`，当前类承担运行循环、节点执行、依赖消息投递、审计落盘、最终状态收敛等多重职责。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagRunOrchestrator.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagNodeExecutionService.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagDependencyPropagationService.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagRunFinalizeService.java`
- 改造要求：
  - `DagActorRuntime` 仅保留参数装配与顶层 `run(...)` 协调，不再承载细节算法。
  - 节点执行重试、租约申请/释放、节点事件发布下沉到 `DagNodeExecutionService`。
  - 依赖消息构造、分片路由、投递审计下沉到 `DagDependencyPropagationService`。
  - 运行结束状态计算、审计汇总、失败聚合下沉到 `DagRunFinalizeService`。
  - 关键路径必须补充中文注释，日志覆盖开始、关键分支、结束与异常。
- 验收标准：
  - `DagActorRuntime` 不再包含节点执行重试循环和依赖投递明细逻辑。
  - 拆分后各服务职责单一，接口参数清晰，命名与包结构可读。
  - 现有 DAG Actor 行为不变，单元测试通过。

### T-P1-PKG-02：`MultiAgentEventPublisher` 领域化拆分
- 问题来源：`P1-2`，事件发布器过大且对多域事件模板高度耦合。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/event/DagEventPublisher.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/event/HandoffEventPublisher.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/event/TeamEventPublisher.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/event/EventPublisherFacade.java`
- 改造要求：
  - 保持外部调用稳定：先保留门面，再逐步迁移到分域发布器。
  - 事件字段构造逻辑按域收敛，不允许跨域硬编码散落。
  - 统一错误处理与日志字段，避免不同发布方法口径漂移。
  - 引入统一事件构建辅助器，减少重复 `Map` 拼装。
- 验收标准：
  - `MultiAgentEventPublisher` 仅保留门面与委派，不再堆积所有 `publish*` 细节实现。
  - dag/handoff/team 三类事件发布实现解耦，新增或修改事件只影响单域代码。
  - 事件相关测试覆盖关键字段与异常场景。

### T-P1-PKG-03：`MultiAgentCoordinator` 用例化解耦
- 问题来源：`P1-3`，应用层组合器同时处理模型调用、角色解析、路由决策、执行器选择、结果拼装。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentCoordinator.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentRoutingPolicy.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/usecase/MultiAgentExecutionUseCase.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/usecase/ExecutionRouteDecider.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/usecase/ExecutionResultAssembler.java`
- 改造要求：
  - Coordinator 仅作为应用层入口，不直接承载路由与拼装细节。
  - 路由策略决策抽离成独立组件，支持后续策略扩展。
  - 结果拼装从流程控制中抽离，减少主流程方法长度与圈复杂度。
  - 保留现有能力语义，不引入历史兼容分支。
- 验收标准：
  - `MultiAgentCoordinator` 主流程显著收敛为“入参校验 -> 用例执行 -> 结果返回”。
  - 路由、执行、结果拼装具备独立可测性。
  - 不同执行模式（如 DAG/Supervisor）通过策略组件扩展而非 if/else 堆叠。

## 5. P1完成定义（DoD）
- 结构上：`DagActorRuntime`、`MultiAgentEventPublisher`、`MultiAgentCoordinator` 三个核心类均完成职责收敛。

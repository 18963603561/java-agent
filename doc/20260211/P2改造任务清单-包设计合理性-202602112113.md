# P2改造任务清单-包设计合理性-202602112113

## 1. 输入与范围
- 依据文档：`doc/20260211/multiagent包设计评审-P0P4分级-202602111841.md`
- 关联基线：`doc/20260211/P1改造落地与测试报告-包设计合理性-202602112110.md`
- 改造范围：`src/main/java/com/example/agent/orchestration/multiagent`
- 本清单目标：仅落地 `P2` 中优先级问题，重点解决契约显式化、状态语义统一、重复逻辑收敛与装配边界稳定。

## 2. P2改造总目标（必须全部达成）
1) 将核心链路中 `Map<String, Object>` 结果契约替换为显式 DTO，降低运行时键漂移风险。
2) 将运行状态与原因码从字符串常量收敛为统一枚举，保证统计口径一致。
3) 将步骤参数读取逻辑抽取为通用组件，消除重复解析实现。
4) 明确 InMemory 与持久化实现的装配边界，避免环境误用。
5) 每个阶段完成后执行阶段测试，最后执行全量回归。

## 3. P2具体改造任务清单

### T-P2-PKG-01：执行结果与上下文 DTO 化
- 问题来源：`P2-1 Map<String, Object> 泛化过度`。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentCoordinator.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/usecase/MultiAgentExecutionUseCase.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/supervisor/SupervisorCoordinator.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/handoff/HandoffService.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/model/MultiAgentExecutionResult.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/model/DagExecutionResult.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/model/SupervisorExecutionResult.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/model/HandoffExecutionResult.java`
- 改造要求：
  - 协调入口、用例层、监督器和交接服务的内部返回值全部使用 DTO。
  - `Map` 仅允许出现在事件 payload 或外部可扩展元数据，不允许作为主流程结果契约。
  - 对外控制器如需 `Map`，必须在 API 适配层做单点转换，不回流到业务层。
- 验收标准：
  - `multiagent` 主流程服务方法不再以 `Map<String, Object>` 作为核心返回契约。
  - 关键字段（mode/status/dagRunId/failures/handoffStatuses）具备编译期约束。

### T-P2-PKG-02：状态与原因码枚举统一
- 问题来源：`P2-2 状态与原因码字符串散落`。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagNodeExecutionService.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagRunFinalizeService.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/supervisor/SupervisorCoordinator.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/control/DagControlService.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/model/RunStatus.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/model/ReasonCode.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/control/ControlCommandType.java`
- 改造要求：
  - 将 `COMPLETED/FAILED/PARTIAL_SUCCESS`、`NODE_FAILED/NODE_RETRY/READY_QUEUE_FULL` 等字符串改为枚举。
  - 事件发布层保留字符串输出时，统一通过枚举映射导出，不允许手写常量。
  - 日志、审计、回放记录统一用同一枚举字典，避免口径分裂。
- 验收标准：
  - 关键路径不再出现散落状态字符串字面量。
  - 状态与原因码可在一处集中维护并向外部序列化。

### T-P2-PKG-03：步骤参数读取器收敛
- 问题来源：`P2-3 参数解析逻辑重复`。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/usecase/ExecutionRouteDecider.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/DagPlanner.java`
  - 其它存在重复读取/类型判断逻辑的 `StepSpec` 消费类
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/support/StepArgumentReader.java`
- 改造要求：
  - 列表、字符串、布尔、数字读取逻辑统一沉淀到 `StepArgumentReader`。
  - 统一处理空值、去重、大小写、逗号分隔兼容策略，禁止各处重复实现。
  - 解析异常统一返回可观测错误信息，避免静默吞错。
- 验收标准：
  - `resolveStringList` 等重复方法删除或仅保留薄委派。
  - 参数读取逻辑在一个组件内可测试、可复用。

### T-P2-PKG-04：仓储与传输装配边界收敛
- 问题来源：`P2-4 InMemory 实现边界不清`。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/InMemoryDagRuntimeStateRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/InMemoryDagMessageDedupRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/InMemoryDagDeadLetterRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/handoff/InMemoryHandoffRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/InProcessDagMailboxTransport.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/config/MultiAgentStorageConfiguration.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/config/MultiAgentTransportConfiguration.java`
- 改造要求：
  - 使用条件装配或 profile 显式区分 `test/local/prod`。
  - 生产环境默认禁用 InMemory 实现，缺失持久化实现时应 fail-fast。
  - 测试环境默认启用 InMemory，确保测试稳定和可重复。
- 验收标准：
  - 启动日志可明确打印当前生效实现。
  - 生产配置下不会误装配 InMemory 仓储与传输。

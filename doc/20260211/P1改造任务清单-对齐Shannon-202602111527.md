## 2. P1缺口复核结论（结合当前代码）

### 2.1 P1-01 DAG 监督策略抽象缺失（成立）

- 本项目现状证据：
  - `DagActorRuntime` 已有失败收敛，但未形成独立监督策略对象：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:73`
  - 当前失败仅记录到 `failures` 集合并终态返回，缺少“失败阈值 + 策略分支”治理：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:151`
  - `SupervisorPolicy` 已有 `maxFailures/failurePolicy`，但尚未复用于 DAG Actor：`src/main/java/com/example/agent/orchestration/multiagent/supervisor/SupervisorPolicy.java:10`
- Shannon 对照证据：
  - 失败阈值采用 `50%+1` 规则：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:472`
  - 按任务记录重试次数并基于阈值中止流程：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:473`
- 结论：P1 需要把 DAG 运行时的失败处理从“结果聚合”升级为“策略治理”。

### 2.2 P1-02 节点重试与退避机制缺失（成立）

- 本项目现状证据：
  - 节点异常后直接 `tryFail` 并结束，不存在节点级重试：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:256`
  - 运行时仅有批次等待超时，缺少节点级重试退避参数与过程事件：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:139`
- Shannon 对照证据：
  - 失败后递增重试计数并执行重试分支：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:974`
  - 重试超限后按失败策略参与全局终止判定：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:977`
  - 重试日志与流程推进语义明确：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:1004`
- 结论：P1 需要引入节点级“可配置重试 + 指数退避 + 重试可观测”。

### 2.3 P1-03 背压控制与等待治理缺失（成立）

- 本项目现状证据：
  - `DagMailbox` 容量满仅日志告警，未触发治理事件或节流动作：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMailbox.java:42`
  - `DagActorRuntime` 未限制就绪队列深度、激活节点数、待处理消息阈值：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:99`
  - `EventType` 已定义 `WAITING/BACKPRESSURE_APPLIED/CIRCUIT_OPENED`，但 DAG 路径未系统化使用：`src/main/java/com/example/agent/streaming/domain/EventType.java:112`
- Shannon 对照证据：
  - 依赖等待时发布 `WAITING`：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:691`
  - 等待采用选择器 + 指数退避，减少忙轮询：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:720`
  - 依赖等待超时有明确告警上下文：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:741`
  - 主题通知发送失败时采用非阻塞跳过并记录：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:1033`
- 结论：P1 需要引入“队列阈值治理 + 等待退避 + 背压事件”闭环。

## 3. P1实施批次建议

- 批次 `P1-1`：监督策略与配置模型落地（先把治理参数固化）。
- 批次 `P1-2`：节点重试、失败传播与中止策略接入（先保稳定）。
- 批次 `P1-3`：背压与等待治理接入（再保可控）。
- 批次 `P1-4`：测试矩阵与文档收口（最后保可回归）。

## 4. 具体改造任务清单

### 4.1 批次 P1-1：监督策略与配置模型

#### T-P1-SUP-01：新增 DAG 监督策略对象（复杂度 `L2`）

- 目标：将运行时治理参数从代码常量升级为策略对象，便于复用和统一控制。
- 改造点：
  - 新增 `DagSupervisorPolicy`：`maxFailures`、`maxRetriesPerNode`、`failurePropagationPolicy`、`nodeTimeoutMs`
  - 与现有 `FailurePropagationPolicy` 对齐，避免重复定义同义枚举
  - 提供默认安全值与参数边界校验
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagSupervisorPolicy.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 运行时不再依赖硬编码阈值
  - 策略对象可被单测独立验证

#### T-P1-SUP-02：新增 DAG 背压策略对象（复杂度 `L2`）

- 目标：统一管理并发、队列、邮箱容量与等待超时参数。
- 改造点：
  - 新增 `DagBackpressurePolicy`：`maxActiveNodes`、`maxReadyQueueSize`、`mailboxCapacity`、`waitTimeoutMs`、`backoffMinMs`、`backoffMaxMs`
  - 运行时从策略读取并发池大小与阈值
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagBackpressurePolicy.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMailbox.java`
- 验收标准：
  - 队列/邮箱/并发阈值可通过配置调整
  - 阈值越界配置会在启动阶段被规整或拒绝

#### T-P1-SUP-03：补齐配置项与文档（复杂度 `L2`）

- 目标：让治理策略进入可运维配置面。
- 改造点：
  - 在 `application.yml` 增加 `agent.multiagent.dag.supervision` 与 `agent.multiagent.dag.backpressure`
  - 明确默认值、可选范围、风险说明
- 涉及文件：
  - 修改 `src/main/resources/application.yml`
- 验收标准：
  - 配置项可被策略对象读取并生效

### 4.2 批次 P1-2：节点重试与失败传播

#### T-P1-RET-01：实现节点级重试与指数退避（复杂度 `L3`）

- 目标：提升瞬时故障下流程恢复能力，避免一次失败直接终止。
- 改造点：
  - 在 `DagActorRuntime#executeNode` 加入节点重试循环
  - 引入指数退避与上限控制
  - 重试前后记录结构化日志（节点、尝试次数、延时、异常类型）
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 可选新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagRetryBackoff.java`
- 验收标准：
  - 可恢复异常在重试窗口内可转成功
  - 超过重试上限后按策略进入失败传播

#### T-P1-RET-02：实现失败传播策略（复杂度 `L3`）

- 目标：将“单点失败”提升为“全局治理决策”。
- 改造点：
  - `FAIL_FAST`：任一关键节点失败立即终止 DAG
  - `PARTIAL_SUCCESS`：允许失败但在 `maxFailures` 超限后终止
  - 返回结果中增加失败摘要与终止原因
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentCoordinator.java`
- 验收标准：
  - 两种策略行为可由测试明确区分
  - 终止原因在结果与日志中可追溯

#### T-P1-RET-03：补齐重试与失败事件（复杂度 `L2`）

- 目标：让运行过程的“重试/失败传播”可观察。
- 改造点：
  - `MultiAgentEventPublisher` 新增 DAG 重试事件方法
  - 失败传播触发时发布 `TEAM_STATUS` 摘要
  - 失败超限时发布 `WAITING` 或 `STEP_FAILED` 的治理上下文
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
- 验收标准：
  - 重试链路至少产生“重试中 + 最终结果”两类事件

### 4.3 批次 P1-3：背压控制与等待治理

#### T-P1-BP-01：接入就绪队列与激活并发上限（复杂度 `L3`）

- 目标：限制瞬时激活规模，防止并发雪崩。
- 改造点：
  - `readyQueue` 深度上限控制
  - 每批激活节点数限制为 `maxActiveNodes`
  - 超阈值时触发延迟再调度
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 压测场景中队列深度受控，不出现无限增长

#### T-P1-BP-02：接入 mailbox 过载治理（复杂度 `L2`）

- 目标：从“仅日志告警”升级为“可治理动作 + 可观测事件”。
- 改造点：
  - `DagMailbox#offer` 失败时返回结构化拒绝结果
  - 运行时收到拒绝后发布 `BACKPRESSURE_APPLIED`
  - 记录关键上下文（nodeId、capacity、queueSize、messageType）
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMailbox.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
- 验收标准：
  - 邮箱满载场景可稳定触发 `BACKPRESSURE_APPLIED`

#### T-P1-BP-03：接入等待超时与退避事件（复杂度 `L2`）

- 目标：避免“静默等待”，让等待过程可观测可追踪。
- 改造点：
  - 依赖等待阶段按退避周期发布 `WAITING`
  - 超过 `waitTimeoutMs` 后进入失败或继续等待（由策略控制）
  - 发布等待原因、累计等待时长、重试次数
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
- 验收标准：
  - 任一依赖长等待场景均能看到 `WAITING` 事件与最终结论

## 5. P1交付门槛（Definition of Done）

- 治理达标：
  - DAG 运行时具备可配置监督策略、重试退避、失败传播机制
- 稳定达标：
  - 并发高压下不发生队列失控与执行雪崩
- 可观测达标：
  - `WAITING/BACKPRESSURE_APPLIED` 在对应场景可稳定触发
- 质量达标：
  - 分阶段回归与全量回归均通过

## 7. 结论

P1的核心不是“再做并行”，而是把 P0 的并行能力升级为“可治理并行”。  
建议严格按 `P1-1 -> P1-2 -> P1-3 -> P1-4` 顺序推进，优先保证失败与背压场景下的确定性行为与可观测闭环。

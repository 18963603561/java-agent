# P0改造任务清单-对齐Shannon-202602111429

## 1. 输入与范围

- 依据文档：`doc/20260211/DAG-Actor模式可行性评估与优先级方案-202602111414.md`
- 参考源码：`vendor/Shannon`（只读对齐）
- 当前基线：DAG 仍为拓扑排序后的串行遍历，不具备 Actor 运行时能力
- 本清单仅覆盖 `P0`，目标是落地“依赖门控 + 并行骨架 + 最小可观测”

## 2. P0目标定义（必须达成）

P0阶段只解决三个核心问题：

1) 把 `executeDag` 从串行遍历升级为 Actor 运行时驱动并行执行。  
2) 通过 `remainingDeps` 与幂等去重保证依赖消息正确性。  
3) 打通最小事件闭环，支持节点启动、完成、失败与依赖等待可观测。

## 3. 对齐 Shannon 的关键依据

- Mailbox 基础语义（消息接收、非阻塞转发、查询可见）：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:101`
- 依赖等待主流程（先查 workspace，再等待信号/定时器）：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:643`
- 选择器 + 指数退避：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:720`
- 生产者写入 workspace 后通知等待方：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:1028`

对齐原则：

- 不照搬 Temporal 细节，只迁移“消息驱动 + 依赖等待 + 通知唤醒 + 退避重试”的语义。  
- 保持单进程实现，避免在 P0 引入分布式复杂度。  
- 旧串行 DAG 执行主逻辑删除，不保留双轨分支。

## 4. P0实施批次建议

- 批次 `P0-1`：Actor 运行时骨架与消息模型。  
- 批次 `P0-2`：依赖门控、去重与状态机。  
- 批次 `P0-3`：协调器接入、路由收敛、最小事件与测试闭环。

## 5. 具体改造任务清单

### 5.1 批次 P0-1：Actor 运行时骨架

#### T-P0-ARC-01：新增 DAG 消息模型（复杂度 `L1`）

- 目标：统一 Actor 运行时消息契约，消除字符串事件散落。
- 改造点：
  - 新增 `DagMessageType`（`DEPENDENCY_SATISFIED/NODE_START/NODE_COMPLETE/NODE_FAIL`）
  - 新增 `DagMessage`（`workflowId/messageId/fromNode/toNode/topic/payload/timestamp`）
  - 约束消息幂等键：`workflowId:fromNode:toNode:topic:version`
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMessageType.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMessage.java`
- 验收标准：
  - 运行时不再使用裸字符串表示消息类型
  - 消息对象可携带依赖判定所需的最小上下文

#### T-P0-ARC-02：新增节点运行时状态模型（复杂度 `L2`）

- 目标：让每个节点有独立、可原子流转的状态与依赖计数。
- 改造点：
  - 新增 `DagNodeExecutionStatus`（`PENDING/READY/RUNNING/SUCCEEDED/FAILED`）
  - 新增 `DagNodeRuntimeState`，包含 `remainingDeps`、`status`、`processedMessageIds`
  - 提供 CAS 风格状态变更方法，禁止非法跳转
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeExecutionStatus.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeRuntimeState.java`
- 验收标准：
  - 重复消息不会重复扣减 `remainingDeps`
  - 节点不能从 `SUCCEEDED/FAILED` 回退到 `RUNNING`

#### T-P0-ARC-03：新增 Mailbox 与节点 Actor（复杂度 `L2`）

- 目标：建立“单节点串行消费 + 运行时并行调度”的执行基础。
- 改造点：
  - 新增 `DagMailbox`（有界队列，支持入队、出队、容量检查）
  - 新增 `DagNodeActor`（消费 `DagMessage`，驱动状态机和依赖扣减）
  - Mailbox 满载时记录 `warn` 日志并返回拒绝结果
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMailbox.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeActor.java`
- 验收标准：
  - 节点内部消息消费串行
  - 不同节点可并行处理消息与执行

#### T-P0-ARC-04：新增 DAG Actor 总运行时（复杂度 `L3`）

- 目标：把 DAG 执行从“遍历顺序”升级为“就绪队列 + 消息驱动”。
- 改造点：
  - 新增 `DagActorRuntime`，负责初始化节点状态与下游索引
  - 以入度为 0 的节点启动首批执行
  - 节点完成后向下游发送 `DEPENDENCY_SATISFIED`
  - 维护执行汇总结果（节点视图、顺序、失败原因）
- 涉及文件：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 无依赖节点可并行启动
  - 有依赖节点只会在依赖满足后进入 `READY`

### 5.2 批次 P0-2：依赖门控与数据面改造

#### T-P0-DAG-01：扩展 `DagPlan` 运行时元数据（复杂度 `L2`）

- 目标：让执行器直接消费结构化依赖关系，避免运行时重复推导。
- 改造点：
  - 在 `DagPlan` 增加入度映射、下游邻接表、节点依赖快照
  - 保持 `topologicalOrder` 仅用于调试展示，不再作为执行驱动
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/DagPlan.java`
- 验收标准：
  - `DagActorRuntime` 不再手工二次构图
  - DAG 依赖元数据一次构建、全程复用

#### T-P0-DAG-02：增强 `DagPlanner` 依赖校验（复杂度 `L2`）

- 目标：在规划期拒绝非法依赖，减少运行时不确定性。
- 改造点：
  - `dependsOn` 引用不存在节点时直接抛错
  - 自依赖与环依赖继续拦截
  - 输出运行时所需邻接/入度结构
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/DagPlanner.java`
- 验收标准：
  - 非法依赖请求在构图阶段失败，不进入执行阶段

#### T-P0-DATA-01：增强 workspace 快照与读取接口（复杂度 `L2`）

- 目标：为依赖补偿和就绪判定提供数据面支持。
- 改造点：
  - 增加按 workflow 维度读取全部 topic 快照能力
  - 增加按 topic 读取最近条目能力（用于依赖快速判定）
  - 保留现有 `append/hasTopic/list` 语义
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/handoff/WorkspaceSyncService.java`
- 验收标准：
  - 运行时可在启动时执行一次依赖补偿扫描

### 5.3 批次 P0-3：协调器接入、路由收敛与可观测

#### T-P0-INT-01：改造 `executeDag` 接入 Actor 运行时（复杂度 `L3`）

- 目标：删除串行 DAG 逻辑，统一到 Actor 执行路径。
- 改造点：
  - `MultiAgentCoordinator#executeDag` 调整为调用 `DagActorRuntime.run(...)`
  - 删除旧的 `for (String nodeId : dagPlan.getTopologicalOrder())` 串行主逻辑
  - 保持输出字段兼容：`mode/status/dagNodes`
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentCoordinator.java`
- 验收标准：
  - DAG 模式执行不再依赖拓扑遍历循环

#### T-P0-INT-02：调整路由策略使 DAG 承接依赖场景（复杂度 `L2`）

- 目标：让 `dependsOn/consumes/produces` 场景可走新 DAG Actor。
- 改造点：
  - 更新 `MultiAgentRoutingPolicy` 的默认策略
  - 显式 `mode=supervisor` 仍可保留作为手动切换
  - 删除“仅因有依赖就强制 Supervisor”的旧规则
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentRoutingPolicy.java`
- 验收标准：
  - 默认多智能体步骤能命中新 DAG Actor 路径

#### T-P0-OBS-01：补齐 P0 最小事件集（复杂度 `L2`）

- 目标：保障并行执行可观测与问题可诊断。
- 改造点：
  - 在 `MultiAgentEventPublisher` 增加 DAG 节点启动/完成/失败发布方法
  - 依赖等待超时发布 `WAITING`
  - 事件 payload 至少包含 `nodeId/roleId/workflowId/topic`（按场景）
- 涉及文件：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
  - 视实现修改 `src/main/java/com/example/agent/streaming/domain/EventType.java`
- 验收标准：
  - 单次 DAG 执行可完整看到关键生命周期事件

## 7. P0交付门槛（Definition of Done）

- 架构达标：
  - DAG 执行由 `DagActorRuntime` 驱动，串行拓扑遍历执行主逻辑已删除
- 依赖达标：
  - 依赖门控生效，`remainingDeps` 与去重机制稳定
- 并行达标：
  - 同层无依赖节点并行执行，存在依赖节点严格后置
- 可观测达标：
  - 节点启动/完成/失败、依赖等待事件可见
- 质量达标：
  - 分阶段测试与全量回归均通过

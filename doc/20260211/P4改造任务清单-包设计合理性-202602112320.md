## 2. P4改造总目标（必须全部达成）
1) 事件与指标命名从“类内硬编码”升级为“统一字典管理”，降低跨类漂移与统计口径分裂风险。
2) 包级 README 从“说明文档”升级为“可执行规范”，补齐放置规则、依赖不变式、评审检查清单。
3) 建立字典与文档一致性守护测试，确保后续迭代不会回退到硬编码状态。
4) 全程保持行为兼容，不引入历史兼容分支，不改变既有业务路径。

## 3. P4具体改造任务清单

### T-P4-PKG-01：事件与指标字典中心化
- 问题来源：`P4-1 事件与指标字典建议统一元数据定义`。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/event/*`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcher.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/DagRecoveryService.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/runtime/DagNodeExecutionService.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/control/DagControlService.java`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/observability/MultiAgentMetricKeys.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/observability/MultiAgentEventKeys.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/observability/MultiAgentTagKeys.java`
- 改造要求：
  - 统一收敛 `metricName/eventType/tagKey` 常量，禁止在业务类内直接硬编码字符串。
  - 统一 `workflowId/dagRunId/nodeId/tenantId/stepType` 上下文字段命名，避免同义字段并存。
  - 字典命名必须可读、可追踪，禁止缩写导致语义不清。
- 验收标准：
  - multiagent 子域关键类不再出现新增的指标/事件硬编码字面量。
  - 相同语义仅有一个常量定义来源，代码搜索可追踪。

### T-P4-PKG-02：包级文档规范化与检查清单化
- 问题来源：`P4-2 包级设计文档建议补齐`。
- 主要涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/README.md`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/README.md`
  - 新增建议：
    - `src/main/java/com/example/agent/orchestration/multiagent/package-info.java`
    - `src/main/java/com/example/agent/orchestration/multiagent/dag/package-info.java`
    - `doc/20260211/notes/multiagent-包评审检查清单-202602112320.md`
- 改造要求：
  - 将 README 扩展为“规范 + 检查项 + 反例”，而非纯说明文本。
  - `package-info.java` 明确包职责、依赖边界、禁止事项与新增类落位规则。
  - 输出代码评审检查清单（命名、依赖方向、日志字段、测试要求）用于团队执行。
- 验收标准：
  - 新成员可在 10 分钟内基于文档定位类应落位位置。
  - 评审清单可直接用于 MR/PR 检查，不依赖口头约定。

### T-P4-PKG-03：字典与文档一致性守护测试
- 问题来源：P4 目标若无测试守护，后续迭代易回退。

  - `src/test/java/com/example/agent/orchestration/multiagent/architecture/MultiAgentReadmeGuardTest.java`
- 改造要求：
  - 增加“硬编码扫描守护”：关键类禁止直接出现新增指标/事件字面量。
  - 增加“文档一致性守护”：README 中声明的核心分层目录在代码中必须存在。
  - 守护测试必须纳入默认测试集，不能成为手工可选检查。
- 验收标准：
  - 违反字典规则或文档规则时测试稳定失败并给出可定位信息。
  - 当前结构下守护测试稳定通过。

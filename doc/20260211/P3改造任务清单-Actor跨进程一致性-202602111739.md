# P3改造任务清单-Actor跨进程一致性-202602111739

## 1. 输入与范围

- 依据文档：`doc/20260211/DAG-Actor模式可行性评估与优先级方案-202602111414.md`

## 2. P3缺口复核结论（结合当前代码）

### 2.1 P3-01 跨进程消息投递通道缺失（成立）

- 本项目现状证据：
  - 运行时明确标注“单进程运行时，不负责跨进程消息一致性”：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:42`
  - DAG 调度依赖进程内 `readyQueue + 线程池`：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:134`
  - 节点邮箱为本地 `ArrayBlockingQueue`：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMailbox.java:22`
- Shannon 对照证据：
  - 支持跨工作流信号投递：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:38`
  - `mailbox_v1` 信号通道接入与消费：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:102`
- 结论：缺少“外置消息通道 + 进程间投递协议”，`P3-01` 成立。

### 2.2 P3-02 分片路由与节点归属机制缺失（成立）

- 本项目现状证据：
  - 节点运行实例由当前进程 `actorMap` 直接持有：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:130`
  - 下游投递以“本地对象调用”完成：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:445`
- Shannon 对照证据：
  - 消息投递目标通过 `targetWorkflowID` 决定，具备天然路由语义：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:37`
- 推断结论：需要把“节点归属”从本地对象映射升级为“可计算路由 + 远程寻址”，`P3-02` 成立。

### 2.3 P3-03 跨实例幂等与状态一致性未持久化（成立）

- 本项目现状证据：
  - 消息去重集合仅存于内存：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeRuntimeState.java:20`
  - 依赖计数状态在本地原子变量维护：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeRuntimeState.java:18`
  - 工作区 topic 当前为进程内 `ConcurrentHashMap`：`src/main/java/com/example/agent/orchestration/multiagent/handoff/WorkspaceSyncService.java:25`
- Shannon 对照证据：
  - 查询处理器暴露可观测状态，支撑一致性核验：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:127`
  - 版本门控确保变更确定性：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:101`
- 结论：缺少“去重键全局持久化 + 状态快照版本控制”，`P3-03` 成立。

### 2.4 P3-04 跨实例恢复与补偿重驱链路缺失（成立）

- 本项目现状证据：
  - 当前运行态不具备“节点租约丢失/实例重启”后的自动接管机制。
  - 依赖推进仍以本地流程为主，缺少“运行中补偿扫描 + 重驱投递”标准流程。
- Shannon 对照证据：
  - 依赖等待采用 `selector + timer + backoff`，具备可恢复等待语义：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:720`
  - 依赖等待超时具备显式告警上下文：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:741`
  - topic 通知为非阻塞发送，避免阻塞导致系统性卡死：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:1028`
- 结论：缺少“宕机恢复 + 补偿重驱 + 死信治理”三件套，`P3-04` 成立。

### 2.5 P3-05 分布式控制面与运维面不足（成立）

- 本项目现状证据：
  - P2 已具备回放与诊断，但没有“分片状态、租约状态、mailbox堆积”的运维查询面。
  - 缺少 pause/resume/rebalance 等运行时控制指令。
- Shannon 对照证据：
  - `getMailbox/listTeamAgents/findTeamAgentsByRole` 提供控制面查询能力：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:127`
- 结论：缺少“分布式 Actor 运行控制面”，`P3-05` 成立。

## 4. 具体改造任务清单

### 4.1 批次 P3-1：外置消息通道与分片路由

#### T-P3-INF-01：抽象跨进程消息通道 SPI（复杂度 `L3`）

- 目标：把节点间投递从“本地对象调用”升级为“可外置传输层”。
- 改造点：
  - 新增 `DagMailboxTransport` 接口（`send/poll/ack/nack`）
  - 新增 `DagMessageEnvelope`（含 `dagRunId/messageId/shardKey/attempt/deadline`）
  - 提供 `InProcessDagMailboxTransport` 与 `RedisDagMailboxTransport`（或 `JdbcDagMailboxTransport`）双实现
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxTransport.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMessageEnvelope.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/InProcessDagMailboxTransport.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/RedisDagMailboxTransport.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 同一 DAG 可在两实例部署下完成跨实例依赖投递。

#### T-P3-INF-02：新增节点分片与归属路由器（复杂度 `L3`）

- 目标：明确“某节点由哪个实例负责执行”。
- 改造点：
  - 新增 `DagShardRouter`（一致性哈希或 Rendezvous Hash）
  - 引入 `nodeOwner` 计算规则（`tenantId/workflowId/nodeId`）
  - 在 `DagActorRuntime` 投递时按 `nodeOwner` 路由到目标 shard mailbox
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagShardRouter.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagShardAssignment.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 相同输入在稳定节点成员集下路由结果确定。

#### T-P3-INF-03：新增分布式消息分发器（复杂度 `L2`）

- 目标：实现“拉取 -> 执行 -> ack”标准消费环。
- 改造点：
  - 新增 `DagMailboxDispatcher` 周期轮询所属 shard
  - 消费后调用本地 `DagNodeActor`，成功 `ack`，失败 `nack` 并退避
  - 指标上报（lag、inflight、ack latency）
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcher.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeActor.java`
- 验收标准：
  - 单实例下行为与当前 P2 结果一致；双实例下不丢消息。

### 4.2 批次 P3-2：一致性与幂等持久化

#### T-P3-CON-01：运行态快照持久化与版本控制（复杂度 `L3`）

- 目标：实例重启后可恢复 `remainingDeps/status/attempt`。
- 改造点：
  - 新增 `DagRuntimeStateRepository`（memory + jdbc）
  - 新增 `DagNodeRuntimeSnapshot`（含 `version` 乐观锁）
  - 在关键状态迁移点写入快照（READY/RUNNING/SUCCEEDED/FAILED）
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/DagRuntimeStateRepository.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/DagNodeRuntimeSnapshot.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeRuntimeState.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 进程重启后可从最新快照恢复并继续推进。

#### T-P3-CON-02：全局消息去重仓储（复杂度 `L2`）

- 目标：跨实例场景下重复投递不重复生效。
- 改造点：
  - 新增 `DagMessageDedupRepository`（按 `messageId` 记录消费状态）
  - 去重键落盘并支持 TTL
  - `DagNodeActor#processMessage` 改为“先查去重仓储再执行”
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/DagMessageDedupRepository.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeActor.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagMessage.java`
- 验收标准：
  - 压测下重复消息不重复扣减依赖，不重复执行节点。

#### T-P3-CON-03：节点执行租约与抢占保护（复杂度 `L3`）

- 目标：确保同一节点同一时刻仅一个实例执行。
- 改造点：
  - 新增 `DagNodeLeaseService`（获取、续租、释放）
  - 执行前强制加租约，失租立即中止并回收消息
  - 围绕 `dagRunId + nodeId` 形成全局互斥语义
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/DagNodeLeaseService.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 双实例并发消费同一节点时，最多一个成功进入 RUNNING。

### 4.3 批次 P3-3：恢复补偿与死信治理

#### T-P3-REC-01：启动恢复与补偿扫描（复杂度 `L3`）

- 目标：实例启动后自动修复“状态与事实不一致”。
- 改造点：
  - 新增 `DagRecoveryService`，扫描未终态 `dagRunId`
  - 对照 `WorkspaceSyncService.snapshot` 进行依赖补偿重驱
  - 对超时停滞节点触发重投递或失败收敛
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/DagRecoveryService.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/handoff/WorkspaceSyncService.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 杀进程重启后，运行中 DAG 能恢复推进或正确失败。

#### T-P3-REC-02：消息重试队列与死信队列（复杂度 `L2`）

- 目标：不可达消息可追踪、可补偿、可人工干预。
- 改造点：
  - 新增 `DagDeadLetterMessage` 与 `DagDeadLetterRepository`
  - `nack` 超限进入 DLQ，并记录原因码、重试次数、首末失败时间
  - 新增 DLQ 重放入口（按 `dagRunId/nodeId/messageId`）
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/DagDeadLetterMessage.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/DagDeadLetterRepository.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcher.java`
- 验收标准：
  - 任意超限失败消息可在 DLQ 中定位并执行重放。

#### T-P3-REC-03：等待退避策略分布式化（复杂度 `L2`）

- 目标：跨实例等待不忙轮询、不雪崩。
- 改造点：
  - 在分布式投递失败场景引入指数退避 + 上限
  - 首次等待发布 `WAITING`，超时发布标准失败原因码
  - 对齐 P2 审计字段，记录 `attempt/waitedMs/reasonCode`
- 涉及文件（建议）：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcher.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/DagAuditService.java`
- 验收标准：
  - 分布式等待路径的事件与审计字段完整可追。

## 5. P3交付门槛（Definition of Done）

- 架构达标：
  - DAG Actor 支持跨实例消息投递与分片路由。
- 一致性达标：
  - 去重键全局生效；同节点同时间仅一实例执行。
- 韧性达标：
  - 宕机恢复、补偿重驱、DLQ 重放形成闭环。
- 运维达标：
  - 具备分布式查询、控制与告警能力。
- 质量达标：
  - 分阶段测试、全量回归、灰度验证全部通过。

## 7. 结论

P3 的本质不是“再加并发”，而是把现有单进程 Actor 升级为“跨实例可控、可恢复、可运维”的分布式执行系统。  
建议严格按 `P3-1 -> P3-2 -> P3-3 -> P3-4 -> P3-5` 推进，先打通通信，再确保一致性，最后完成恢复与运维闭环。

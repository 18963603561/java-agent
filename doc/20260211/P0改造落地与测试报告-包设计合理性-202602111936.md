## 2. 分阶段落地结果

### Stage A：依赖消息单路径收敛（T-P0-PKG-01）
- `DagActorRuntime` 删除依赖消息“本地直投 + 等待重试”路径，仅保留 `dispatcher.send -> dispatcher.dispatchDagRun`。
- 删除 `waitAndDeliverDependency(...)` 整段遗留逻辑。
- `saveDependencyAuditRecord(...)` 改为显式参数签名，统一落盘 `QUEUED` 审计口径。
- 新增 `DagMessageSinglePathTest`，断言依赖事件仅出现 `QUEUED` 投递状态，避免双路径回归。

### Stage B：分片路由真实化（T-P0-PKG-02）
- `DagActorRuntime` 路由入参从单实例改为 `dagDistributedProperties.resolveActiveInstancesOrThrow(...)`。
- `DagControlService` 查询路由与实例列表改为统一走 `resolveActiveInstancesOrThrow(...)`。
- `DagDistributedProperties` 新增：
  - 启动校验（`@PostConstruct`）：`activeInstances` 非空、`instanceId` 非空。
  - 运行校验：`resolveActiveInstancesOrThrow(scene)`，含归一化与日志。
- `DagShardRouter` 改为实例集为空时 fail-fast（抛异常），删除“回落 instance-local”隐式语义。
- `DagShardRouterTest` 同步更新为 fail-fast 断言。

### Stage C：Redis 传输去占位（T-P0-PKG-03）
- 重写 `RedisDagMailboxTransport`，不再委托 `InProcessDagMailboxTransport`。
- 完整实现 `send/poll/ack/nack/listPendingByDagRun`：
  - `send`：写 envelope 主体 + ready zset + dag index set。
  - `poll`：ready -> inflight 迁移，设置 `ackDeadline`。
  - `ack`：删除 ready/inflight/index/data。
  - `nack`：按 backoff 回推 ready，并递增 attempt；超限直接清理（由上层写 DLQ）。
  - `listPendingByDagRun`：按 dag index 扫描并清理失效索引。
- 新增 `RedisDagMailboxTransportTest`，覆盖 send/poll/ack、nack 回退、超限清理、pending 查询。

### Stage D：生产/测试装配隔离（T-P0-PKG-04）
- `InProcessDagMailboxTransport` 增加条件装配：
  - `agent.dag.distributed.transport=inprocess`（默认）时启用。
- `RedisDagMailboxTransport` 增加条件装配：
  - `agent.dag.distributed.transport=redis` 时启用。
- InMemory 实现增加条件装配：
  - `agent.multiagent.storage.mode=inmemory`（默认）时启用。
  - 涉及：`InMemoryDagAuditRepository`、`InMemoryDagRuntimeStateRepository`、`InMemoryDagMessageDedupRepository`、`InMemoryDagDeadLetterRepository`、`InMemoryHandoffRepository`。
- 新增 `MultiAgentStorageConfiguration`：
  - `prod + agent.multiagent.storage.mode=persistent` 下，启动期强校验关键 Bean 不得为 InMemory（含 `DagMailboxTransport`）。
- `application.yml` 增加默认配置：
  - `agent.dag.distributed.transport: inprocess`
  - `agent.multiagent.storage.mode: inmemory`

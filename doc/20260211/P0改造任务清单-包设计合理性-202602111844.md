# P0改造任务清单-包设计合理性-202602111844

## 1. 输入与范围
- 依据文档：`doc/20260211/multiagent包设计评审-P0P4分级-202602111841.md`
- 评审范围：`src/main/java/com/example/agent/orchestration/multiagent`
- 本清单目标：仅落地 `P0` 级问题，先消除跨进程 Actor 的语义分裂与生产风险。

## 2. P0改造总目标（必须全部达成）
1) DAG 依赖消息只保留一条真实投递链路（Transport -> Dispatcher -> Actor）。
2) 分片路由必须基于真实实例集合，而不是单实例回环。
3) Redis 传输从“占位委托”升级为可工作的跨进程实现。
4) 生产与测试装配隔离，避免 InMemory 实现误入生产。
5) 每个阶段完成后执行完整流程测试，最终全量回归通过。

## 3. P0具体改造任务清单

### T-P0-PKG-01：依赖消息单路径收敛（最高优先级）
- 问题来源：当前 `DagActorRuntime` 同时调用 `dagMailboxDispatcher.send(...)` 与 `downstreamActor.deliver(...)`，形成双路径。
- 涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcher.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagNodeActor.java`
- 改造要求：
  - 删除 `DagActorRuntime` 中依赖消息直接 `deliver` 的分支与等待重试分支（含 `waitAndDeliverDependency` 直投逻辑）。
  - 下游依赖推进统一通过 `buildEnvelope -> dispatcher.send -> dispatcher.dispatchDagRun`。
  - 审计记录统一在分发结果处落盘，不允许同一消息双重审计口径。
- 验收标准：
  - 代码中不再出现 `downstreamActor.deliver(dependencyMessage)` 依赖推进调用。
  - 依赖消息在单次执行中仅出现一次有效消费（以消息 ID 去重验证）。

### T-P0-PKG-02：分片路由真实化
- 问题来源：路由计算使用 `List.of(dagDistributedProperties.getInstanceId())`，分片失效。
- 涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagShardRouter.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagDistributedProperties.java`
  - `src/main/resources/application.yml`
- 改造要求：
  - 路由入参统一改为 `dagDistributedProperties.getActiveInstances()`。
  - 若 `activeInstances` 为空，明确 fail-fast 或降级策略（必须统一，不可隐式回环）。
  - 增加 `activeInstances` 配置合法性校验日志（启动时与运行时）。
- 验收标准：
  - 多实例配置下同一 `(tenant, workflow, node)` 路由结果稳定且可预测。
  - 路由结果可通过运维接口查询并与运行实例一致。

### T-P0-PKG-03：RedisDagMailboxTransport 实现去占位
- 问题来源：`RedisDagMailboxTransport` 当前仅委托 `InProcessDagMailboxTransport`。
- 涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/RedisDagMailboxTransport.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxTransport.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcher.java`
  - `src/main/resources/application.yml`
- 改造要求：
  - 使用项目现有 Redis 依赖落地 `send/poll/ack/nack/listPendingByDagRun` 全链路。
  - 明确消息存储结构（建议：待消费队列 + in-flight 索引 + 可见时间 + 尝试次数）。
  - `nack` 必须落地退避时间语义；`ack` 必须真正删除投递记录；超限进入 DLQ。
  - 保证接口语义与 InProcess 版本一致，便于切换。
- 验收标准：
  - 重启进程后未 ack 消息仍可被恢复消费。
  - 具备跨进程消费能力，不依赖 JVM 本地内存。

### T-P0-PKG-04：装配策略收敛（生产/测试隔离）
- 问题来源：多个 InMemory 仓储/传输以常规 Bean 方式装配，生产风险高。
- 涉及文件：
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/InProcessDagMailboxTransport.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/InMemoryDagRuntimeStateRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/state/InMemoryDagMessageDedupRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/InMemoryDagDeadLetterRepository.java`
  - `src/main/java/com/example/agent/orchestration/multiagent/handoff/InMemoryHandoffRepository.java`
  - 新增建议：`src/main/java/com/example/agent/orchestration/multiagent/config/MultiAgentStorageConfiguration.java`
- 改造要求：
  - 明确 `test/local/prod` 三类 profile 或条件装配。
  - 生产默认禁用 InMemory 实现；测试默认启用 InMemory 实现。
  - 去掉依赖 `@Primary` 临时兜底的装配方式，改为显式条件选择。
- 验收标准：
  - 在 `prod` 配置下应用启动不应绑定 InMemory 传输与仓储实现。
  - 在 `test` 配置下现有单测可继续运行。

### T-P0-PKG-05：一致性与回归测试闭环
- 涉及测试文件（新增/改造）：
  - `src/test/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMailboxDispatcherTest.java`
  - `src/test/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagShardRouterTest.java`
  - `src/test/java/com/example/agent/orchestration/multiagent/dag/actor/recovery/DagRecoveryServiceTest.java`
  - 新增建议：`src/test/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/RedisDagMailboxTransportTest.java`
  - 新增建议：`src/test/java/com/example/agent/orchestration/multiagent/dag/actor/distributed/DagMessageSinglePathTest.java`
- 改造要求：
  - 增加“单消息单消费”断言，防止双路径回归。
  - 增加 Redis 断言：`ack` 删除、`nack` 延迟重投、超限 DLQ。
  - 增加分片一致性断言：同 key 稳定映射。
- 验收标准：
  - 所有 P0 测试通过后，再执行全量 `mvn test` 通过。

## 5. P0完成定义（DoD）
- 运行链路：依赖消息仅有单路径，代码中无直投残留。
- 一致性：分片路由与实例配置一致；重复消息不会重复执行。
- 可靠性：Redis 传输可跨进程、可恢复、可 ack/nack。
- 装配：生产与测试实现边界清晰，配置行为可预期。
- 质量：阶段测试与全量测试全部通过。

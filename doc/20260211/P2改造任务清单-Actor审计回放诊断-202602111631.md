# P2改造任务清单-Actor审计回放诊断-202602111631

## 1. 输入与范围

- 依据文档：`doc/20260211/DAG-Actor模式可行性评估与优先级方案-202602111414.md`
- 参考源码：`vendor/Shannon`（只读对齐）
- 当前基线：`P0/P1` 已落地，DAG Actor 已具备依赖门控、重试与背压基础能力。
- 本清单仅覆盖该评估文档定义的 `P2`：审计、回放、诊断能力。

## 2. P2缺口复核结论（Actor 专项）

### 2.1 P2-01 运行态审计模型缺失（成立）

- 本项目现状证据：
  - DAG 结果输出仍以摘要为主，仅包含 `status/dagOrder/dagNodes/failures`：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:764`
  - 协调器仅透传上述摘要，未沉淀“节点尝试级”审计记录：`src/main/java/com/example/agent/orchestration/multiagent/MultiAgentCoordinator.java:205`
  - 当前节点视图仅含最终状态与剩余依赖，缺少尝试次数、等待段、背压段、关键耗时：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:742`
- Shannon 对照证据：
  - Mailbox 消息维护并暴露查询处理器：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:88`
  - Agent 执行记录持久化（含输入输出、耗时、模型）：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:887`
  - Agent 性能记录（成功率、耗时、Token）持续沉淀：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:958`
- 结论：当前系统“可执行、可看流”，但“不可审计复盘”，`P2-01` 成立。

### 2.2 P2-02 DAG语义回放链路不完整（成立）

- 本项目现状证据：
  - 事件流已支持游标续传与重放（`lastEventId`），但为通用流语义：`src/main/java/com/example/agent/streaming/sse/EventStreamService.java:72`
  - 当前公开接口仅提供 SSE 订阅入口，未提供 DAG 专项回放查询：`src/main/java/com/example/agent/streaming/sse/SseStreamController.java:84`
  - 当前流请求模型仅有 `workflowId/types/lastEventId`，缺少 `dagRunId/nodeId/attempt` 过滤维度：`src/main/java/com/example/agent/streaming/sse/TaskStreamRequest.java:10`
  - DAG 事件虽已发布等待/背压等信息，但缺少统一的“回放锚点字段”（如 `dagRunId/messageId/attemptId`）用于强语义重建。
- Shannon 对照证据：
  - 依赖等待事件、退避与超时上下文清晰：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:677`
  - 依赖满足事件有明确输出语义：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:748`
  - 主题通知采用非阻塞发送并记录行为，可用于解释回放分叉：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:1028`
- 结论：当前“流可看”，但“DAG 运行重建不可控”，`P2-02` 成立。

### 2.3 P2-03 诊断闭环与根因归并不足（成立）

- 本项目现状证据：
  - 失败信息以字符串列表为主，缺少结构化原因码与归类：`src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java:769`
  - 团队状态事件有状态摘要，但缺少可计算诊断维度（关键路径、阻塞热点、重试热点）。
  - 缺少 DAG 级“诊断报告对象/服务/接口”。
- Shannon 对照证据：
  - 依赖等待超时会记录 `topic/wait_time/attempts` 等关键上下文：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:741`
  - 失败重试有 `retry_count` 与失败阈值收敛逻辑：`vendor/Shannon/go/orchestrator/internal/workflows/supervisor_workflow.go:974`
- 结论：当前具备“异常可见”，但不具备“根因可归并、可建议”，`P2-03` 成立。

## 3. P2实施批次建议

- 批次 `P2-1`：先补审计数据底座（记录先行）。
- 批次 `P2-2`：再补回放能力（重建先行）。
- 批次 `P2-3`：最后补诊断服务（解释先行）。
- 批次 `P2-4`：测试矩阵与规格收口。

## 4. 具体改造任务清单

### 4.1 批次 P2-1：审计数据底座

#### T-P2-AUD-01：新增 DAG 运行审计实体（复杂度 `L3`）

- 目标：从“结果摘要”升级为“运行轨迹审计”。
- 改造点：
  - 新增 `DagRunAuditRecord`（`dagRunId/workflowId/startAt/endAt/status/failurePolicy`）
  - 新增 `DagNodeAttemptRecord`（`nodeId/attempt/startAt/endAt/outcome/reasonCode`）
  - 新增 `DagDependencyEventRecord`（`fromNode/toNode/messageId/topic/deliverResult`）
  - 新增 `DagBackpressureRecord`（`nodeId/queueSize/capacity/delayMs/reason`）
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/DagRunAuditRecord.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/DagNodeAttemptRecord.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/DagDependencyEventRecord.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/DagBackpressureRecord.java`
- 验收标准：
  - 任一 DAG 运行均可输出完整运行轨迹骨架。

#### T-P2-AUD-02：新增审计仓储 SPI 与默认实现（复杂度 `L2`）

- 目标：支持后续切换到外部存储，同时保持当前项目可快速落地。
- 改造点：
  - 新增 `DagAuditRepository` 接口（`saveRun/saveAttempt/appendEvent/queryByRunId`）
  - 新增 `InMemoryDagAuditRepository` 默认实现
  - 预留 Redis/JDBC 扩展点，不在本批次强制落地
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/DagAuditRepository.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/audit/InMemoryDagAuditRepository.java`
- 验收标准：
  - 运行后可按 `dagRunId` 查询完整审计对象。

#### T-P2-AUD-03：运行时接入审计写入（复杂度 `L3`）

- 目标：把节点生命周期、依赖投递、重试退避、等待超时统一落盘。
- 改造点：
  - `DagActorRuntime` 在开始、尝试、完成、失败、等待、背压分支写审计记录
  - 为每次运行生成稳定 `dagRunId`
  - `DagActorRuntimeResult` 增加 `dagRunId/auditSummary` 引用
- 涉及文件（建议）：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentCoordinator.java`
- 验收标准：
  - 回传结果可定位到审计主键，审计可与事件流双向关联。

### 4.2 批次 P2-2：DAG语义回放

#### T-P2-REP-01：统一 DAG 事件锚点字段（复杂度 `L3`）

- 目标：让事件具备“可重建 DAG 状态机”的最小必要信息。
- 改造点：
  - 为 DAG 事件统一增加：`dagRunId/nodeId/attempt/messageId/messageType/fromNode/toNode/topic`
  - 等待/背压事件补充：`waitedMs/queueSize/capacity/activeNodes`
  - 保持向后兼容：新增字段不破坏现有消费方
- 涉及文件（建议）：
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 可仅依赖事件流重建主要状态迁移轨迹。

#### T-P2-REP-02：新增 DAG 回放服务（复杂度 `L3`）

- 目标：提供可编程回放而非仅 SSE 消费。
- 改造点：
  - 新增 `DagReplayService`，输入 `workflowId + dagRunId + 游标/时间窗`
  - 合并 `EventStreamService` 与 `DagAuditRepository` 输出，生成时间线
  - 输出回放对象：`DagReplayFrame`（状态快照、事件、差异）
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/replay/DagReplayService.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/replay/DagReplayFrame.java`
  - 修改 `src/main/java/com/example/agent/streaming/sse/EventStreamService.java`（提供按条件拉取辅助接口）
- 验收标准：
  - 可按游标分段重放并得到一致状态序列。

#### T-P2-REP-03：新增 DAG 回放查询接口（复杂度 `L2`）

- 目标：让运维与开发可直接查询某次运行链路。
- 改造点：
  - 新增 `GET /api/v1/workflows/{workflowId}/dag/replay`
  - 支持参数：`dagRunId/fromSeq/toSeq/nodeId/attempt`
  - 统一租户隔离校验与鉴权上下文
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/gateway/controller/DagReplayController.java`
  - 新增请求响应 DTO
- 验收标准：
  - 同一 `dagRunId` 可稳定复现关键状态演进。

### 4.3 批次 P2-3：诊断闭环

#### T-P2-DIA-01：新增失败与阻塞原因码体系（复杂度 `L2`）

- 目标：把字符串错误升级为可统计、可聚合的原因码。
- 改造点：
  - 新增 `DagFailureReasonCode`、`DagBlockingReasonCode`
  - 将 `dependency_wait_timeout/mailbox_overloaded/retry_exhausted` 标准化
  - 事件与审计双写原因码
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/diagnosis/DagFailureReasonCode.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/diagnosis/DagBlockingReasonCode.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/dag/actor/DagActorRuntime.java`
- 验收标准：
  - 失败路径 100% 带标准原因码。

#### T-P2-DIA-02：新增 DAG 诊断服务（复杂度 `L3`）

- 目标：自动输出“为什么慢、为什么卡、为什么失败”。
- 改造点：
  - 新增 `DagDiagnosisService`
  - 计算指标：关键路径、最长等待节点、重试热点、背压热点、失败根因分布
  - 输出 `DagDiagnosisReport`
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/diagnosis/DagDiagnosisService.java`
  - 新增 `src/main/java/com/example/agent/orchestration/multiagent/dag/diagnosis/DagDiagnosisReport.java`
- 验收标准：
  - 单次失败运行可自动生成结构化诊断结论与建议动作。

#### T-P2-DIA-03：新增诊断接口与事件（复杂度 `L2`）

- 目标：把诊断结果纳入标准交付面。
- 改造点：
  - 新增 `GET /api/v1/workflows/{workflowId}/dag/diagnosis`
  - 诊断完成发布 `TEAM_STATUS` 子状态（如 `DAG_DIAGNOSED`）
  - 重要异常发布诊断摘要事件
- 涉及文件（建议）：
  - 新增 `src/main/java/com/example/agent/gateway/controller/DagDiagnosisController.java`
  - 修改 `src/main/java/com/example/agent/orchestration/multiagent/MultiAgentEventPublisher.java`
- 验收标准：
  - 可通过接口与事件双通道获取诊断结果。

## 5. P2交付门槛（Definition of Done）

- 审计达标：
  - 每次 DAG 运行都有可查询审计主记录、节点尝试记录、依赖投递记录。
- 回放达标：
  - 支持按 `dagRunId + 游标` 回放，状态重建一致。
- 诊断达标：
  - 失败与阻塞具备结构化原因码；可输出自动诊断报告。
- 质量达标：
  - 分阶段测试 + 全量回归通过。

## 7. 结论

该 P2 不是“再提升并行度”，而是把已落地的 Actor 执行能力升级为“可审计、可回放、可诊断”的生产可运维能力。  
建议严格按 `P2-1 -> P2-2 -> P2-3 -> P2-4` 推进，先保证数据可追，再保证状态可复，再保证根因可解释。

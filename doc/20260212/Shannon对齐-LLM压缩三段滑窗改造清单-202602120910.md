# Shannon 对齐改造清单（LLM 压缩 + 三段式滑窗）

## 1. 目标与边界

- 目标：在当前工程中引入“Shannon 风格”的 **LLM 压缩 + 三段式滑窗（Primers + Summary + Recents）**，并保持现有预算、背压、审计能力可用。
- 边界：本清单是改造计划，不含代码落地；按可灰度、可回滚、可观测原则拆分。

## 2. 当前差异（作为改造依据）

1) 当前压缩主链路为规则/模板式，不是 LLM 生成式：
- `src/main/java/com/example/agent/budget/trim/application/DefaultCompressionExecutionService.java`
- `src/main/java/com/example/agent/capabilities/memory/store/CompressedMemoryStore.java`

2) 当前缺少 Shannon 同名三段滑窗参数与实现：
- 未见 `primers_count`、`recents_count`、`compression_trigger_ratio`、`compression_target_ratio`、`shapeHistory`

3) Shannon 参考实现关键点：
- LLM 压缩活动：`vendor/Shannon/go/orchestrator/internal/activities/context_compress.go`
- 三段式滑窗：`vendor/Shannon/go/orchestrator/internal/workflows/helpers.go`
- 比例阈值触发：`vendor/Shannon/go/orchestrator/internal/workflows/simple_workflow.go`

## 3. P0-P4 改造任务清单

## P0（必须优先）——能力骨架与开关治理

### P0-1 引入压缩模式开关与参数骨架

- 目标：先建立可切换架构（`rule`/`llm`/`hybrid`），避免一次性替换风险。
- 关键任务：
  - 新增压缩模式配置与参数校验（触发比例、目标比例、primers、recents、超时、降级策略）。
  - 保留现有规则压缩路径作为兜底。
- 涉及修改文件：
  - `src/main/java/com/example/agent/budget/trim/config/ContextCompressionProperties.java`（扩展字段）
  - `src/main/resources/application.yml`（新增配置）
  - `src/main/resources/application.yml.example`（新增配置示例）

### P0-2 建立压缩执行抽象（策略路由）

- 目标：把“如何压缩”从 `ContextCompressionService` 中解耦。
- 关键任务：
  - 扩展执行结果结构，支持记录压缩来源（rule/llm）、原始 token、压缩 token、失败原因。
  - 在服务层实现模式路由：`rule -> llm -> fallback`。
- 涉及修改文件：
  - `src/main/java/com/example/agent/budget/trim/application/ContextCompressionService.java`
  - `src/main/java/com/example/agent/budget/trim/application/CompressionExecutionService.java`
  - `src/main/java/com/example/agent/budget/trim/model/CompressionExecutionResult.java`
  - `src/main/java/com/example/agent/budget/trim/application/DefaultCompressionExecutionService.java`

### P0-3 为 LLM 压缩预留模型场景

- 目标：压缩流量走独立模型路由，避免挤占主流程模型额度。
- 关键任务：
  - 新增 `ModelScene.CONTEXT_COMPRESS`。
  - 在模型路由配置中增加 `context_compress` 场景可配置项。
- 涉及修改文件：
  - `src/main/java/com/example/agent/capabilities/llm/contract/ModelScene.java`
  - `src/main/java/com/example/agent/capabilities/llm/config/ModelConfigProperties.java`（必要时补说明）
  - `src/main/resources/application.yml`（`agent.model.routes`）

### P0 验收口径

- 可通过配置切换压缩模式，不影响现有 rule 路径稳定性。
- `ContextCompressionService` 产生统一结果对象，能区分执行来源与失败原因。

## P1（高优先）——接入 LLM 压缩主能力

### P1-1 新增 LLM 压缩执行器

- 目标：用 `ModelInvocationService` 生成中段摘要，替代纯规则拼接。
- 关键任务：
  - 新增 LLM 压缩执行器，构建压缩提示词，调用模型并输出摘要。
  - 支持超时、空摘要、模型异常的可控降级。
- 涉及新增文件：
  - `src/main/java/com/example/agent/budget/trim/application/LlmCompressionExecutionService.java`
  - `src/main/java/com/example/agent/budget/trim/model/LlmCompressionRequest.java`
  - `src/main/java/com/example/agent/budget/trim/model/LlmCompressionResponse.java`
  - `src/main/java/com/example/agent/budget/trim/prompt/ContextCompressionPromptBuilder.java`
- 涉及修改文件：
  - `src/main/java/com/example/agent/budget/trim/application/ContextCompressionService.java`
  - `src/main/java/com/example/agent/budget/trim/application/DefaultCompressionExecutionService.java`（明确 rule fallback 语义）
  - `src/main/java/com/example/agent/capabilities/llm/client/ModelInvocationService.java`（补压缩 phase 元数据透传）

### P1-2 压缩摘要写回与安全治理

- 目标：摘要落库可追踪、可脱敏、可审计。
- 关键任务：
  - 压缩摘要写回继续复用 `CompressionSummaryApplier`。
  - 引入脱敏处理（可复用 redaction 服务）与最大长度保护。
- 涉及修改文件：
  - `src/main/java/com/example/agent/budget/trim/application/DefaultCompressionSummaryApplier.java`
  - `src/main/java/com/example/agent/capabilities/memory/store/CompressedMemoryStore.java`
  - `src/main/java/com/example/agent/capabilities/memory/write/MemoryWriteRedactionProcessor.java`（复用或封装调用）

### P1 验收口径

- 在 `llm` 模式下，压缩摘要来自模型输出；在模型失败时可降级到 rule。
- 摘要具备长度控制与脱敏策略，不引入明文敏感信息回流。

## P2（中高优先）——三段式滑窗（Primers + Summary + Recents）

### P2-1 新增滑窗整形器

- 目标：对齐 Shannon 的历史整形语义。
- 关键任务：
  - 新增 `shapeHistory` 等价实现：保留首段 `primers` + 中段 `summary` + 末段 `recents`。
  - 边界处理：`primers + recents >= total` 时回退原历史。
- 涉及新增文件：
  - `src/main/java/com/example/agent/budget/trim/application/SlidingWindowHistoryShaper.java`
  - `src/main/java/com/example/agent/budget/trim/model/SlidingWindowShapeResult.java`

### P2-2 引入比例阈值触发逻辑

- 目标：增加与 Shannon 接近的触发判定（`trigger_ratio` / `target_ratio`）。
- 关键任务：
  - 在触发策略中增加比例判定维度，与现有预算超限判定并存。
  - 输出触发原因标签，支持观测区分。
- 涉及修改文件：
  - `src/main/java/com/example/agent/budget/trim/application/DefaultCompressionTriggerPolicy.java`
  - `src/main/java/com/example/agent/budget/trim/application/CompressionTriggerPolicy.java`
  - `src/main/java/com/example/agent/budget/trim/config/ContextCompressionProperties.java`

### P2-3 将 summary 注入最终上下文装配

- 目标：让压缩摘要进入最终提示词链路。
- 关键任务：
  - 在装配层增加 `context_summary` 注入策略（带开关）。
  - 记录“是否注入摘要/是否整形滑窗”元数据。
- 涉及修改文件：
  - `src/main/java/com/example/agent/capabilities/context/DefaultContextBuilder.java`
  - `src/main/java/com/example/agent/capabilities/context/assembly/DefaultContextAssembler.java`
  - `src/main/java/com/example/agent/capabilities/context/assembly/PromptContextPolicyApplier.java`
  - `src/main/java/com/example/agent/budget/trim/model/ContextCompressionResult.java`（补 summary 注入相关字段）

### P2 验收口径

- 能配置 `primers_count`、`recents_count`、`compression_trigger_ratio`、`compression_target_ratio`。
- 上下文中可观测到“中段摘要注入 + 首尾保留”的行为。

## 5. 风险提示（改造前确认）

1) 需要提前确定压缩模型与成本预算（避免与主链路争抢配额）。
2) 需要明确压缩摘要是否进入持久化（合规与脱敏要求）。
3) 需要确定滑窗对象是“会话消息历史”还是“记忆召回结果视图”（两者实现复杂度不同）。

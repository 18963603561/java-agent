# Shannon 对齐（LLM 压缩 + 三段滑窗）P4 包设计改造任务清单

## 1. 目标与边界

- 目标：在 `P0-P3` 已具备压缩主能力、阶段事件、观测与契约的前提下，补齐“灰度发布、双轨对比、自动回滚、质量评估”的包级能力。
- 边界：`P4` 不改写压缩核心算法，不重构 `P0-P3` 已稳定接口；仅新增优化层与治理层。
- 输入依据：
  - `doc/20260212/Shannon对齐-LLM压缩三段滑窗改造清单-202602120910.md`
  - `doc/20260212/Shannon对齐-P3包设计改造任务清单-202602121114.md`

## 2. 当前 P4 视角包设计缺口

1) 双轨对比逻辑若直接写入 `ContextCompressionService`，会造成编排层职责膨胀。  
2) 缺少独立“灰度策略域”，租户维度、场景维度与比例维度规则无法复用。  
3) 缺少“对比记录模型 + 持久化端口”，线上无法形成可审计的压缩实验闭环。  
4) 缺少统一质量评估端口，无法稳定表达“压缩收益与质量损失”的平衡。  
5) 回滚判定尚未形成独立守卫服务，故障恢复依赖人工操作。

## 3. P4 具体改造任务（按包设计合理性）

---

### P4-PKG-001：抽离双轨执行编排器（主链路解耦）

- 任务目标：将“主生效结果 + 对比结果”的执行流程从 `ContextCompressionService` 抽离，避免服务继续膨胀。
- 关键动作：
  - 新增双轨执行编排器，仅负责 `rule` 与 `llm` 两条轨道的调用顺序与结果归并。
  - 主链路只消费“生效结果”，对比轨仅产出观测与记录，不影响请求结果。
  - 对比轨超时、异常、空结果全部降级为“仅记录失败”，不得影响主轨。
- 计划新增文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/application/CompressionDualTrackOrchestrator.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/model/DualTrackExecutionResult.java`
- 计划修改文件：
  - `src/main/java/com/example/agent/budget/trim/application/ContextCompressionService.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/application/CompressionExecutionRouter.java`
- 验收标准：
  - `ContextCompressionService` 不再包含双轨比对细节。
  - 双轨失败不影响主轨响应。

---

### P4-PKG-002：建立灰度策略域（配置与决策分层）

- 任务目标：形成“可复用、可审计、可按租户扩展”的灰度决策能力。
- 关键动作：
  - 抽象灰度决策端口，输入租户、工作流、会话、策略版本，输出是否开启双轨。
  - 支持全局比例、租户白名单、场景白名单三层规则叠加。
  - 支持策略版本号，便于回放时重建当时决策。
- 计划新增文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/policy/CompressionRolloutPolicy.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/model/RolloutDecision.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/infrastructure/policy/DefaultCompressionRolloutPolicy.java`
- 计划修改文件：
  - `src/main/java/com/example/agent/budget/trim/config/ContextCompressionProperties.java`
  - `src/main/resources/application.yml`
  - `src/main/resources/application.yml.example`
- 验收标准：
  - 灰度决策只在策略域内实现，业务服务不再持有策略细节。
  - 可按租户和场景单独开关双轨。

---

### P4-PKG-003：补齐对比记录模型与持久化端口（实验闭环）

- 任务目标：形成“可追踪、可统计、可回放”的压缩对比数据资产。
- 关键动作：
  - 定义对比记录模型：主轨来源、对比轨来源、压缩前后 token、质量分、是否命中回滚。
  - 定义仓储端口，屏蔽存储实现（可落库、可缓存、可异步写入）。
  - 保证记录写入失败不影响主链路，仅打告警和指标。
- 计划新增文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/model/CompressionComparisonRecord.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/port/CompressionComparisonRepository.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/infrastructure/repository/InMemoryCompressionComparisonRepository.java`
- 计划修改文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/application/CompressionDualTrackOrchestrator.java`
  - `src/main/java/com/example/agent/runtime/prepare/RuntimePreparationService.java`（按需补充上下文字段透传）
- 验收标准：
  - 双轨开启时必有对比记录。
  - 记录写入失败不影响业务返回。

---

### P4-PKG-004：建立质量评估端口与评分实现（收益与质量平衡）

- 任务目标：避免仅以 token 节省率判断优劣，补齐质量维度决策依据。
- 关键动作：
  - 定义质量评估端口，统一输入原文、摘要、结构化字段、统计特征。
  - 首版提供规则评分实现（长度、覆盖、关键事实保留率）。
  - 预留模型评分实现扩展点，后续可接入评审模型。
- 计划新增文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/port/CompressionQualityEvaluator.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/model/CompressionQualityScore.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/infrastructure/evaluator/RuleBasedCompressionQualityEvaluator.java`
- 计划修改文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/application/CompressionDualTrackOrchestrator.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/observability/CompressionObservationFactory.java`
- 验收标准：
  - 每条对比记录都可产出可解释质量分。
  - 质量评估实现可替换，不影响编排层。

### P4-PKG-005：抽离自动回滚守卫（故障快速止损）

- 任务目标：将“何时切回 rule-only”从人工决策改为策略化守卫。
- 关键动作：
  - 定义回滚守卫服务：按失败率、质量阈值、超时率触发回滚。
  - 与灰度策略联动：触发回滚后自动降级为单轨。
  - 输出回滚原因码，供事件、日志、指标统一使用。
- 计划新增文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/application/guard/CompressionRollbackGuard.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/domain/model/RollbackDecision.java`
- 计划修改文件：
  - `src/main/java/com/example/agent/capabilities/context/compression/experiment/application/CompressionDualTrackOrchestrator.java`
  - `src/main/java/com/example/agent/budget/trim/config/ContextCompressionProperties.java`
  - `src/main/resources/application.yml`
- 验收标准：
  - 回滚触发条件可配置且可观测。
  - 回滚后主链路稳定，且可人工恢复灰度。

### P4-PKG-006：补齐双轨观测与事件契约（线上可运营）

- 任务目标：让“是否双轨、谁胜出、为何回滚”可在事件和指标中直接识别。
- 关键动作：
  - 新增双轨对比事件类型与载荷对象。
  - 新增实验指标字典：双轨开启次数、对比完成次数、回滚次数、胜出来源占比。
  - 统一日志字段：`rolloutVersion`、`primarySource`、`shadowSource`、`winner`、`rollbackReason`。
- 计划新增文件：
  - `src/main/java/com/example/agent/streaming/payload/CompressionComparisonEventPayload.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/observability/CompressionExperimentMetricKeys.java`
- 计划修改文件：
  - `src/main/java/com/example/agent/streaming/domain/EventType.java`
  - `src/main/java/com/example/agent/streaming/payload/ContextEventPublisher.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/application/port/CompressionTelemetryPort.java`
  - `src/main/java/com/example/agent/capabilities/context/compression/infrastructure/telemetry/MetricsCompressionTelemetryAdapter.java`
- 验收标准：
  - 可通过事件和指标完整还原双轨决策过程。
  - 不输出敏感正文，仅输出结构化元数据。

---

### P4-PKG-007：测试与架构守卫补齐（防回耦）

- 任务目标：为 P4 新增包边界和行为建立回归护栏。
- 关键动作：
  - 新增双轨编排测试：主轨成功、影子轨失败、回滚触发、回滚恢复。
  - 新增灰度策略测试：全局比例、租户白名单、场景白名单。
  - 新增架构守卫：禁止 `ContextCompressionService` 直接依赖实验仓储实现。
- 计划新增/修改测试文件：
  - 新增 `src/test/java/com/example/agent/context/compression/CompressionDualTrackOrchestratorTest.java`
  - 新增 `src/test/java/com/example/agent/context/compression/CompressionRolloutPolicyTest.java`
  - 新增 `src/test/java/com/example/agent/streaming/CompressionComparisonEventPublisherTest.java`
  - 修改 `src/test/java/com/example/agent/budget/ContextCompressionServiceTest.java`
  - 修改 `src/test/java/com/example/agent/budget/BudgetArchitectureGuardTest.java`
- 验收标准：
  - 双轨关键场景有单测覆盖。
  - 包边界违规会触发守卫测试失败。

## 4. P4 推荐实施顺序

1) `P4-PKG-002`（先有灰度策略域）  
2) `P4-PKG-001`（再接双轨编排器）  
3) `P4-PKG-003`（补实验记录端口）  
4) `P4-PKG-004`（接质量评分）  
5) `P4-PKG-005`（补自动回滚守卫）  
6) `P4-PKG-006`（补事件与指标契约）  
7) `P4-PKG-007`（补测试与守卫）

## 5. P4 完成判定

- 双轨对比能力与主链路解耦，`ContextCompressionService` 不承担实验细节。  
- 灰度策略具备全局、租户、场景三层控制，并可版本化审计。  
- 具备自动回滚能力，触发条件、原因与恢复路径可观测。  
- 事件、指标、日志三者字段一致，可支持运营看板与问题回放。  
- 新增架构守卫可防止后续代码回耦到“服务大泥球”。

## 4. 专项问题结论

### 4.1 现有工程是否存在滑动窗口压缩

- 结论：**Found Evidence（存在“预算驱动的上下文裁剪+压缩链路”）**。
- 证据：
  - `src/main/java/com/example/agent/capabilities/context/DefaultContextBuilder.java` 在构建阶段串联 `allocate -> trim -> compressIfNeeded`
  - `src/main/java/com/example/agent/budget/trim/application/ContextCompressionService.java` `compressIfNeeded`
  - `src/main/java/com/example/agent/budget/trim/application/DefaultCompressionTriggerPolicy.java` `resolveTriggerReason`
  - `src/main/java/com/example/agent/capabilities/memory/store/CompressedMemoryStore.java` `compress`

### 4.2 什么时候触发压缩

- 结论：**Found Evidence**。
- 触发条件（静态）：
  1. 上下文预算超限触发：`OVER_TOTAL` 或 `OVER_SECTION`（`DefaultCompressionTriggerPolicy#resolveTriggerReason`）。
  2. 记忆自动压缩触发：大小阈值、令牌阈值、最大年龄阈值（`MemoryPolicy#shouldCompress`）。
  3. 冷却防抖：压缩最小间隔控制（`ContextCompressionProperties#minIntervalSeconds` + `CompressionCooldownService`）。

### 4.3 是否包含 Shannon 三段式保留策略（Primers + Summary + Recents）

- 结论：**Confirmed Missing**（按 Shannon 语义 1:1 对齐口径）。
- 本项目证据：存在压缩与裁剪，但未发现 Shannon 同名参数与同名切片函数。
- 检索关键词与范围：
  - 关键词：`primers_count`、`recents_count`、`compression_trigger_ratio`、`compression_target_ratio`、`shapeHistory`、`history_window_size`、`use_case_preset`
  - 范围：`src/main/java` + `src/test/java`

- Shannon 对照：
  - `vendor/Shannon/go/orchestrator/internal/workflows/helpers.go` `getPrimersRecents/getCompressionRatios/shapeHistory`

### 4.4 是否实现三层预算控制、背压机制

- 三层预算控制结论：**Found Evidence（实现了等价三层控制面，但非 Shannon 原始命名）**。

  - 执行层：`DefaultContextTrimmer#trim` + `ContextCompressionService#compressIfNeeded`

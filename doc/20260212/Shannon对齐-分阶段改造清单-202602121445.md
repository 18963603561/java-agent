# Shannon 对齐分阶段改造清单（含配置建议与代码改造点）

## 1. 目标与范围

- 目标：基于 `Shannon-剪裁与裁剪能力对标分析-202602121437.md`，将本工程从“默认 rule 文本裁剪主导”逐步升级为“语义压缩主导、规则兜底、可灰度可回滚”的稳定体系。
- 范围：覆盖配置、压缩执行链路、JSON 内容识别、滑窗参数、观测与回滚，不在本清单中展开业务提示词细节优化。
- 原则：
  - 先可用后优化：先打通 `llm/hybrid` 主链路，再提升摘要质量。
  - 先灰度后全量：所有高风险能力必须可开关、可回退。
  - 先观测后提速：先补齐指标与事件，再做激进参数调整。

---

## 2. 现状差距（对齐靶点）

1) 压缩执行模式差距：
- Shannon 主链路偏 `LLM` 语义压缩。
- 本工程默认 `rule`，大量字符截断与拼接。

2) 滑窗参数差距：
- Shannon 常用默认：`primers=3`、`recents=20`。
- 本工程默认：`primers=2`、`recents=6`。

3) 阈值策略差距：
- Shannon 常见：触发 `0.75`，目标 `0.375`。
- 本工程默认：触发 `0.85`，目标 `0.70`。

4) JSON 语义处理差距：
- 本工程默认路径将 JSON 输出当普通文本处理，存在“字段语义未识别、关键键被截断”风险。

---

## 3. 分阶段改造总览

- Phase-0：基线加固与观测补齐（低风险）
- Phase-1：启用 `hybrid` 并跑通 LLM 主链路（中风险）
- Phase-2：引入 JSON 感知压缩输入（中高风险）
- Phase-3：滑窗与阈值参数对齐 Shannon（中风险）
- Phase-4：灰度、回滚与质量门禁（中高风险）
- Phase-5：全量切换与运营化收口（高风险）

---

## 4. Phase-0（基线加固与观测补齐）

### 4.1 阶段目标

- 在不改变主执行模式前提下，补齐压缩链路可观测性与数据基线，为后续对比提供依据。

### 4.2 配置建议

- 保持：`agent.context.compression.mode.type=rule`。
- 增加观测标签字段：`scene`、`tenantId`、`sessionId`、`source`、`reason`。
- 保持冷却：`min-interval-seconds=30`（先不调整）。

### 4.3 代码改造点

1) 指标补齐（执行前后 token 与摘要质量）
- `src/main/java/com/example/agent/budget/trim/application/ContextCompressionService.java`
- `src/main/java/com/example/agent/capabilities/context/compression/infrastructure/telemetry/MetricsCompressionTelemetryAdapter.java`

2) 注入观测增强（注入成功率、注入长度）
- `src/main/java/com/example/agent/capabilities/context/assembly/DefaultContextSummaryInjectionPolicy.java`

3) 压缩输入摘要化日志（仅元数据）
- `src/main/java/com/example/agent/capabilities/context/compression/prompt/DefaultCompressionPromptBuilder.java`

### 4.4 验收标准

- 能统计：触发率、成功率、失败原因分布、注入成功率、压缩后仍超预算比例。
- 不记录敏感正文，仅记录结构化元数据。

## 5. Phase-1（启用 hybrid，打通 LLM 主链路）

### 5.1 阶段目标

- 在保持 `rule` 兜底的前提下，让 `LLM` 成为压缩主路径，验证稳定性。

### 5.2 配置建议

```yaml
agent:
  context:
    compression:
      mode:
        type: hybrid
      llm:
        scene: context_compress
        timeout-ms: 3500
        retry: 1
        fallback: rule
      trigger:
        compression-trigger-ratio: 0.82
        compression-target-ratio: 0.65
```

说明：先温和下调阈值，避免一次性压缩触发激增。

### 5.3 代码改造点

1) 路由策略显式化（主轨与兜底轨语义）
- `src/main/java/com/example/agent/capabilities/context/compression/application/CompressionExecutionRouter.java`
- `src/main/java/com/example/agent/capabilities/context/compression/domain/policy/DefaultCompressionFallbackPolicy.java`

2) LLM 结果健壮性增强（解析失败可重试、失败码标准化）
- `src/main/java/com/example/agent/capabilities/context/compression/application/LlmCompressionOrchestrator.java`
- `src/main/java/com/example/agent/capabilities/context/compression/parser/CompressionResponseParser.java`

3) 摘要治理策略完善（长度与脱敏策略分层）
- `src/main/java/com/example/agent/capabilities/context/compression/summary/CompressionSummaryGuard.java`

### 5.4 验收标准

- `hybrid` 下 LLM 压缩成功率达到预设阈值（建议 >= 95%）。
- `rule` 兜底可覆盖全部失败场景，无主流程中断。

## 6. Phase-2（JSON 感知压缩输入）

### 6.1 阶段目标

- 解决“输出在 JSON 中但未识别”的核心问题，减少无意义截断。

### 6.2 配置建议

```yaml
agent:
  context:
    compression:
      json-aware:
        enabled: true
        max-fields: 40
        max-field-chars: 300
        key-whitelist:
          - answer
          - conclusion
          - highlights
          - toolName
          - confidence
```

说明：先白名单关键键，再逐步扩展。

### 6.3 代码改造点

1) 新增 JSON 感知提取器（压缩前标准化）
- 新增：`src/main/java/com/example/agent/capabilities/context/compression/parser/JsonAwareCompressionInputExtractor.java`
- 修改：`src/main/java/com/example/agent/capabilities/context/compression/prompt/DefaultCompressionPromptBuilder.java`

2) 写入侧摘要生成改造（避免原始 JSON 直接拼接）
- `src/main/java/com/example/agent/capabilities/memory/write/MemoryWriteSerializer.java`
- `src/main/java/com/example/agent/capabilities/memory/store/CompressedMemoryStore.java`

3) 保留兼容路径（无法解析 JSON 时回退文本模式）
- `src/main/java/com/example/agent/capabilities/memory/support/MemoryTextUtils.java`

### 6.4 验收标准

- 关键字段保留率显著提升（建议 >= 90%）。
- “摘要可读性差/JSON 残片”告警占比明显下降。

## 7. Phase-3（滑窗与阈值参数对齐 Shannon）

### 7.1 阶段目标

- 使本工程窗口行为与 Shannon 更接近，提升长会话连续性。

### 7.2 配置建议

```yaml
agent:
  context:
    compression:
      window:
        primers-count: 3
        recents-count: 20
      trigger:
        compression-trigger-ratio: 0.75
        compression-target-ratio: 0.40
```

说明：目标比例先用 `0.40`，观察稳定后再逼近 `0.375`。

### 7.3 代码改造点

3) 触发策略与目标达标判定统一
- `src/main/java/com/example/agent/capabilities/context/compression/domain/policy/DefaultCompressionTriggerPolicy.java`
- `src/main/java/com/example/agent/budget/trim/application/ContextCompressionService.java`

### 7.4 验收标准

- 压缩后仍超预算比例下降。

1. 先做 `Phase-0`（补观测，拿基线）。

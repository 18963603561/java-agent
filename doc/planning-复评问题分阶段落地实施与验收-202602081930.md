# planning 复评问题分阶段落地实施与验收

## 1. 目标与原则

- 依据文档：`doc/planning包设计合理性复评-202602081855.md`
- 落地原则：
  - 新项目直接按新方案落地，不保留历史兼容分支
  - 优先解决 P1，再收口 P2/P3
  - 每阶段完成后执行全量测试 `mvn -q test`

## 2. 阶段一：编排层职责拆分（PlannerService 收口）

### 2.1 实施内容

1. 新增能力评估与上下文回写服务：
   - `src/main/java/com/example/agent/planning/capability/PlanningCapabilityService.java`
   - `src/main/java/com/example/agent/planning/capability/PlanningRecommendationMapper.java`

2. 新增审批标记服务：
   - `src/main/java/com/example/agent/planning/approval/PlanningApprovalService.java`

3. `PlannerService` 改为纯编排：
   - 删除评估输入组装、推荐策略映射、审批写入等细节方法
   - 统一委托 `PlanningCapabilityService` 与 `PlanningApprovalService`

4. 同步改造测试装配：
   - `src/test/java/com/example/agent/planning/PlannerServiceTest.java`
   - `src/test/java/com/example/agent/runtime/AgentRuntimeApprovalIntegrationTest.java`

### 2.2 阶段一验收

- 执行：`mvn -q test`
- 结果：通过

## 3. 阶段二：LLM 规划管线与解析契约收口

### 3.1 实施内容

1. 解析失败契约显式化：
   - 新增 `PlanParseAttemptResult` 与 `PlanParseErrorTypes`
   - `PlanParser` 增加 `parseAttempt`，保留原 `parse` 兼容调用方

2. LLM 规划流程状态收口：
   - 新增 `LlmPlanAttemptResult`
   - `LlmPlanEngine` 提取 `resolvePlanResult`，减少主流程状态变量
   - 修复流程改为显式错误类型传递

3. 策略优先级硬编码收口：
   - 新增 `PlanningStrategyOrders`
   - 各处理器 `getOrder()` 改为常量引用
   - `PlanningStrategyRegistry` 增加优先级冲突校验，冲突即抛错

4. 提示词模板读取优化：
   - `PlanningPromptBuilder` 引入模板缓存（`AtomicReference`）

5. 对应测试增强：
   - `PlanParserTest` 新增 `parseAttempt` 错误类型断言
   - `LlmPlanEngineTest` 迁移到 `parseAttempt` 桩
   - `PlanningStrategyRegistryTest` 新增优先级冲突用例

### 3.2 阶段二验收

- 执行：`mvn -q test`
- 结果：通过

## 4. 阶段三：上下文与遥测边界收口

### 4.1 实施内容

1. 规划上下文瘦身：
   - 新增 `PlanningPromptSummaryFactory`
   - `PlanningContext.toPromptSummary()` 改为委托工厂
   - 删除 `PlanningContext` 内部记忆/证据统计聚合细节

2. 策略上下文副作用边界收口：
   - `PlanningStrategyContext` 构造阶段防御性拷贝
   - `getSteps/getPlanSteps/getDependencies` 改为只读视图
   - 新增 `appendStep/appendDependency/getStepCount`
   - `AbstractPlanningStrategyHandler` 改为通过上下文方法写入

3. 遥测职责拆分：
   - 新增 `PlanningPromptTraceService`
   - `PlanTelemetry.recordPromptTrace` 改为委托追踪服务

4. 结果对象可变性收口：
   - `PlanResult` 新增 `readonly(...)`
   - `HeuristicPlanBuilder` 与 `LlmPlanEngine` 输出使用只读步骤列表

5. 修复阶段内回归：
   - 修复策略上下文防御性拷贝导致的步骤丢失问题（`HeuristicPlanBuilder` 从策略结果回读步骤）

6. 测试增强：
   - 新增 `PlanningCapabilityAndApprovalServiceTest`

### 4.2 阶段三验收

- 执行：`mvn -q test`
- 结果：通过
